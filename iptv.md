# Общая информация

IPTV сервис предоставляет ссылку на список каналов в формате [M3U][m3u-extending] или [XSPF][xspf-extending].

Ввиду возможности изменения списка каналов политика кэширования может быть задана средствами транспортного протокола, например, в случае протокола HTTP на стороне сервера при помощи заголовков `Expires`, `Last-Modified`, `ETag` и т.д.

При обращении за списком каналов *рекомендуется* устанавливать HTTP заголовок `User-Agent`. Данный заголовок может быть использован системой при генерации списка каналов. Значение заголовка должно однозначно определять платформу и класс устройства.

Пример задания HTTP–заголовка `User-Agent`:

	Peers.TV/3.2.1 (iOS/7.1.0; iPhone/6,2; build 484) Darwin/14.0.0

[m3u-extending]: m3u-extending.md
[xspf-extending]: xspf-extending.md

## Cписок каналов

Список каналов содержит набор источников вещания и директив, содержащих дополнительные атрибуты: название, идентификатор канала, признак наличия записей, признак наличия доступа к каналу и т.д.

В случае поддержки директив клиентское ПО *должно*:

- сгруппировать источники вещания по общему идентификатору канала:
	- отобразить в графическом интерфейсе только одну сущность для канала;
	- в случае отсутствия идентификатор может быть получен по имени при помощи [TVGuide API][tvguide-api].
- отобразить признак наличия архива телепередач, если хотя бы один источник имеет установленный признак архива;
- при выборе источника вещания, к которому нет доступа, — уведомить пользователя об отсутствии доступа и по возможности предложить перейти в "Личный кабинет":
	- после возврата из "Личного кабинета" необходимо обновить список каналов.

[tvguide-api]: tv-guide.md

# Дополнительные возможности

Ниже описаны дополнительные возможности сервиса IPTV.

## Timeshift

Позволяет просматривать вещание со сдвигом от эфирного.

О наличии данной возможности сервер сообщает в HTTP заголовке `Inetra-Timeshift` при обращении к потоку.

Формат заголовка:

	Inetra-Timeshift: template="<uri_template>"; duration=<duration>

где:

- `<uri_template>` — шаблон базового адреса, по которому необходимо выполнять обращения;
- `<duration>` — максимальный сдвиг по времени в секундах от эфирного вещания канала. Текущее время вещания может быть получено из HTTP заголовка `Date`.

Шаблон содержит переменные в формате `${template_variable}`, где `template_variable` задает имя переменной. Путем замены переменных соответствующими значениями можно получить базовый адрес для обращений к возможности Timeshift.

В случае [Http Live Streaming][hls-standard-url] базовый адрес указывает на индексный файл (ресурс с расширением m3u8).

[hls-standard-url]: http://tools.ietf.org/html/draft-pantos-http-live-streaming-07

Список переменных:

название     | значение     | смысл
-------------|--------------|--------
`start_time` | `натуральное`| абсолютное время начала в формате Unix time по времени UTC+0
`redirect`   |`true`,`false`| осуществлять перенаправление на ссылку с постоянным смещением от эфирного вещания

При задании значения `true` для переменной шаблона `redirect` будет произведено перенаправление (HTTP код ответа `302`) на постоянную ссылку с относительным смещением от эфирного вещания. В этом случае клиент должен самостоятельно обработать переход и передать проигрывателю результирующую ссылку. В случае указания значения `false` будет сформирована сессия с использованием HTTP заголовка `Set-Сookie`.

В случае если обработать запрос невозможно (например, нет записанных сегментов), то будет возвращена ошибка с кодом ответа 404.

В случае HLS—вещания:

- при формировании "скользящего" окна допускается погрешность на уровне длительности сегмента;
- стандарт HLS вносит задержку вещания. В случае задания переменной `start_time` близкой к текущему времени, сервер может проигнорировать переданное значение и вернет индексный файл, соответствующий эфирному вещанию;
- при задании параметра `start_time` первый сегмент в индексном файле должен ссылаться на заданное время;
- суммарная длительность сегментов в индексном файле должна не более чем в 3 раза превышать максимальную длительность сегмента, задаваемую директивой `EXT-X-TARGETDURATION`.

## Взаимодействие с автоматизированной системой расчетов оператора связи

Список каналов, поставляемый оператором связи может содержать дополнительные признаки доступности каналов абоненту. Для этого служат специальные поля `allowed`, `allowed-till` и `pending-till`. С помощью них оператор может указать, какие из каналов доступны абоненту, имеются ли временные ограничения по доступности.

Для операторов–партнеров предусмотрена возможность покупки каналов абонентом непосредственно из приложения. Для этого оператору необходимо предоставить Инетре URL автоматизированной системы расчета, по которому будет переходить приложение для осуществления операции покупки.

При переходе на указанную страницу приложение передает дополнительные параметры запроса (методом GET протокола HTTP), позволяющие автоматизированной системе расчетов определить, для чего именно пришел абонент.

 параметр             | значения  | смысл
----------------------|-----------|-------
`inetra-visit-reason` | константа | причина визита абонента
`inetra-channel-ids`  | числа через `,` | идентификаторы выбранных пользователем каналов

Возможные причины визита (`inetra-visit-reason`):

- `buy-subscription` — желание абонентом подписаться на каналы, идентификаторы которых передаются в параметре `inetra-channel-ids`. Если каналов несколько — они перечисляются через символ `,`. 

Идентификаторы каналов берутся приложением из списка каналов, и должны быть указаны в параметре `channel-id` тега `EXT-INETRA-CHANNEL-INF` в случае [M3U8][m3u-extending] формата списка каналов, и тега `inetra:channel-inf`, в случае [XSPF][xspf-extending].

<span style="color:#f00">Внимание!</span> Если в списке каналов не будет указан его идентификатор, приложение сможет передать только причину визита абонента (`inetra-visit-reason=buy-subscription`), без указания выбранного пользователем канала.

При покидании пользователем страницы автоматизированной системы расчета приложение перечитывает список каналов, чтобы отобразить изменения в доступности. При этом если оборудованию провайдера требудет время для применения новой конфигурации, ожидаемое время доступа необходимо указать в поле `pending-till` для купленного канала.
