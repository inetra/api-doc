# Общая информация

IPTV сервис предоставляет ссылку на плейлист в формате XSPF или M3U.

Плейлист содержит набор источников вещания и дополнительных атрибутов: название, идентификатор канала, признак наличия записей и т.д.

Ввиду возможности изменения содержимого плейлиста политика кэширования может быть задана средствами транспортного протокола, например, в случае HTTP на стороне сервера при помощи HTTP–заголовков `Expires`, `Last-Modified`, `ETag` и т.д.

Правила формирования плейлиста для сервиса IPTV могут быть найдены:

- в существующей документации в [JIRA][jira-playlists-extending];
- в черновике документа [Правила расширения плейлиста][playlist-extending].

# Дополнительные возможности

Ниже описаны дополнительные возможности сервиса IPTV.

## Timeshift

Позволяет просматривать эфир с отставанием от реального вещания.

О наличии данной возможности сервер сообщает в HTTP–заголовке `INETRA-TIMESHIFT` при обращении к потоку.

Формат заголовка:

	INETRA-TIMESHIFT: template="<uri_template>"; duration=<duration>

где:

- `<uri_template>` — шаблон базового адреса, по которому необходимо выполнять обращения;
- `<duration>` — время в секундах, для которого доступен таймшифт.

Шаблон содержит переменные в формате `${template_variable}`, где `template_variable` задает имя переменной. Путем замены переменных соответствующими значениями можно получить базовый адрес для обращений к возможности Timeshift. В случае [Http Live Streaming][hls-standard-url] базовый адрес указывает на индексный файл.

[hls-standard-url]: http://tools.ietf.org/html/draft-pantos-http-live-streaming-07

Список переменных:

название     | значение     | смысл
-------------|--------------|--------
`start_time` | `число`      | абсолютное время начала в формате Unix time по времени UTC+0 (обязательный параметр)
`window`     | `число`      | количество сегментов в плейлисте
`redirect`   |`true`,`false`| осуществлять редирект на ссылку с постоянным смещением от текущего эфира


При задании значения `true` для переменной шаблона `redirect` будет произведено перенаправление(HTTP–код 302) на постоянную ссылку с относительным смещением от реального эфира. В этом случае клиент должен самостоятельно обработать переход и передать проигрывателю результирующую ссылку. В случае указания значения `false` будет сформирована сессия с использованием HTTP–меток (`cookie`)

В случае HLS—вещания:

- при формировании "скользящего" окна допускается погрешность на уровне длительности сегмента;
- стандарт HLS предполагает вещание близкое к реальному эфиру (с некоторым отставанием). В случае задания параметра `offset` близкого к реальному эфиру, сервер может проигнорировать переданное значение и вернуть ссылку на реальный эфир.

Размер "плавающего" окна не должен быть чрезмерно большим или малым, рекомендуется выбирать значения из интервала от 30 до 50 секунд.

В случае если обработать запрос невозможно (например, нет записанных сегментов), то будет возвращена ошибка с HTTP–кодом 404.
