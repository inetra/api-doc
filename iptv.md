# Общая информация

IPTV сервис предоставляет ссылку на список каналов в формате [M3U][m3u-extending] или [XSPF][xspf-extending].

Рекомендуемый формат — M3U.

Ввиду возможности изменения списка каналов политика кэширования может быть задана средствами транспортного протокола, например, в случае протокола HTTP на стороне сервера при помощи заголовков `Expires`, `Last-Modified`, `ETag` и т.д.

При обращении за списком каналов *рекомендуется* устанавливать HTTP заголовок `User-Agent`. Данный заголовок может быть использован системой при генерации списка каналов. Значение заголовка должно однозначно определять платформу и класс устройства.

Пример задания HTTP–заголовка `User-Agent`:

	Peers.TV/3.2.1 (iOS/7.1.0; iPhone/6,2; build 484) Darwin/14.0.0

[m3u-extending]: m3u-extending.md
[xspf-extending]: xspf-extending.md

## Cписок каналов [channels-list]

При построении списка доступных каналов у приложения имеются несколько списков каналов операторов связи, каждый из которых содержит:

- URI источника вещания канала
- Название канала
- Информационные характеристики (опционально):
	- Идентификатор канала (в случае его отсутствия может быть получен по имени при помощи [Media Guide API][media-guide-api])
	- Идентификатор территории вещания канала
	- Признак наличия архива записей<sup>1</sup>
	- Логотип канала
	- Возрастное ограничение для канала
- Характеристики источника вещания (опционально):
	- Разрешение изображения
	- Пропорции изображения
	- Рекомендации кадрирования изображения
	- Наличия у пользователя доступа к вещанию
	- Наличия поддержки [технологии Timeshift][timeshift]<sup>2</sup>

Замечания:

1. Признак наличия архива не гарантирует доступность записей для конечного пользователя.
2. Признак наличия поддержки технологии Timeshift носит вспомогательный характер и не гарантирует поддержку сервером вещания.

В случае поддержки директив клиентское ПО *должно*:

- сгруппировать источники вещания по общему идентификатору канала, при этом отобразить в графическом интерфейсе только одну сущность для канала;
- при отображении информации о канале, такой как: название, логотип, возрастное ограничение:
	- если информация имеется в Media Guide API, отображать ее;
	- в противном случае брать параметры из списка каналов оператора. При этом, если два оператора предоставляют источники вещания для канала с одинаковым названием, без указания идентификатора канала, и по данному названию Media Guide API не может подобрать подходящего идентификатора, объединять каналы по названию, указанному в списке каналов операторов.
- отобразить признак наличия архива телепередач, если хотя бы один оператор указал признак наличия записей;
- при выборе источника вещания, к которому нет доступа, — уведомить пользователя об отсутствии доступа и по возможности предложить [перейти в "Личный кабинет"][billing-communicate]
- отобразить дополнительные элементы управления воспроизведением (пауза, перемотка, переход на начало передачи), если источник вещания или другие источники (условно эквивалентные к текущему) имеют признак наличия поддержки технологии Timeshift

Архив записей телепередач предоставляется при помощи [Media Guide API][media-guide-api] и [MediaLocator API][media-locator-api].

[media-guide-api]: tv-guide.md
[media-locator-api]: media-locator.md

# Дополнительные возможности

Ниже описаны дополнительные возможности сервиса IPTV.

## Timeshift [timeshift]

Позволяет просматривать вещание со сдвигом от эфирного.

О наличии данной возможности сервер сообщает в HTTP заголовке `Inetra-Timeshift` при обращении к источнику вещания. Заголовок содержит набор атрибутов, разделенных символом точка с запятой (`;`), строковые значений оборачиваются символом кавычки (`"`).

Атрибуты заголовка:

название     | тип    | по умолчанию| смысл
-------------|--------|-------------|--------
`template`   |`строка`| отсутствует | шаблон базового адреса (<span style="color: red">Устарело в 1.5.0</span>)
`base-uri`   |`строка`| отсутствует | базовый адрес доступа к технологии Timeshift
`api-version`|`число` | `1`         | версия программного интерфейса, применима к `base-uri`
`duration`   |`число` | `0`         | максимальный сдвиг по времени в секундах от эфирного вещания канала. Текущее время вещания может быть получено из HTTP заголовка `Date`

Пример заголовка:

	Inetra-Timeshift: base-uri="http://peers.tv/timeshift/1kanal/playlist.m3u8";duration=86400

В случае [Http Live Streaming][hls-draft-url] базовый адрес должен указывать на индексный файл (ресурс с расширением m3u8).

[hls-draft-url]: http://tools.ietf.org/html/draft-pantos-http-live-streaming-07
[wiki-unix-time-ru]: http://ru.wikipedia.org/wiki/UNIX-время

### Обращение на основе базового адреса

Для обращения к технологии Timeshift клиент должен сформировать адрес вещания на основе базового адреса (`base-uri`) и дополнительным параметров:

название    | тип         | смысл
------------|-------------|-------
Доступ по относительному времени|||
`offset`    |`натуральное`| смещение относительно эфирного вещания
Доступ по абсолютному времени + StartOver|||
`start_time`|`натуральное`| абсолютное время начала вещания в формате [Unix time][wiki-unix-time-ru].
`start_over`|`булев`      | признак перехода на начало передачи

При выполнении запросов с использованием параметра `start_time` клиент должен обработать перенаправление (HTTP код ответа 302) на постоянную ссылку с относительным смещением от эфирного вещания и передать проигрывателю результирующую ссылку.

Параметр `start_over` принимает значения `true` или `false`, значение по умолчанию — `false`. При указании параметра `start_over` со значением `true` в дополнение к параметру `start_time` сервер выполнит перенаправление на ссылку с относительным смещением от эфирного вещания, которая будет соответствовать фактическому началу передачи, включающей указанное в `start_time` абсолютное время. Рекомендуется использовать параметр `start_over` для реализации функции "Начать с начала".

Ссылка на адрес вещания, сформированная при помощи параметра `offset`, может быть передана непосредственно на воспроизведение.

Параметры `start_time` и `offset` являются взаимоисключающими.

ВАЖНО: Клиент должен учитывать случай, когда базовый адрес уже содержит с составе запроса GET параметры (см. [раздел 3 из RFC 3986][rfc3986-section3]). Параметры разделяются при помощи символа амперсанд (`&`).

[rfc3986-section3]: http://tools.ietf.org/html/rfc3986#section-3

### Обращение при помощи шаблона адреса (<span style="color: red">Устарело в 1.5.0</span>)

Для обращения к технологии Timeshift клиент должен сформировать адрес вещания на основе шаблона базового адреса.

Шаблон содержит переменные в формате `${variable_name}`, где `variable_name` задает имя переменной. Имя переменной может состоять из символов латинского алфавита, цифр и символа подчеркивания (`_`), имя переменной не может начинаться с цифр.

При формировании базового адреса на основе шаблона клиент должен выбрать все переменные из шаблона, заменить известные переменные на соответствующие значения, а неизвестные заменить на строку `not_supported`.

Если переменная отсутствует в шаблоне, значит функциональность, реализуемая установкой значения данной переменной, недоступна.

Для поиска переменных в шаблоне можно воспользоваться регулярным выражением:

	(\\$\\{[a-zA-Z_][a-zA-Z0-9_]*\\})

Список переменных:

название     | значение    | по умолчанию | смысл
-------------|-------------|--------------|-------
`start_time` |`натуральное`| отсутствует  | абсолютное время начала в формате [Unix time][wiki-unix-time-ru]

Клиент должен обратиться при помощи HTTP метода `HEAD` к адресу вещания, сформированному из шаблона, обработать перенаправление (HTTP код ответа `302`) на постоянную ссылку с относительным смещением от эфирного вещания и передать проигрывателю результирующую ссылку.

### Особенности реализации

В случае если обработать запрос невозможно (например, нет записанных сегментов), то будет возвращена ошибка с кодом ответа 404.

В случае HLS—вещания:

- при формировании "скользящего" окна допускается погрешность на уровне длительности сегмента;
- при установке нулевого значения для параметра `offset` сервер вернет индексный файл, соответствующий эфирному вещанию;
- в случае задания переменной `start_time` близкой к текущему времени, сервер может проигнорировать переданное значение и вернет индексный файл, соответствующий эфирному вещанию;
- при задании параметра `start_time` сегмент, содержащий указанное время, должен отставать от конца индексного файла не более чем на 3 значения максимальной длительности сегмента (директива `EXT-X-TARGETDURATION`).

Рекомендации по формированию базового адреса:

- рекомендуется включать идентификатор или алиас канала;
- при предоставлении оператором услуги Timeshift в нескольких регионах, рекомендуется включать идентификатор территории, для выбора сервером правильного расписания телепередач. Если код территории не указан, сервер должен интерпретировать территорию как ту, которую он обслуживает по умолчанию, или ту, на которой он сам расположен;
- для вариативного вещания каждый вложенный индексный файл должен содержать соответствующую величину сдвига от эфирного вещания, указанную для мастер-индекс файла.

#### Формирование индексного файла вещания

Проигрыватели по–разному воспроизводят онлайн–вещание в формате HLS. Стандарт [HTTP Live Streaming][hls-draft-url] рекомендует выбирать сегмент для воспроизведения, который отстоит от конца индексного файла на 3 максимальных длительности сегмента (директива `EXT-X-TARGETDURATION`), однако некоторые проигрыватели игнорирует данное предписание и начинают воспроизводить первый медиа–сегмент из списка.

В связи с этим становится сложным предугадать с какого момента времени проигрыватель начнет воспроизведение, поэтому ниже предлагается частная рекомендация по формированию индексного файла.

Частная рекомендация по формированию индексного файла:

- максимальная длительность сегмента — 11 секунд;
- средняя длительность сегмента — 10;
- индексный файл содержит 3–4 сегмента, суммарная длительность которых не более чем в 3 раза превышает максимальную длительность (директива `EXT-X-TARGETDURATION`);
- первый сегмент в индексном файле содержит метку абсолютного времени (задается при помощи директивы `EXT-X-PROGRAM-DATE-TIME`).

Пример:

	#EXTM3U
	#EXT-X-TARGETDURATION:11
	#EXT-X-MEDIA-SEQUENCE:005117
	#EXT-X-PROGRAM-DATE-TIME:2014-05-18T13:06:20Z
	#EXTINF:10, no desc
	segment-1400367207-005117.ts
	#EXTINF:10, no desc
	segment-1400367207-005118.ts
	#EXTINF:10, no desc
	segment-1400367207-005119.ts
	#EXTINF:10, no desc
	segment-1400367207-005120.ts


## Взаимодействие с автоматизированной системой расчетов оператора связи [billing-communicate]

Список каналов, поставляемый оператором связи может содержать дополнительные признаки доступности каналов абоненту (см. документы по расширению [M3U][m3u-extending] или [XSPF][xspf-extending]). Для этого служат специальные атрибуты источников вещания каналов `access`, `allowed-till` и `pending-till`. С их помощью оператор может указать, какие из каналов доступны абоненту, имеются ли временные ограничения по доступности.

Различные интерпретации приложением данных атрибутов перечислены в таблице ниже:

 `access` | `allowed-till` | `pending-till` | интерпретация
----------|----------------|----------------|---------------
`denied`  | не указан      | игнорируется   | Доступ к вещанию канала запрещен. Для операторов–партнеров приложение может предложить купить подписку на канал в ["Личном кабинете"][anchor-personal-office] абонента
`denied`  | `число`        | игнорируется   | Доступ на постоянной основе к вещанию канала у абонента отсутствует, но доступен режим пробного ознакомления с вещанием канала в течение времени, указанного в параметре `allowed-till`, в данном случае значение указывается в секундах.
`pending` | игнорируется   | `число`        | Канал оплачен, но вещание еще не доступно абоненту в силу ряда причин (ожидание подтверждения оплаты, применение конфигурации на оборудовании и т.п.). Планируемое время появления доступа к вещанию каналу указывается в параметре `pending-till`, в формате GMT UNIX time. При наступлении этого времени приложение перечитает список каналов. 
`allowed` | не указан      | игнорируется   | Канал доступен без ограничений по времени. Это может быть как бесплатный канал, так и платный с автоматическим продлением подписки.
`allowed` | `число`        | игнорируется   | Канал доступен абоненту с ограниченным временем подписки. Время, когда оканчивается подписка, указывается в параметре `allowed-till`, в формате GMT UNIX time.

При наличии доступа (полноценного, с ограничением по времени или пробного режима) ожидается, что по указанному в списке каналов URI для HTTP запросов будет возвращаться ответ с кодом 200. HTTP ответ с кодом 401 будет интерпретироваться как завершение подписки на вещание канала.

При интерпретации времени, указанное сервером производится с учетом текущего времени сервера, переданного им в ответе в заголовке `Date`. Тем самым приложение может переводить абсолютное время в относительное для отображения обратного отсчета до событий (например, появления доступа до вещания канала) в графическом интерфейсе или выставления таймеров.

### Личный кабинет [anchor-personal-office]

Для операторов–партнеров предусмотрена возможность интеграции "Личного кабинета" абонента автоматизированной системы расчетов (АСР) посредством встраивания веб–страницы непосредственно в приложение, что позволяет абоненту выполнять действия, например, для покупки недоступных каналов или авторизации сброса PIN–кода родительского контроля.

Для этого оператору необходимо предоставить URL веб–страницы "Личного кабинета" абонента автоматизированной системы расчетов, по которому будет переходить приложение для осуществления действий.

При переходе на такую страницу приложение передает дополнительные параметры методом GET протокола HTTP, позволяющие автоматизированной системе расчетов определить, для чего именно пришел абонент.

 параметр             | значения  | смысл
----------------------|-----------|-------
`inetra-visit-reason` | константа | причина визита абонента
`inetra-callback-url` | строка    | кодированный URL страницы обратного вызова
Подписка на каналы ||
`inetra-channel-ids`  | числа через `,` | числовые идентификаторы выбранных пользователем каналов

Возможные причины визита, `inetra-visit-reason`:

- `buy-subscription` — желание абонентом подписаться на каналы;
- `reset-parental-pincode` – желание абонента получить авторизацию на сброс PIN–кода родительского контроля посредством принудительной аутентификации в "Личном кабинете".
- `reset-parental-pincode-via-call-center` — желание абонента получить авторизацию на сброс PIN–кода родительского контроля посредством обращения в контакт–центр Оператора.

Если параметр `inetra-visit-reason` не указан, автоматизированная система расчетов может считать такое обращение как визит страницы "Личного кабинета" абонента без указанной явно цели.

Завершение взаимодействия пользователя со страницей автоматизированной системы расчета может быть осуществлено двумя способами:

1. По инициативе пользователя. Пользователь самостоятельно закрывает страницу с помощью элементов графического интерфейса, например, с помощью кнопки "закрыть окно" в браузере.
2. По инициативе системы расчета. Для этого браузер, открывший страницу "Личного кабинета" абонента должен быть перенаправлен на адрес, указанный в параметре `inetra-callback-url`. Приложение должно отслеживать все URL, на которые перенаправляется браузер и закрывает браузер, в случае обнаружения перенаправления на адрес, закодированный в параметре `inetra-callback-url`.

#### Подписка на каналы

С целью подписки на каналы приложение переходит на страницу "Личного кабинета", передав в параметре `inetra-visit-reason` значение `buy-subscription`, а в параметре `inetra-channel-ids` — числовые идентификаторы каналов, на которые абонент хочет подписаться.

Числовые идентификаторы каналов могут быть получены клиентом из списка каналов (см. документы [M3U8][m3u-extending] и [XSPF][xspf-extending]) или посредством связывания по названию канала при помощи [Media Guide API][media-guide-api].

<span style="color:#f00">Внимание!</span> Если приложение не сможет определить числовой идентификатор канала, приложение передаст только причину визита абонента (`inetra-visit-reason=buy-subscription`), без указания выбранного пользователем канала.

При покидании пользователем страницы автоматизированной системы расчета приложение перечитывает список каналов, чтобы отобразить изменения в доступности. При этом если оборудованию провайдера требудет время для применения новой конфигурации, ожидаемое время доступа необходимо указать в поле `pending-till` для купленного канала.

#### Родительский контроль

По умолчанию приложение ограничивает доступ к аудиовизуальным материалам, не предназначенным лицам не достигшим совершеннолетия. Чтобы получить доступ до подобных материалов необходимо подтвердить возраст (достижение совершеннолетия) одним из двух возможных методов:

- путем сильной аутентификации в "Личном кабинете" Оператора;
- путем обращения в контакт–центр Оператора.

Подтвердив возраст единожды, абонент может установить PIN–код родительского контроля для доступа к нежелательным аудиовизуальным материалам или убрать ограничения вовсе. В случае забывания PIN–кода абонент может повторно подтвердить свой возраст для получения авторизации на сброс PIN–кода родительского контроля одним из методов, указанных выше.

Подтверждение возраста путем сильной аутентификации в "Личном кабинете":

1. клиент должен перейти на веб–страницу "Личного кабинета", передав в качестве параметра `inetra-visit-reason` значение `reset-parental-pincode`;
2. абонент должен ввести логин и пароль, выданные Оператором;
	- пройти дополнительные шаги для подтверждения возраста (если требуется).

Подтверждение возраста путем обращения в контакт–центр Оператора:

1. Абонент должен совершить звонок в контакт–центр Оператора;
2. После подтверждения пользователем факта совершения звонка, клиент должен выполнить обращение к веб–странице "Личного кабинета" любым браузером без отображения графического интерфейса, передав в качестве параметра `inetra-visit-reason` значение `reset-parental-pincode-via-call-center`;
	- если для обращения к веб–странице "Личного кабинета" требуется аутентификация, сервер вернет ответ с HTTP кодом `401`. Для прохождения аутентификации клиент должен воспользоваться запрошенными ранее аутентификационными данными или запросить их у пользователя. Рекомендуется использовать аутентификацию по методу HTTP Basic;
	- если автоматизированной системе расчетов не удалось верифицировать, что абонент подтвердил свой возраст путем обращения в контакт–центр Оператора, то сервер вернет ответ с HTTP кодом `403`;
	- при успешном завершении автоматизированная система расчетов должна сбросить признак подтверждения пользователем возраста через контакт–центр.

При успешном завершении процедуры подтверждения возраста (независимо от используемого метода) сервер выполнит перенаправление на адрес, указанный в параметре `inetra-callback-url`, передав дополнительно в параметре `expire_in` время, в течении которого действует авторизация на сброс (или установку) PIN–кода родительского контроля.

##  Кадрирование и изменение пропорций изображений каналов стандартной четкости [crop-n-aspect-ratio]

Некоторые каналы периодически вещают изображение с применением [техники Letterboxing][wiki-letterboxing-ru]. Для того, чтобы на устройствах с широкоформатным экраном полезная часть изображения занимала большую его часть, оператор может указать рекомендуемый способ кадрирования транслируемого изображения.

Параметр `crop`, отвечающий за кадрирование, состоит из двух положительных целых чисел от `0` до `100`, разделенные двоеточием: `X:Y`.

* `X` — ширина изображения в процентах от ширины кадра, которую нужно гарантированно показать, остальное можно обрезать
* `Y` — высота изображения в процентах от высоты кадра, которую нужно гарантированно показать, остальное можно обрезать

При обрезании картинки результирующий прямоугольник должен находиться по центру исходного изображения.

Для примера рассмотрим канал, иногда передающий большую часть времени "полезную" картинку в формате 16:9, вписанную в полный кадр 768x576. Если не применить кадрирование, на широкоформатном экране она будет иметь поля со всех сторон. Применив кадрирование приложение вырезает прямоугольник с заданными шириной и высотой, а затем вписывает ее в область отображения видео:

![Оригинальное изображение размером 768x576 с помощью указанного оператором IPTV параметра `crop=100:75` обрезается до размера 768x432, а затем масштабируется до размеров экрана (в случае FullHD — в 2,5 раза).](img/crop-example.png?p=plain)

Кадрирование применяется только на устройствах с широкоформатным экраном.

Изменение [пропорций изображения][wiki-aspect-ratio-ru] может понадобиться каналам с неквадратными пикселями. Для видеопроигрывателей, не понимающих [анаморфное вещание][wiki-anamorph-ru], оператор может дополнительно указать параметр `aspect-ratio`, указывающий истинные пропорции вещаемого эфира. Например:

![Оригинальное SDTV изображение размером 768x576 с помощью параметра `aspect-ratio=16:9` растягивается до размеров 1024x576, а затем масштабируется (в случае FullHD — в 1,875 раз), при этом можно наблюдать исправление пропорций в изображении.](img/anamorph-example.png?p=plain)
