# О чем данный раздел?

Данный раздел содержит описание способов взаимодействий приложений, запущенных на устройствах пользователя взаимодействовать с окружающим миром. При этом приложению мир представляется:

- как множество территорий, которые имеют между собой отношение вложенности, родительской для всех является территория "Весь мир";
- как множество операторов связи, которые предоставляют связность в интернете. Операторы связи могут объединяться между собой в группы дешевого обмена трафиком, также называемые ареалами;
- как множество поставщиков услуг, предоставляющих свои сервисы. Каждая услуга (или "сервис") предоставляется на определенной территории и/или оператору связи.

Операторы связи и поставщики услуг объединяются в единую сущность под названием "контрагент" и именно под таким названием встречаются в документации.

Единой точкой получения информации о доступных сервисах является [Регистратура][registry-doc], которая [заполняется][registry-filling-recommendations] следующими участниками:

1. ООО "Инетра", является разработчиком Регистратуры и ее модератором;
2. Контрагенты, предоставляющие свои услуги через Регистратуру. ООО "Инетра" также является и поставщиком некоторых услуг, и имеет отдельные права на редактирование собственных услуг.

Программное обеспечение получает информацию с помощью [Registry API][registry-api-ref].

## Различие синтаксиса и семантики

В данном разделе документации описываются лишь способы общения программного обеспечения и сервисов. При этом, у различных сервисов могут быть одинаковые механизмы передачи информации (например, связка HTTP + JSON), способы упаковки и структуры данных, но разные смыслы.

Обратимся за примером к TV API. У сообщения `Channel` имеется поле `access`, отвечающее за наличие доступа у абонента к данному каналу. Однако, не все сервисы, работающие по TV API, могут сообщить информацию о доступности канала. Допустим, у абонента *А*, который находится в Москве, доступны следующие сервисы:

- IP–телевидение от его оператора связи, скажем, "Ростелеком";
- Кабельное телевидение от провайдера "Стрим";
- Интернет–канал "Первый";
- Телепрограмма от "Инетры".

Каждый провайдер, предоставляющий непосредственное вещание "Первого" канала может передать информацию о доступности или недоступности канала для конкретного абонента. Сервис "Телепрограмма", напротив, сделать этого не может, так как не имеет (и, в общем случае, никогда не сможет получить) доступа к автоматизированной системе расчета с абонентами ни одного из поставщиков услуг вещания "Первого" канала.

Поэтому для сервисов, предоставляемых одним API, отдельно оговаривается, какие параметры для них имеют или не имеют смысла.

На данный момент все API описаны способом Google Protocol Buffers. Как его понимать описано на отдельной странице.

## Связи между сервисами

Между сервисами могут существовать связи. Характер связи определяется типом сервисов, участвующих в ней. Связи между сервисами определяются как "многие–ко–многим".

# Типы сервисов контрагентов

На момент написания данной документации существуют следующие типы сервисов:

- Каталог фильмов, афиша
- IP–телевидение
- Запись телепередач
- Файлообменная сеть "Пирс"
- Универсальная телепрограмма
- Авторизационный сервис
- Сервис отправки уведомлений
- Сервис подписок на получение уведомлений
- Трекинг событий

Сервис "Peers.TV", предоставляемый ООО "Инетра", является смесью сервисов "IP–телевидения" и "Запись телепередач" и на данный момент выделен в отдельную сущность. В дальнейшем он будет разбит на два сервиса, как и положено.


## Каталог фильмов

С помощью API данного сервиса можно получить список фильмов по указанному фильтру, детальную информацию о фильме, а также ссылки на файлы фильма в файлообменной сети "Пирс".

На данный момент сервис предоставляется единолично ООО "Инетра" на территории "Весь мир". Возможно зеркалирование сервиса у провайдеров–партнеров, например, ООО "Владлинк", предоставляющий данный сервис для своих абонентов.

## IP–телевидение

Сервис позволяет смотреть эфир различных телеканалов. Предоставляется множеством провайдеров, обычно только на своей территории влияния. В качестве API зачастую используются списки каналов, хранящиеся в файлах на серверах провайдера в XSPF или M3U форматах. Некоторые операторы генерируют для абонентов список, состоящий только из бесплатных и уже купленных каналов. Одним из таких примеров является ООО "Новотелеком".

Сервис может использовать различные способы доставки контента абоненту, на данный момент основным является multicast, дополнительным, продвигаемым компанией "Инетра" — HTTP Live Streaming, поддерживающийся на большем количестве устройств, в отличие от первого, но имеющий свои недостатки. Один оператор связи может предоставлять одну и ту же услугу несколькими способами доставки, в том числе и одновременно.

Важным исключением является контрагент "Инетра", предоставляющий сервис "Peers.TV", частью которого также является вещание эфира телеканалов.

## Записи телепередач

Сервис позволяет смотреть записи эфира различных телеканалов. Предоставляется по TV API.

На данный момент единственным контрагентом является ООО "Инетра", предоставляющая услугу в рамках сервиса "Peers.TV".

## Файлообменная сеть "Пирс"

Сервис позволяет… обмениваться файлами. Предоставляется клиентами Peers и Pikachu, на данный момент осуществляется только по NMDC и ADC протоколам. В разработке находится еще один протокол, который будет поддерживаться только новым клиентом, Pikachu.

Услуга предоставляется несколькими операторами связи, основные из них это "Новотелеком" в Новосибирске и области, "Эртелеком" в различных регионах России, "E-Light" в Кемерово и области, а также "Владлинк" во Владивостоке.

## Универсальная телепрограмма

Сервис позволяет получать информацию о канале, в том числе расписания телепередач, в зависимости от территории пользователя. Сервис не привязан ни к одному поставщику услуг телевидения, носит информационный характер. Предоставляется в виде TV API, единственный поставщик — ООО "Инетра".

Данный сервис позволяет узнать:

- список идентификаторов (также известных как `cn-id`) каналов;
- о канале по его `cn-id`:
	- название;
	- описание;
	- логотип;
	- транслируемый выпуск телепередачи;
	- наличие расписания;
	- возрастное ограничение.
- расписание телепередач для канала за определенные даты, в которое входит:
	- название выпуска;
	- описание выпуска;
	- время начала выпуска;
	- продолжительность выпуска;
	- возрастное ограничение.

Данный сервис **не позволяет** и **не может быть использован** для получения:

- списка каналов провайдера;
- адресов вещания каналов;
- идентификаторов выпусков телепередач;
- ссылок на записи телепередач;
- информации о доступности канала.

За данной информацией надо обращаться к сервисам телевидения и записей телепередач соответствующих провайдеров. 

## Авторизационный сервис

Данный сервис может быть использован приложением: для получения по логину и паролю пользователя получить идентификатор сессии, используемый для доступа к другим сервисам. 
другими сервисами: по идентификатору сессии получить логин пользователя для внутренних нужд.

На данный момент (июль 2013) примеров сервисов нет.

## Трекинг событий

Сервис позволяет поставщику услуг отслеживать события, происходящие у приложения. Это может быть как статистические данные о продолжительности времени работы, так и сбор сведений о качестве предоставления услуг.

На одной и той же территории для одного сервиса может существовать несколько сервисов трекинга. Так, плеер IP–телевидения может отправлять статистику использования приложения своему разработчику, а события, характеризующие качество предоставляемой услуги IP–телевидения — провайдеру.

На данный момент предоставляется только "Инетрой", по протоколу [Tracking API][tracking-api-ref].
