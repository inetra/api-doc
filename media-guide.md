# Цель и смысл

Данный документ описывает программный интерфейс (API) сервиса  Media Guide, ранее известный как TV Guide ("программа телепередач").

С помощью данного API  можно выяснить:

- название, описание канала
- текущую передачу для канала
- расписание выпусков передач (соответствующее переданной территории)
- описание выпусков передач
- идентификаторы: каналов, передач и выпусков передач

На замену настоящему API для получения информации о каналах, передачах и выпусках готовится [Media Catalogue API][catalogue-api-ref].

Получение ссылок на адреса вещания осуществляется:

- для каналов при помощи сервисов [IPTV][IPTV-doc], [Радио][radio-doc];
- для выпусков передач и сюжетов при помощи сервиса [Media Locator][media-locator-doc].

# Размещение и использование

Точка входа определяется [Регистратурой][registry-api-ref], при этом числовой идентификатор сервиса — `4`, строковый — `tv_guide`.

Запросы формируются следующим образом:

[registry-api-ref]: registry.md

	http://<path_to_api>/<method>.<format>?[parameters]

Где:

- `path_to_api` — путь до API, полученный из Регистратуры
- `method` — имя метода
- `format` — формат передачи данных, может быть одним из:
	- `json` — JSON
	- `xml` — XML
- `parameters` — параметры метода

Значения всех параметров необходимо кодировать для предотвращения неоднозначной интерпретации так, как это рекомендуется в [RFC3986].

[RFC3986]: http://tools.ietf.org/html/rfc3986

# Возрастные ограничения

В версии 2.1 введено понятие возрастного ограничения (возраст в годах, с которого можно потреблять медиа–контент без вреда для психики человека) для:

- выпуска передачи;
- передачи;
- канала.

Возрастные ограничения могут быть выставлены вручную или автоматически, на основании возрастных ограничений элементов, из которых состоит сущность. При автоматическом вычислении возрастного ограничения результат является максимумом возрастных ограничений элементов. Таким образом, для канала, возрастные ограничения передач которого колеблются от 0 до 18 лет, возрастным ограничением будет 18 лет.

Замечания:

1. Рекомендуется явно указывать территорию, для которой запрашивается программа передач.
2. Параметры `vitrina_timezone_name`, `vitrina_region` и `vitrina_geoname_id` используются для выбора программной зоны по меткам Vitrina TV (см. ниже). Параметр `t` при их наличии не используется для выбора зоны.

## Выбор программной зоны по меткам Vitrina [vitrina-zone-selection]

Параметры позволяют выбрать программную зону канала по меткам распространения версии канала Vitrina TV:

| параметр | соответствие в EPG/API Vitrina | пример |
|----------|--------------------------------|--------|
| `vitrina_timezone_name` | `timezone_name` (IANA Time Zone Database) | `Asia/Yekaterinburg` |
| `vitrina_region` | `region` (ISO 3166-2) | `RU-CHE` |
| `vitrina_geoname_id` | `geoname_id` (GeoNames) | `1486209` |

Несколько значений в одном параметре передаются через запятую.
Пустая строка означает отсутствие меток данного типа; строка без запятых — одну метку.

Обратная совместимость: параметр `geo` является синонимом `vitrina_timezone_name`.

Правило поиска зоны:

1. Все переданные значения `vitrina_timezone_name`, `vitrina_region` и `vitrina_geoname_id` объединяются в один набор меток.
2. Выбирается активная зона канала, в поле `geo` которой содержатся **все** переданные метки (логическое «И»).
3. Если точной зоны нет, используется зона с меткой `World/Anywhere` (если есть).

Клиент с плеером Vitrina: если Orbit отдал событие выбора версии, но все три метки пустые
(у версии нет `target_regions`), нужно передать `vitrina_timezone_name=World/Anywhere`.
Иначе параметры не попадут в запрос, и зона будет выбрана по территории `t`, а не по EPG Vitrina.

Правило выбора зоны применяется ко всем zone-sensitive методам Media Guide:

- [`schedule`][m-schedule] — расписание передач;
- [`channels`][m-channels] — поля `currentTelecast`, `scheduledDates`, `hasSchedule`;
- [`channel`][m-channel] — полная информация о канале (включая текущую передачу и даты).

Пример:

	.../schedule.json?channel=10338229&dates=2026-07-16&vitrina_timezone_name=Asia/Yekaterinburg&vitrina_region=RU-SVE

	.../channels.json?channel=10338245&fields=currentTelecast&t=126&vitrina_timezone_name=Asia/Novosibirsk

Пример для версии без региональных меток:

	.../schedule.json?channel=…&dates=2026-07-16&vitrina_timezone_name=World/Anywhere

# Методы Media Guide API [methods-tv-guide]

## `idbytitle` — получение списка идентификаторов каналов по их именам [m-idbytitle]

Запрос идентификаторов каналов, для которых в списке каналов провайдера (службы [IPTV][IPTV-doc], [Радио][Radio-doc]) не указан числовой идентификатор канала.

ВАЖНО: названия каналов передаются в кодировке текста UTF-8

### Обращение при помощи GET–запроса (<span style="color:#f00">устарело с версии 2.11</span>)

Параметры запроса:

 параметр | значение
----------|----------
`titles`  | Список названий каналов из списка каналов (службы IPTV или Радио), для которых запрашиваются идентификаторы

Список названий каналов кодируются следующим образом:

1. Все запятые (`,`) в названии каналов экранируются символом `\`
2. Преобразованные названия склеиваются с помощью запятой (`,`)

### Обращение при помощи POST–запроса

Список названий каналов, для которых запрашиваются идентификаторы, передается сообщением [`TitlesRequest`][p-titlesrequest] в теле запроса методом POST в формате запроса.

Формат ответа: сообщение [`ChannelsList`][p-channelslist].

Замечания:

- Порядок каналов в ответе строго соответствует порядку каналов в запросе
- Для каждого запрошенного названия возвращается либо один идентификатор, либо ни одного
- Если для канала не было найдено подходящего идентификатора, но на соответствующей позиции *должно присутствовать пустое* сообщение `Channel`
- Если для канала был найден подходящий идентификатор, то в сообщении `Channel` должны заполняться поля:
	- `title` — локализованное название найденного канала
	- `channelId` — идентификатор найденного канала
- При поиске канала по названию сервер:
	- производит регистро-независимый поиск по названию канала
	- производит замену символов `е` и `ё` при необходимости
	- производит замену символов табуляции и переноса строки на символ пробела
	- удаляет лишние пробелы в названии (лидирующие, хвостовые и идущие подряд несколько раз)

Замечание к серверной реализации: в случае если для переданного названия было найдено две и более сущности, то данный факт необходимо зафиксировать в журнале событий как ошибку.

## `channels` — получение информации о каналах [m-channels]

Дополнительные параметры:

 параметр  | значение
-----------|----------------
`channel`  | список числовых идентификаторов каналов через `,`
`fields`   | список полей через `,` из сообщения `Channel` (допускается указывать любое поле)

В независимости от переданного значения в параметре `fields` в выдаче для каждого сообщения `Channel` должно присутствовать поле `channelId`. Если параметр `fields` задан, то неуказанные в параметре поля (за исключением `channelId`) не должны попадать в выдачу.

Если параметр `fields` не задан, то по умолчанию в выдачу должны быть включены поля `title`, `alias`, `logoURL`, `ageRestriction`, `hasSchedule`, что гарантирует наличие в выдаче:

- названия канала;
- идентификатора канала (в том числе строкового);
- URL логотипа канала;
- возрастного ограничения;
- наличие расписания для канала (без указания точных дат).

Если параметр `channel` не задан, то должна быть возвращена информация по всем каналам.

Поля `currentTelecast`, `scheduledDates` и `hasSchedule` зависят от выбранной программной зоны.
При запросе каналов Vitrina/Orbit клиент должен передавать те же общие параметры `vitrina_*`, что и для [`schedule`][m-schedule]
(см. [Выбор программной зоны по меткам Vitrina][vitrina-zone-selection]).
Поле `currentTelecast` не входит в набор полей по умолчанию — его нужно явно указать в `fields`.

Пример:

	GET /tvguide/2/channels.json?channel=10338245&fields=currentTelecast,hasSchedule&t=126&vitrina_timezone_name=Asia/Novosibirsk&vitrina_region=&vitrina_geoname_id=

Формат ответа: сообщение [`ChannelsList`][p-channelslist].

## `schedule` — получение расписания для канала [m-schedule]

 параметр | по умолчанию | значение
----------|--------------|--------------
`channel` | отсутствует  | идентификатор канала
`dates`   | текущий день | даты, по которой выдать расписание (в формате `YYYY-MM-DD`, через запятую)

Выбор программной зоны — по общим параметрам `t` / `vitrina_*` (см. [Выбор программной зоны по меткам Vitrina][vitrina-zone-selection]).

Формат ответа: сообщение [`Schedule`][p-schedule].

Вне зависимости от порядка запрошенных дат расписание вернется в хронологическом порядке без повторов.

	message Telecast {
	  optional uint64 id = 1;
	  optional string title = 2;
	  optional string description = 3;
	  optional DateTime date = 4;
	  optional uint32 duration = 5;
	  optional string URL = 6;

Замечания:

- `title` — локализованное название выпуска
- `description` — локализованное описание выпуска
- `date` — время выхода выпуска по расписанию
- `duration` — продолжительность (в секундах)
- `URL` — адрес выпуска передачи на сайте
- `telecastImages` — изображения для передачи
- `tvShow` — передача. При наличии, указывается только идентификатор передачи
- `channel` — канал выпуска передачи. При наличии, указывается только идентификатор канала
- `ageRestriction` — возрастное ограничение для выпуска передачи
- `views_count` — количество просмотров (прослушиваний) выпуска передачи за все время
- `time_offset`:
	- для выпуска передачи: разница в секундах между фактическим временем выхода выпуска и временем по расписанию,
	- для сюжета выпуска передачи (задан `parent_id`): время в секундах от начала выпуска передачи до начала сюжета в нем.
- `parent_id` — идентификатор выпуска передачи, к которой относится сюжет (<span style="color:#0f0">новое в версии 2.8.1</span>)
- `categories` — категории передач (<span style="color:#0f0">новое в 2.9</span>)
- `ad_tags` — список идентификаторов рекламных тэгов
- `alias` — строковый идентификатор передачи

	message Schedule {

Замечание:

- `items_skipped` — количество пропущенных выпусков передач в выдаче
