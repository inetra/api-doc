# Введение [anchor-personal-office]

Для операторов–партнеров предусмотрена возможность интеграции "Личного кабинета" абонента автоматизированной системы расчетов (АСР) при помощи встраивания веб–страницы непосредственно в клиенте, что позволяет абоненту осуществлять покупку недоступных каналов или авторизацию на установку (сброс) PIN–кода родительского контроля.

Для этого оператор должен предоставить адрес веб–страницы "Личного кабинета" абонента автоматизированной системы расчетов, по которому приложение будет переходить для осуществления действий. Адрес на веб–страницу "Личного кабинета" может быть получен посредством [Registry API][registry-doc].

При переходе на такую страницу приложение передает дополнительные параметры методом GET протокола HTTP, позволяющие автоматизированной системе расчетов определить, с какой целью пришел абонент.

 параметр             | значения  | смысл
----------------------|-----------|-------
`inetra-visit-reason` | константа | причина визита абонента
`inetra-callback-url` | строка    | кодированный URL страницы обратного вызова
Подписка на каналы ||
`inetra-channel-ids`  | числа через `,` | числовые идентификаторы выбранных пользователем каналов
Активация промо–кода ||
`inetra-promo-code`   | строка    | введенный пользователем промо–код

Возможные причины визита, `inetra-visit-reason`:

- `buy-subscription` — желание абонентом подписаться на каналы;
- `authorize-for-parental-pincode` – желание абонента получить авторизацию на сброс (на установку) PIN–кода родительского контроля посредством принудительной аутентификации в "Личном кабинете".
- `check-parental-pincode-authorization` — запрос клиентом статуса выполненной ранее процедуры авторизации абонента на сброс PIN–кода родительского контроля (независимо от способа авторизации);
- `activate-promo-code` — желание пользователя активировать промо–код.

Если параметр `inetra-visit-reason` не указан, автоматизированная система расчетов может считать такое обращение как визит страницы "Личного кабинета" абонента без явно указанной цели.

Клиент должен отобразить веб–страницу как есть, отслеживая переходы на адрес, закодированный в параметре `inetra-callback-url`. Клиент не должен анализировать (в том числе коды ответов) или модифицировать содержимое веб–страницы "Личного кабинета".

Завершение взаимодействия пользователя со страницей автоматизированной системы расчета может быть осуществлено двумя способами:

1. По инициативе пользователя. Пользователь самостоятельно закрывает страницу с помощью элементов графического интерфейса, например, с помощью кнопки "закрыть окно" в браузере.
2. По инициативе системы расчета. Для этого браузер, открывший страницу "Личного кабинета" абонента должен быть перенаправлен на адрес, указанный в параметре `inetra-callback-url`. В случае перехода на указанный адрес клиент должен закрыть браузер.

Автоматизированная система расчетов Оператора может запретить доступ к интерфейсу "Личного кабинета" неабонентам, вернув специальным образом сформированную страницу.

## Подписка на каналы

С целью подписки на каналы приложение переходит на страницу "Личного кабинета", передав в параметре `inetra-visit-reason` значение `buy-subscription`, а в параметре `inetra-channel-ids` — числовые идентификаторы каналов, на которые абонент хочет подписаться.

Числовые идентификаторы каналов могут быть получены клиентом из списка каналов (см. документы [M3U8][m3u-extending] и [XSPF][xspf-extending]) или посредством связывания по названию канала при помощи [Media Guide API][media-guide-api].

<span style="color:#f00">Внимание!</span> Если приложение не сможет определить числовой идентификатор канала, приложение передаст только причину визита абонента (`inetra-visit-reason=buy-subscription`), без указания выбранного пользователем канала.

При покидании пользователем страницы автоматизированной системы расчетов приложение перечитывает список каналов, чтобы отобразить изменения в доступности. При этом если оборудованию провайдера требудет время для применения новой конфигурации, ожидаемое время доступа необходимо указать в поле `pending-till` для купленного канала.

## Родительский контроль

По умолчанию приложение ограничивает доступ к аудиовизуальным материалам, не предназначенным лицам не достигшим совершеннолетия, например, с порнографическим содержанием. Чтобы получить доступ до подобных материалов необходимо подтвердить возраст (достижение совершеннолетия) одним из двух возможных методов:

- путем сильной аутентификации в "Личном кабинете" Оператора;
- путем обращения в контакт–центр Оператора.

Подтвердив возраст, абонент может установить PIN–код родительского контроля для доступа к нежелательным аудиовизуальным материалам или убрать ограничения вовсе. В случае забывания PIN–кода абонент может повторно подтвердить свой возраст для получения авторизации на сброс PIN–кода родительского контроля одним из методов, указанных выше.

Подтверждение возраста путем сильной аутентификации в "Личном кабинете":

1. клиент должен перейти на веб–страницу "Личного кабинета", передав в качестве параметра `inetra-visit-reason` значение `authorize-for-parental-pincode`;
2. абонент должен ввести логин и пароль, выданные Оператором;
	- пройти дополнительные шаги для подтверждения возраста (если требуется).

Подтверждение возраста путем обращения в контакт–центр Оператора:

1. Абонент должен совершить звонок в контакт–центр Оператора;
	- пройти дополнительные шаги для подтверждения возраста (если требуется).

Автоматизированная система расчетов Оператора должна в течении некоторого времени хранить информацию об успешных и неуспешных попытках подтверждения возраста абонента с целью в дальнейшем сообщить статус авторизации. Успешный статус авторизации должен устанавливаться в АСР Оператора мгновенно по завершению абонентом необходимых шагов.

О факте завершения процедуры подтверждения возраста клиент может узнать по действию пользователя или по завершению взаимодействия с "Личным кабинетом". После подтверждения абонентом возраста клиент должен проверить статус авторизации при помощи обращения к веб–странице "Личного кабинета" любым браузером без отображения графического интерфейса, передав в качестве параметра `inetra-visit-reason` значение `check-parental-pincode-authorization`:

- eсли для обращения к веб–странице "Личного кабинета" требуется аутентификация, сервер должен вернуть ответ с HTTP кодом `401`. Для прохождения аутентификации клиент должен воспользоваться запрошенными ранее аутентификационными данными или запросить их у пользователя. Рекомендуется использовать аутентификацию по методу HTTP Basic;
- если процедура подтверждения возраста была прервана по инициативе автоматизированной системы расчетов (неподдерживаемый клиент, пользователь не является абонентом и т.д.), то должен быть возвращен ответ с HTTP кодом 200 и описанием причины;
- при успешном завершении запроса автоматизированная система расчетов должна сбросить признак подтверждения пользователем возраста.

Формат ответа — JSON, сообщение [`PINAuthorizationStatus`][message-pin-authorization].

В случае если пользователь отменил установку PIN–кода (покинул экран), клиент должен сбросить разрешение на смену PIN–кода родительского контроля.

## Активация промо–кодов

Контрагент может участвовать в совместных с Инетрой промо–акциях, для это контрагент должен реализовать механизм активации промо–кода в "Личном кабинете".

Промо–акции добавляются модератором со стороны Инетры, промо–коды могут быть добавлены контрагентом самостоятельно при помощи [Promo API][promo-api-doc].

С целью активации промо–кода приложение переходит на страницу "Личного кабинета", передав в параметре `inetra-visit-reason` значение `activate-promo-code`, а в параметре `inetra-promo-code` введенный пользователем промо–код.

Сервер, получив промо–код, должен проверить существование промо–кода, срок действия промо–кода и срок действия акции, в рамках которой был предоставлен промо–код. Сервер должен также проверить количество доступных активаций для данного промо–кода. В случае если промо–код не был найден, срок действия промо–кода или акции истек или количество активаций промо–кода израсходовано, то сервер должен сообщить пользователю, что активировать промо–код нельзя. 

В рамках промо–акции контрагент может предоставить пользователю платную услугу, например подписку на канал, поэтому при покидании пользователем страницы автоматизированной системы расчетов приложение перечитывает список каналов и список предоставляемых контрагентом услуг.

[promo-api-doc]: promo.md

# Описание сообщений в формате Google Protocol Buffers

## PINAuthorizationStatus —  проверка статуса авторизации на сброс PIN–кода родительского контроля [message-pin-authorization]

	message PINAuthorizationStatus {
	  enum Status {
	    ACCEPTED = 0;
	    REJECTED = 1;
	    NOT_REQUESTED = 2;
	  }

	  optional Status status = 1;
	  optional uint32 expire_in = 2 [default = 3600];
	  optional String reason = 3;
	}

Замечания:

- `status` — статус авторизации на установку (на сброс) PIN–кода родительского контроля:
	- `ACCEPTED` — подтверждена;
	- `REJECTED` — отклонена, не пройдены все шаги для подтверждения возраста;
	- `NOT_REQUESTED` — запросов на получение авторизации от абонента не поступало.
- `expire_in` — время в секундах, в течении которого клиент может установить или сбросить PIN–код родительского контроля. Значение по умолчанию — 3600 секунд;
- `reason` — причина отклонения авторизации, может присутствовать в случае статуса `REJECTED`.
