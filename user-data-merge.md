# О чем данный документ

Данный документ описывает API слияния учеток двух пользователей в одну.

Виды пользователей описаны в документах [История просмотра: варианты использования][ВИ История] и [Auth API], могут быть двух видов:

- с паспортом CN.ru
- анонимные

[Auth API]: auth.md
[ВИ История]: http://drug/iwiki/pages/viewpage.action?pageId=4063632

Слияние пользователей — суть слияние их деревьев данных. В первой версии API возможны слияния только двух пользователей, при этом хотя бы один из них должен быть анонимным.

# Общее описание

API работает по протоколу HTTPS для сокрытия передаваемых данных. Запросы составляются следующим образом:

	https://<path_to_api>/<method>?[extra_data]

Где:

- `path_to_api` — путь до API, полученный из Регистратуры
- `method` — название метода
- `extra_data` — дополнительные параметры метода

# Методы

## merge — слияние пользовательских данных

Дополнительные параметры:

параметр       | значение по умолчанию  |	смысл 
---------------|------------------------| ----- 
`mine_token`   | отсутствует            | токен доступа пользователя, которой производит слияние
`their_token`  | отсутствует            | временный токен доступа пользователя, который запросил слияние
`resolve_hint` | `auto`                 | в чью пользу разрешать конфликты слияния данных

Подсказка для разрешения конфликтов может принимать следующие значения:

- `mine` — при наличии конфликта слияния решить его в пользу владельца `mine_token`
- `their` — решать конфликт в пользу владельца `their_token`
- `auto`
	- если оба пользователя анонимны — равносильно `mine`
	- иначе конфликты решаются в пользу не анонимного пользователя

Возможные коды ответов:

код | значение
----|---------
200 | успешное слияние
400 | не задан обязательный параметр
401 | неверный токен доступа пользователя, производившего слияние
403 | неверный временный токен доступа пользователя, запросившего слияние
409 | произведена попытка слияния двух не анонимных пользователей

Формат ответа: пустой ответ.

# Алгоритм слияния данных пользователя

При слиянии деревьев данных двух пользователей они должны быть объединены в единое дерево, при этом всегда есть пользователь–источник данных и пользователь–получатель, а слияние данных — суть слияние корневого элемента пользователя–источника в корневой элемент пользователя–получателя.

При перед вызовом алгоритма слияния необходимо понять, в чью пользу принимать решения при конфликтах.

	function merge_users(dst, src, resolve_hint) {
	  if (resolve_hint === 'auto') {
	    if (src.anonymous) {
	      if (dst.anonymous) {
	        resolve_hint = 'mine';
	      } else {
	        resolve_hint = 'their';
	      }
	    } else { // src not anonymous
	      if (dst.anonymous) {
	        resolve_hint = 'mine';
	      } else {
	        return false;
	      }
	    }
	  }
	  merge_elements(dst.root, src.root, resolve_hint === 'mine');
	  return true;
	}

## Алгоритм слияния элементов

1. Произвести слияние атрибутов.
2. Для каждого дочернего элемента в источнике:
	* Если элемент с таким идентификатором отсутствует в элементе–получателе, то скопировать дочерний элемент в элемент–получатель, сохранив его идентификатор.
	* Иначе,
		* Если идентификатор дочернего элемента в источнике является автоматически сгенерированным,
			1. Сгенерировать новый элемент в получателе с идентификатором `new_name`;
			2. Скопировать дочерний элемент в новый элемент `new_name`;
			3. Сохранить `new_name` в качестве идентификатора нового элемента.
		* Иначе, если идентификатор дочернего элемента в получателе является автоматически сгенерированным,
			1. Сгенерировать новый элемент в получателе с идентификатором `new_name`;
			2. Переместить дочерний элемент получателя в новый элемент `new_name`;
			3. Сохранить `new_name` в качестве идентификатора нового элемента;
			4. Скопировать дочерний элемент источника в получатель.
		* Иначе, произвести алгоритм слияния одноименных дочерних элементов из источника в получатель.

Пример реализации алгоритма на псевдоязыке:

	function merge_elements(dst, src, dst_is_winner) {
	  merge_attributes(dst.attributes, src.attributes, dst_is_winner);
	 
	  for (child in src.children) {
	    var new_name;
	    if (!(child.id in dst)) {
	       dst[child.id] = child;
	    } else {
	      if (child.autogenerated_id) {
	         new_name = dst.generate_id();
	         dst[new_name] = child;
	         dst[new_name].id = new_name;
	      } elif (dst[child.name].autogenerated_id) {
	         new_name = dst.generate_id();
	         dst[new_name] = dst[child.id];
	         dst[new_name].id = new_name;
	         dst[child.id] = child;
	      } else {
	         merge_elements(dst[child.id], child, dst_is_winner);
	      }
	    }
	  }
	}

## Алгоритм слияния атрибутов элемента

При слиянии атрибутов элемента в результате всегда получается корректное множество атрибутов, в котором заполненность обязательных атрибутов полностью соответствует описанию результирующего списка классов элемента.

Поэтому слияние множества атрибутов равносильно слиянию значений атрибутов источника в элемент–получатель.

1. Для всех атрибутов элемента–источника:
	2. Если атрибут с данным `protobuf_numbered_tag` отсутствует в получателе, то сохранить его в получателе без изменений
	3. Иначе,
		1. Если атрибут является многозначным, то произвести слияние значений данного атрибута
		2. Иначе, если принято решение принимать решение конфликтов в пользу источника, записать значение атрибута источника в атрибут получателя

	merge_attributes(dst, src, dst_is_winner) {
	  for (protobuf_numbered_tag in src) {
	    if (!(protobuf_numbered_tag in dst)) {
	      dst[protobuf_numbered_tag] = src[protobuf_numbered_tag];
	    } else {
	      if (AttributeDescription[protobuf_numbered_tag].multivalue) {
	        merge_values(dst[protobuf_numbered_tag], src[protobuf_numbered_tag]);
	      } else {
	        if (dst_is_winner) {
	          dst[protobuf_numbered_tag] = src[protobuf_numbered_tag];
	        }
	      }
	    }
	  }
	}

### Слияние значений множественных атрибутов

Для множественных атрибутов одно и то же значение может храниться несколько раз. При этом в результате слияния количество каждого уникального значения возрасти не может.

Так, при слиянии массива значений `[1, 2, 2, 3, 3, 3]` с массивом `[1, 1, 1, 2, 2, 3]` результат: `[1, 1, 1, 2, 2, 3, 3, 3]`.

Реализация может иметь следующий алгоритм:

1. Завести результативный массив
2. Отсортировать оба массива (`src`, `dst`)
2. Завести указатели на элементы в массивах `src` и `dst`, `s` и `d`, соответственно
3. Пока находимся в рамках обоих массивов:
	1. Если значения `src[s]` и `dst[d]` равны, сохраняем это значение в результативном массиве и увеличиваем значения обоих индексов, `s` и `d`
	2. Иначе, находим меньшее из значений на текущих позициях, вставляем его в результативный массив и увеличиваем значение индекса того массива, где было найдено меньшее значение
4. Когда дошли до конца любого из массивов, в результативный массив записываем оставшиеся элементы из второго массива.

Пример реализации:

	function merge_values(dst, src) {
	  result = [];
	  dst.sort();
	  src.sort();

	  for (var d = 0, s = 0; d < dst.length && s < src.length; ) {
	    if (dst[d] === src[s]) {
	      result.push(dst[d]);
	      s++;
	      d++;
	    } else if (dst[d] > src[s]) {
	      result.push(src[s]);
	      s++;
	    } else { // dst[d] < src[s]
	      result.push(dst[d]);
	      d++;
        }
	  }
	  return result.concat(dst.slice(d), src.slice(s));
	}
