# Введение

Media Catalogue API предназначен для получения справочной информации о различных типах медиа-контента: каналы, передачи, фильмы, сериалы, а также предоставляет способ категоризации элементов каталога по различным критериям — рубрикам — для графического представления в пользовательских приложениях.

Данное API призвано заменить существующие [TVGuide API 2.0](tv-guide.md), [Films API 3.0](films.md).

## Цели разработки Catalogue API:

- введение новых возможностей по каталогизации;
- унификация [TVGuide API 2.0](tv-guide.md) и [Films API 3.0](films.md);
- поддержка нескольких форматов: JSON, protobuf;
- оптимизация клиент-серверного взаимодействия.

# Описание предметной области

Две наиболее крупных сущности из предметной области данного API — это *каталог* и *рубрикатор*.

## Каталог 

Содержит информацию об элементах медийного каталога: фильмах, сериалах, сериях, телевизионных каналах, телепередачах и их выпусках.

Каталог представлен множеством элементов, каждый из которых может включать в себя другие. Тогда этот элемент называется родительским по отношению к вложенным, а они, по отношению к нему — дочерними.

### Виды элементов каталога

Элементы каталога могут быть представлены в унифицированном виде за счет сходства свойств у различных сущностей — фильмов, телепередач, серий и т.д.

Виды элементов каталога:

 код | смысл
-----|----------
`0`  | группа элементов
`1`  | фильм, телесериал или телепередача
`2`  | серия или выпуск телепередачи
`3`  | телевизионный канал
`4`  | трейлер

С помощью вложенности элементов каталога реализуется:

1. Расписание эфира вещания для канала. Расписание выпусков телепередач (элементов с кодом 2) является списком дочерних элементов для телевизионный канала (элемента с кодом 3);
2. Серии у телесериала;
3. Выпуски телепередач являются списком дочерних элементов для телепередачи;
4. Сезоны телесериала;
5. Трейлеры фильма.

## Таг [tag]

Метка или ключевое слово, используемое для категоризации, поиска, задания внутренней структуры.

## Фильтр [filter]

Набор правил, применяемых к медиа-каталогу для получения упорядоченной выборки элементов.

## Рубрикатор [rubricator]

Рубрикатор организует простую для пользователя систему навигации по медиа–каталогу. С точки зрения разработчика рубрикатор представляет из себя набор пунктов меню, каждый из которых несет определенный смысл при построении пользовательского интерфейса.

Например, в телеприставке NV101 API поставляет в графическую оболочку системы меню-рубрикатор, а в приложении Peers.TV — различные разделы: Популярное, тематические подборки.

Структура рубрикатора может отличаться для разных языков, территории, а также может иметь несколько представлений для разных клиентских приложений.

### Пункт меню [menu-type]

Пункт меню описывает определенный элемент пользовательского интерфейса:

- **Фиксированный пункт меню** — данный пункт отображается в интерфейсе, можно выполнить переход. Данный пункт меню подразумевает подборку элементов каталога. Существует особый случай фиксированного пункта меню, ссылающийся на элементы, хранимые в хранилище пользовательских данных [User Data][user-data];
- **Пункт меню единственного выбора** — данный элемент подразумевает возможность выбора только одного значения;
- **Пункт меню для множественного выбора** — одновременно могут быть выбрано несколько значений;
- **Пункт меню для задания сортировки** — одновременно может быть выбрано только один вариант сортировки;
- **Пункт меню для поиска** — данный пункт меню несет описательный характер критериев поиска: область поиска, сортировка — при этом размещение данного пункта меню в интерфейсе зависит от дизайна.

[user-data]: user-data.md

Пример рубрикатора:

- Фильмы
	- Россия/СССР
	- Зарубежные
	- Жанр \[ все | боевик | драма | комедия | ужасы \]
	- Сортировка \[ по дате | по рейтингу | по популярности \]
- Мультфильмы
	- Россия/СССР
	- Зарубежные
	- Аниме
	- Сортировка \[ по дате | по рейтингу | по популярности \]
- Поиск

В данном примере "Фильмы", "Мультфильмы", а также вложенные рубрики "Россия/СССР", "Зарубежные", "Аниме" задаются при помощи *Фиксированного пункта меню*, сегментация по жанрам — при помощи *Пункта меню выбора для сегментации*, а сортировка — при помощи *Пункт меню для задания сортировки*.

#### Ограничения

Только *Фиксированный пункт меню* и *Пункт меню для поиска* могут содержать вложенные пункты меню, для других типов это не допустимо. В первом случае вложенные пункты меню реализуют подрубрики, сегментацию по одному критерию или нескольким, сортировку; в случае поиска — задают сегментацию области поиска и сортировку.

#### Обратная сторона

Для интерпретации на серверной стороне пункт меню рекомендуется рассматривать как набор фильтров, применяемых к медиа–каталогу. Таким образом, *Фиксированный пункт меню*, *Пункт меню единственного выбора*, *Пункт меню для множественного выбора* задают некоторую выборку из медийного каталога и соответствует запросу 'WHERE' на языке 'SQL'. *Пункт меню для задания сортировки* задает сортировку и соответствует запросу 'ORDER' на языке 'SQL'. *Пункт меню для поиска* не несет особого смысла и должен быть реализован стандартными для каталога средствами.

При описании пункта меню на серверной стороне допускается возможность использования стандартных и приватных фильтров, не доступных для использования клиентами.

# Сценарии использования

Рубрикатор:

- рубрики и подрубрики неограниченного уровня вложенности;
	- тематические подборки.
- задание критериев сортировки;
- задание одиночных и множественных критериев выборки;
- задание области поиска и сортировки;
- персональные рекомендации или избранное в интерфейсе, при помощи ссылок на User Data;

![Пример интерфейса][rubricator-iphone]

Каталог:

- поиск по названию элементов каталога;
- получение расписания для телевизионного канала;
- получение списка выпусков для телепередачи;
- получение похожих выпусков телепередачи;

# Описание API

API работает по протоколу HTTP, корень доступа может быть получен из Регистратуры при помощи [Registry API](registry.md). Сервисом Регистратура может быть предложено несколько различных типов рубрикаторов, например: рубрикатор "Peers.TV", рубрикатор "Детский Peers", рубрикатор "Peers".

Запросы к API составляются следующим образом:

	http://<path_to_api>/<api_version>/<method>.<format>?[params]

Где:

- `path_to_api` — путь до API, полученный в Регистратуре;
- `api_version` — мажорная версия API (должна быть равна `1`);
- `method` — имя метода API;
- `format` — ожидаемый формат ответа:
	- `json` — JSON;
	- `protobuf` — Google Protocol Buffers.
	- `png` — в формате Portable Network Graphics, только для метода `logo`;
- `params` — параметры метода.

API каталога состоит из следующих RPC-запросов:

- запрос меню-рубрикатора — `rubricator`;
- запрос информации из каталога по набору фильтров — `list`;
- запрос детальной информации об элементе каталога — `item`;
- запрос логотипа для элемента каталога — `logo`.

Все даты передаются в формате UNIX time, в UTC.

Текстовые значения параметров должны передаваться в кодировке UTF-8 с использованием кодирования URI (см. [RFC3986](http://tools.ietf.org/html/rfc3986)).

Составные значения для параметров разделяются запятыми.

## list — Запрос фильтрованного списка элементов каталога [method-list]

Cуществуют следующие стандартные параметры:

 параметр     | формат          | по умолчанию | смысл
--------------|-----------------|--------------|-------
Фильтрация ||||
`type`        | `число`         | отсутствует  | по типу элементов каталога
`ids`         | числа через `,` | отсутствует  | по идентификаторам элементов каталога
`parent_ids`  | числа через `,` | отсутствует  | по идентификаторам родителей
`child_id`    | `число`         | отсутствует  | по идентификатору потомка
`from `       | `число`         | отсутствует  | по дате выхода (левая граница)
`to`          | `число`         | отсутствует  | по дате выхода (правая граница)
`chart`       | `строка`        | отсутствует  | по особому типу коллекции
`search`      | `строка`        | отсутствует  | по названию
`titles`      | строки через `,`| отсутствует  | по названиям элементов
`tags`        | числа через `,` | отсутствует  | по идентификаторам тегов (по наличию хотя бы одного из списка)
`out_state`   | `строка`        | отсутствует  | по состоянию выхода
Представление данных ||||
`fields`      | строки через `,`| отсутствует  | список полей сообщения `CatalogueItem`, которые должны быть возвращены в ответе. По умолчанию возвращаются все доступные поля.
Параметры рубрикатора (см. [описание метода `rubricator`][method-rubricator]) ||||
`menu`        | `число`         | отсутствует  | идентификатор *Фиксированного пункта меню* из рубрикатора
`selected`    | `строка`        | отсутствует  | набор критериев для пунктов меню выбора и сортировки
Выдача упорядоченного списка элементов ||||
`quantity`    | `число`         | отсутствует  | максимальное количество элементов в выдаче
`skip`        | `число`         | `0`          | смещение элементов в выдаче
`order`       | `строка`        | отсутствует  | критерий сортировки

Параметр `chart` задает выборку по особому типу коллекции, к таким типам коллекций можно отнести Популярное, Лучшее, Выбор редакции и т.д. Количество элементов в в коллекции особого типа **должно быть** конечным, например, выпуск передачи с одним просмотром не может считаться популярным, а редакция не может рекомендовать одновременно все элементы каталога.

Поддерживаемые типы коллекций:

- `popular` — популярные элементы каталога. Критерий популярность явно не определен, в качестве критерия может использоваться статистика по количеству просмотров;
- `best` — лучшие по рейтингу(-ам) элементы каталога. (Критерии пока не определены для разных элементов каталога);
- `featured` — рекомендация редакции.

Фильтр `out_state` фактически задает отношение даты выхода и текущей даты. Для фильтра допустимы следующие значения:

- `out` — уже вышедшие на данный момент элементы каталога;
- `live` — элементы, находящиеся в эфире, например, транслируемый выпуск телепередачи на канале;
- `future` — еще не вышедшие элементы каталога, например, фильмы или выпуски телепередач.

Фильтр `titles` позволяет получить список элементов, соответствующих переданным названиям. Список названий элементов кодируются следующим образом:

1. Название элементов передается в кодировке текста utf–8;
2. Все запятые (`,`) в названии элементов экранируются символом косая черта (`\`).

Замечания к фильтру `titles`:

- порядок элементов в ответе соотвествует порядку названий в запросе;
- для каждого запрошенного названия возвращается одно сообщение `CatalogueItem`, если элемент не найден, то атрибуты элемента не передаются;
- данный фильтр может быть совместно использован с параметром `fields`, использование других параметров и фильтров не допустимо;
- При поиске по названию сервер:
	- производит регистронезависимый поиск по названию;
	- производит замену схожих символов по возможности (например, кириллических символов `ё` на `е`);
	- производит замену символов табуляции и переноса строки на символ пробела;
	- удаляет лишние пробельные символы в названии (лидирующие, хвостовые, повторяющиеся).

Каждый клиент может оптимизировать получение информации об элементах путем задания фильтрации по полям объекта  при помощи параметра `fields`.

Значение параметра `quantity` рекомендуется устанавливать равным двойному–тройному количеству элементов на экране устройства. Если данный параметр отсутствует, выбирается подходящее для указанного клиента[^fn-reference-to-client]. Длина страницы выдачи *не может* быть бесконечной или сознательно завышенной, поэтому сервер в любом случае *должен* ограничить quantity значением 200.

[^fn-reference-to-client]: Ссылка на клиента, который более не указывается в явном виде. Используя "авторизацию" (например, идентификатор клиента из Auth API), можно явно связать тип клиента, платформу, представление рубрикатора.

Порядок сортировки выборки задается набором фильтров выбранной коллекции, если упорядочивание не задано фильтром — решение о задании порядка принимается сервером, в таком случае результаты должны быть упорядочены по уменьшению релевантности.

Допустимые значения сортировки для параметра `order`:

- `date` — по дате выхода;
- `title` — по названию элемента каталога;
- `viewCount` — по количеству просмотров.

Для задания обратного порядка сортировки необходимо перед значением указать символ `!`.

Формат ответа: сообщение `CataloguePart`.

### Параметры рубрикатора

Формирование подборок на основе рубрикатора осуществляется при помощи параметров `menu` и `selected`. Рубрикатор является непрозрачной структурой для клиента, поэтому клиент должен придерживаться описанных ниже правил и не использовать параметры рубрикатора для метода `list` без использования рубрикатора.

Для параметра `menu` необходимо передать идентификатор *Фиксированного пункта меню*, данный пункт меню описан типом `FIXED` в сообщении `MenuItem`. Если для данного пункта меню задана ссылка на элементы в User Data, то список элементов может быть получен по данному адресу, а описание элементов при помощи стандартных параметров метода `list`.

Поиск реализуется при помощи стандартного фильтра `search`.

Для *Фиксированного пункта меню* и поиска рубрикатор допускает возможность задания нескольких критериев выборки или сортировки при помощи параметра `selected`. Данный параметр имеет особый формат записи и задается грамматикой:

	Selected := MenuItemID "," MenuValues [";" Selected ]
	MenuValues := MenuValue "," MenuValues
	MenuValues := MenuValue

	MenuValue := выбранное значение пункта меню
	MenuItemID := идентификатор пункта меню

Рассмотрим возможный вариант формирования значения для параметра `selected`:

	selected=1,боевик,фантастика;2,зарубежное кино;3,по названию

В данном случае значения "боевик" и "фантастика" выбраны для пункта меню с идентификатором 1, значение "зарубежное кино" — для пункта меню с идентификатором 2, значение "по названию" — для пункта меню с идентификатором 3.

Значения не должны содержать символы запятая (`,`) и точка с запятой (`;`), данное требование должно быть учтено на серверной стороне при формировании рубрикатора.

Замечание: пример приведен для наглядности, в общем случае, выбранные значения могут быть произвольными строками.

### Примеры использования фильтров

**Получение списка передач в эфире:**

	list.json?type=2&parent_ids=2912938472,229183374,2391233847&out_state=live

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `parent_ids` задает список идентификаторов каналов;
- `out_state` задает признак присутствия передачи "в эфире".

**Получение расписания для определенного канала:**

	list.json?type=2&parent_ids=229183374&from=1389433221&to=1389533221&order=date

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `parent_ids` задает идентификатор канала;
- параметры `from` и `to` задают временные границы выхода передач;
- `order` задает сортировку по дате.

**Получение списка популярных выпусков телепередач:**

	list.json?type=2&chart=popular

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `chart` задает выборку популярных передач.

Замечание:

- Популярное на основе агрегированной за несколько дней статистики просмотров не предусмотрено.

**Получение списка каналов с названиями и логотипами:**

	list.json?type=3&fields=id,title,has_logo

где:

- `type` задает тип элементов медийного каталога — телевизионные каналы;
- `fields` задает список полей, которые должны присутствовать в каждом сообщении `CatalogueItem` списка.

## item — Запрос детальной информации об элементе каталога

 параметр     | формат         | по умолчанию | смысл
--------------|----------------|--------------|-------
`id`          | `число`        | отсутствует  | Идентификатор элемента каталога

Формат ответа: сообщение `CatalogueItem`

Пример запроса:

	item.json?id=229183374

где:

- `id` соответствует элементу каталога с идентификатором 229183374.

## logo — Запрос логотипа для элемента каталога

 параметр     | формат         | по умолчанию | смысл
--------------|----------------|--------------|-------
`item`        | `число`        | отсутствует  | Идентификатор элемента каталога
`menu`        | `число`        | отсутствует  | Идентификатор элемента меню рубрикатора
Представление данных ||||
`profile`     | `строка`       | `web`        | желаемый профиль логотипа, постера
`strict`      | `true`, `false`| `false`      | возращать логотип только при точном соотвествии параметров представления
`resolution`  | `WIDTHxHEIGHT` | отсутствует  | желаемое разрешение логотипов, постеров

Данный метод производит перенаправление на адрес запрашиваемого ресурса. Для данного метода не предусмотрено получение списка логотипов в формате protobuf или JSON.

Для логотипов элементов медиа–каталога может существовать несколько профилей отображения, адаптированных под дизайн или возможности платформы. Чтобы задать желаемый профиль отображения необходимо указать параметр `profile`, в случае отсутствия изображения с запрошенным профилем сервер вернет изображение по умолчанию.

Поддерживаемые значения для параметра `profile`:

- `web` — адаптированный для отображения в вебе, СмартТВ или STB;
- `android` — адаптированный для устройств на базе Андроид;
- `ios` — адаптированный для устройств на базе iOS.

Также можно указать желаемые размеры логотипов для элементов медиа-каталога при помощи параметров `resolution`, если данный параметр указан, то сервер вернет наиболее близкое по размеру изображения, но не меньше запрашиваемого, если подходящего изображения не найдено, то будет возвращено изображение по умолчанию.

При указании параметра `strict` со значением `true` сервер должен вернуть HTTP код `404` с пустым телом ответа, если логотип с запрашиваемыми параметрами представления не найден.

Пример запроса:

	logo.png?item=229183374&profile=android

где:

- `item` соответствует элементу каталога с идентификатором 229183374.

# Спецификация API для Protocol Buffers

## FilterValue, MenuItem, Menu — рубрикатор

	enum MenuItemType {
	    FIXED = 1;
	    SEARCH = 2;
	    SELECT = 3;
	    MULTISELECT = 4;
	    ORDER = 5;
	}

	message SelectableValue {
	    optional string title = 1;
	    optional string value = 2;
	    optional bool selected_by_default = 3; [default = false]
	}

	message MenuItem {
	    optional int32 id = 1;
	    optional MenuItemType type = 2;
	    optional string title = 3;
	    repeated MenuItem submenu = 4; // Только для FIXED, SEARCH

	    repeated SelectableValue values = 5; // Только для SELECT, MULTISELECT, ORDER
	    optional string user_data_path = 6; // Только для FIXED
	}

	message Menu {
	    repeated MenuItem menu = 1;
	}

Замечания:

- `id` — идентификатор пункта меню;
- `title` — локализованное название пункта меню;
- `type` — [вид пункта меню][menu-type];
- `submenu` — вложенные пункты меню;
- `values` — набор критериев выборки или сортировки;
	- `SelectableValue.title` — локализированное название критерия;
	- `SelectableValue.value` — значение фильтра для выбранного критерия;
	- `Filter.selected_by_default` — признак указывающий, что фильтр выбран по умолчанию.
- `user_data_path` — путь в [User Data API][user-data], по которому могут быть найдены идентификаторы элементов каталога.

Типы пунктов меню:

- `FIXED` — *Фиксированный пункт меню*;
- `SEARCH` — *Пункт меню для поиска*
- `SELECT` — *Пункт меню единственного выбора*;
- `MULTISELECT` — *Пункт меню для множественного выбора*
- `ORDER` —  *Пункт меню для задания сортировки*


## CataloguePart — выборка из медиа-каталога

	message CataloguePart {
	  repeated CatalogueItem items = 1;
	  optional int32 total_count = 2;
	  optional int32 items_skipped = 3 [default = 0];

	  optional int64 expires = 4;
	  optional int32 ttl = 5;
	}

Замечания:

- `items` — множество элементов каталога;
- `total_count` — общее количество элементов в фильтрованном множестве;
- `items_skipped` — количество пропущенных элементов в выдаче;
- Поля `expires` и `ttl` задают время в секундах, абсолютное (в UTC) и относительное, соответственно, в течение которого приложение может кэшировать ответ сервера. Эти два поля **не должны** присутствовать в ответе одновременно.

## CatalogueItem — элемент каталога

	enum CatalogueItemType {
	    option allow_alias = true;
	    GROUP = 0;

	    FILM = 1;
	    SERIAL = 1;
	    TVSHOW = 1;

	    SERIE = 2;
	    TELECAST = 2;

	    TV_CHANNEL = 3;

	    TRAILER = 4;
	}

	enum CatalogueItemOutState {
		OUT = 0;
		LIVE = 1;
		FUTURE = 2;
	}

	message CatalogueItem {
	    optional int64 id = 1;
	    optional CatalogueItemType type = 2;

	    optional string title = 3;
	    optional string description = 4;
	    optional bool has_logo = 5;

	    repeated CatalogueItem parents = 6;
	    optional bool has_children = 7;

	    optional uint64 date = 8;
	    optional uint32 duration = 9;
	    optional uint32 age_restriction = 10;

	    repeated Rating ratings = 11;
	    repeated CatalogueItem similar_items = 12;
	    optional TagGroups tag_groups = 13;

	    optional int32 serial_number = 14;
	    optional CatalogueItemOutState out_state = 15;
	}

Замечания:

- Сообщение `CatalogueItem` является унифицированным элементом медийного каталога, для разных видов которого заполняются различные поля.
- Общие поля для всех элементов:
	- `id` — уникальный (в рамках каталога) числовой идентификатор;
	- `type` — тип элемента каталога;
	- `title` — локализованное название;
	- `description` — локализованное  описание;
	- `has_logo` — признак наличия логотипа для элемента каталога;
	- `parents` — список прямых родительских элементов, указывается только тип и идентификатор элемента каталога. Для выпуска телепередачи таковыми являются канал и телепередача;
	- `has_children` — признак наличия дочерних элементов;
	- `date` — дата выхода, в секундах относительно UTC;
	- `duration` — продолжительность, в секундах;
	- `age_restriction` — возрастное ограничение;
	- `ratings` — рейтинги, [см. описание Rating][Rating-message];
	- `similar_items` — похожие элементы;
	- `tag_groups` — теги, [см. описание TagGroup][TagGroup-message];
	- `serial_number` — порядковый номер в родительском элементе (номер сезона или серии);
	- `out_state` — состояние выхода элемента каталога, например,  вышел в прокат, в эфире.
- Специфика для элементов вида "телевизионный канал":
	- наличие дочерних элементов `has_children` равносильно наличию расписания телепередач.

### Rating [Rating-message]

	message Rating {
	    optional int32 id = 1;
	    optional string title = 2;
	    optional int32 votes = 3;
	    optional float rating = 4;
	    optional float max_rating = 5;
	}

Замечания:

- `title` — название системы оценок, отображаемое пользователю ("Кинопоиск", "IMDB" и т.д.);
- `votes` — количество голосов;
- `max_rating` — максимальный рейтинг для системы оценок;
- `rating` — текущая оценка.

### Tag, TagGroup [TagGroup-message] — тег, группа тегов

	message Tag {
	    optional int64 id = 1;
	    optional string title = 2;
	}
	
	message TagGroups {
	    repeated Tag directors = 1;
	    repeated Tag actors = 2;
	    repeated Tag countries = 3;
	    repeated Tag genres = 4;
	}

Замечания:

- `Tag.title` — название тега, отображаемое пользователю;
- поля `TagGroups`:
	- `directors` — режиссеры;
	- `actors` — актеры;
	- `countries` — страны;
	- `genres` — драматургические жанры.
