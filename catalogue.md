# Введение

Media Catalogue API предназначен для получения справочной информации о различных типах медиа-контента: каналы, передачи, фильмы, сериалы, а также предоставляет способ категоризации элементов каталога по различным критериям — рубрикам — для графического представления в пользовательских приложениях.

Данное API призвано заменить существующие [TVGuide API 2.0](tv-guide.md), [Films API 3.0](films.md).

## Цели разработки Catalogue API:

- введение новых возможностей по каталогизации;
- унификация с [TVGuide API 2.0](tv-guide.md);
- поддержка нескольких форматов: JSON, protobuf;
- оптимизация клиент-серверного взаимодействия.

### Принятые решения

В качестве основного средства упаковки сообщений (вместо XML) выбрана библиотека Google Protocol Buffers. Она позволяет решить сразу несколько из заявленных целей:

- обеспечить возможность обратной совместимости при расширении передаваемого набора данных;
- уменьшить накладные расходы на генерацию/декодирование сообщения;
- уменьшить трудозатраты на разработку генератора/парсера сообщения.

# Описание предметной области

Две наиболее крупных сущности из предметной области данного API — это *каталог* и *рубрикатор*.

## Каталог 

Содержит описания фильмов, сериалов, их сезонов и серий, телевизионных каналов, телепередач и их выпусков.

### Виды элементов каталога

Каталог представлен множеством элементов, каждый из которых может включать в себя другие. Тогда этот элемент называется родительским по отношению к вложенным, а они, по отношению к нему — дочерними.

Виды элементов каталога:

 код | смысл
-----|----------
`0`  | группа элементов
`1`  | фильм, телесериал или телепередача
`2`  | серия или выпуск телепередачи
`3`  | телевизионный канал
`4`  | трейлер

С помощью вложенности элементов каталога реализуется:

1. Расписание эфира вещания для канала. Расписание выпусков телепередач (элементов с кодом 2) является списком дочерних элементов для телевизионный канала (элемента с кодом 3);
2. Серии у телесериала;
3. Выпуски телепередач являются списком дочерних элементов для телепередачи;
4. Сезоны телесериала;
5. Трейлеры фильма.


## Таг [tag]

Метка или ключевое слово, используемое для категоризации, поиска, задания внутренней структуры.

## Фильтр [filter]

Набор правил, используемых для формирования выборки элементов каталога.

*Фильтр* может быть фиксированным или изменяемым. Фиксированный фильтр содержит один критерий фильтрации. Изменяемый фильтр содержит несколько критериев фильтрации, один из которых может быть впоследствии выбран пользователем. Поиск является особым типом фильтра, в котором пользовательский ввод является значением фильтра.

Фиксированный фильтр может включать в себя другие фильтры. Изменяемый фильтр ничего в себя включать не может.

Пример:

- Фильмы
	- Россия/СССР
	- Зарубежные
	- Жанр \[ все | боевик | драма | комедия | ужасы \]
	- Сортировка \[ по дате | по рейтингу | по популярности \]
- Мультфильмы
	- Россия/СССР
	- Зарубежные
	- Аниме
	- Сортировка \[ по дате | по рейтингу | по популярности \]

## Рубрикатор [rubricator]

Рубрикатор организует простую для пользователя систему навигации по медиа–каталогу. С точки зрения разработчика рубрикатор представляет из себя набор коллекций, каждая из которых может быть получена в результате применения списка фильтров коллекции к медиа–каталогу. Каждый из фильтров, в свою очередь, определяет способ выбора элементов каталога или способ их упорядочивания. Для формирования набора фильтров выбранной категории необходимо объединить фиксированные фильтры, текущего уровня и находящиеся выше по иерархии, а также выбранные изменяемые фильтры для данной коллекции.[^fn-filters-set]

Например, в телеприставке NV101 API поставляет в графическую оболочку системы меню-рубрикатор, а в приложении Peers.TV — различные разделы: Популярное, тематические подборки.

Структура рубрикатора может отличаться для разных языков, территории, а также может иметь несколько представлений для разных клиентских приложений.

[^fn-filters-set]: В случае формирования структуры рубрикатора для каждого клиента, можно отказаться от необходимости объединения фиксированных фильтров, находящихся выше по иерархии, в данном случае будет достачно передать идентификатор пункта меню текущего уровня и набор изменяемых фильтров, задающих выборку или упорядочивание. Однако в любом случае необходимо явно описать какие критерии фильтрации упорядочивания *могут* использоваться при создании рубрикатора.

### Виды коллекций [collection-type]

Для каждой коллекции могут быть заданы параметры отображения:

- `SEARCHABLE` — присутствует поиск по коллекции;
- `EMBEDDED` — является подколлекцией другой коллекции, необходимо отобразить элементы коллекции в рамках родительской коллекции.

Коллекция с типом отображения `EMBEDDED` **не может** включать дочерние элементы.

### Смыслы коллекций [collection-sense]

Каждая коллекция может обладать собственной семантикой, которая в приложении может быть использована для перемещения данной коллекции в отдельный элемент интерфейса.

Возможные смыслы:

- `Featured` — рекомендованные. Подборка контента редакцией каталога.
- `New` — новинки.
- `Popular` — популярное.

# Описание API

API работает по протоколу HTTP, корень доступа может быть получен из Регистратуры при помощи [Registry API](registry.md). Запросы к API составляются следующим образом:

	http://<path_to_api>/<api_version>/<method>.<format>?[params]

Где:

- `path_to_api` — путь до API, полученный в Регистратуре
- `api_version` — мажорная версия API (должна быть равна `1`)
- `method` — имя метода API
- `format` — ожидаемый формат ответа:
	- `json` — JSON
	- `protobuf` — Google Protocol Buffers
- `params` — параметры метода

API каталога состоит из следующих RPC-запросов:

- запрос меню-рубрикатора - `rubricator`
- запрос информации из каталога по набору фильтров - `list`
- запрос детальной информации об элементе каталога — `item`

Все даты передаются в UNIX time, в UTC.

Текстовые значения параметров должны передаваться в кодировке UTF-8 с использованием URI encoding.
Составные значения для параметров разделяются запятыми.

## Общие параметры запросов

Для формировании ответа с учетом особенностей клиента, во все запросы необходимо включать следующие общие параметры:

параметр         | формат     | по умолчанию | смысл
-----------------|------------|--------------|----------------
`client`         |`строка`    | отсутствует  | Идентифицирует тип клиента, например `Peers.TV`

[ISO 639-1]: http://ru.wikipedia.org/wiki/ISO_639-1

## list — Запрос фильтрованного списка элементов каталога

Cуществуют следующие стандартные параметры:

 параметр   | формат          | по умолчанию | смысл
------------|-----------------|--------------|-------
Фильтрация ||||
`type`      | `число`         | отсутствует  | по типу элементов каталога
`ids`       | числа через `,` | отсутствует  | по идентификаторам элементов каталога
`parent_ids`| числа через `,` | отсутствует  | по идентификаторам родителей
`child_id`  | `число`         | отсутствует  | по идентификатору потомка
`from `     | `число`         | отсутствует  | по дате выхода (левая граница)
`to`        | `число`         | отсутствует  | по дате выхода (правая граница)
`coll_type` | `строка`        | отсутствует  | по типу коллекции
`search`    | `строка`        | отсутствует  | по названию
`tags`      | числа через `,` | отсутствует  | по идентификаторам тегов [^fn-tags-functions]
`out_state` | `строка`        | отсутствует  | по состоянию выхода
Представление данных ||||
`logo_res`  | `WIDTHxHEIGHT`  | отсутствует  | желаемое разрешение постеров[^fn-logos-for-platrform]
`ss_res`    | `WIDTHxHEIGHT`  | отсутствует  | желаемое разрешение стоп–кадров
`fields`    | строки через `,`| отсутствует  | список полей сообщения `CatalogueItem `, которые должны быть возвращены в ответе. По умолчанию возвращаются все доступные поля.
Выдача упорядоченного списка элементов[^fn-orderby-note] ||||
`quantity`  | `число`         | отсутствует  | максимальное количество элементов в выдаче
`skip`      | `число`         | `0`          | смещение элементов в выдаче
`order`     | `строка`        | отсутствует  | сортировка выборки

При использовании рубрикатора в зависимости от выбранной категории должны быть заданы **дополнительные параметры**, обусловленные набором фильтров категории. В этом случае параметр "Имя фильтра" задается атрибутом `filter_name` из сообщения `Menu`, а значение - атрибутом `filter_value`, в случае фиксированного меню, или составным значением `value_name` из массива `values` сообщений `FilterValue`.

Параметр `coll_type` задает выборку по особому типу коллекции, к таким типам коллекций можно отнести Популярное, Лучшее, Выбор редакции и т.д. Поддерживаемые типы коллекций:

- `popular` — популярные элементы каталога. Критерий популярность явно не определен, в качестве критерия может использоваться статистика по количеству просмотров. Количество элементов в выборке Популярное **должно быть** конечным, выпуск передачи с одним просмотром не может считаться популярным;
- `best` — лучшие по рейтингу(-ам) элементы каталога. (Критерии пока не определены для разных элементов каталога);
- `featured` — рекомендация редакции.

Фильтр `out_state` фактически задает отношение даты выхода и текущей даты. Для фильтра допустимы следующие значения:

- `out` — уже вышедшие на данный момент элементы каталога;
- `live` — элементы, находящиеся в эфире, например, транслируемый выпуск телепередачи на канале.
- `future` — еще не вышедшие элементы каталога, например, фильмы или выпуски телепередач.

Рекомендуется устанавливать значение параметра `quantity` равным двойному–тройному количеству элементов на экране устройства. Если данный параметр отсутствует, выбирается подходящее для указанного клиента. Длина страницы выдачи *не может* быть бесконечной или сознательно завышенной, поэтому сервер в любом случае *должен* ограничить quantity значением 200.

Каждый клиент может оптимизировать получение информации об элементах путем задания фильтрации по полям объекта  при помощи параметра `fields`. Другими словами, не потребуется расширять стандартный набор полей в списке, в случае если этого потребует одна из версий приложений.

Порядок упорядочивания выборки задается набором фильтров выбранной категории, если упорядочивание на задано фильтром - решение о задании порядка принимается сервером.

Допустимые значения сортировки для параметра `order`:

- `date` — по дате выхода;
- `title` — по названию элемента каталога;
- `viewCount` — по количеству просмотров.

Для задания обратного порядка сортировки необходимо перед значением указать символ `!`.

[^fn-orderby-note]: Несмотря на название раздела, параметров сортировки нет. Считаю поддержку сортировки абсолютно необходимой, поскольку мы планируем поддерживать БОЛЬШИЕ каталоги, и в клиент *будет* запрашивать всякие разные подборки, в том числе «Новинки» (отсортировано по дате поступления в каталог в обратном порядке), «Фильмография» (отсортировано по дате выпуска фильмов на экран) и т.д.

[^fn-logos-for-platrform]: В угоду дизайна существуют несколько профилей для логотипов канала — для iOS(квадратные, залитые) и для андройда/веба (со скругленными углами, с контуром). А также различные размеры логотипов. Twitter, FB API предоставляют отдельный метод для получения изображения по типу "{item_id}/image" (или до URL Rewrite — "image?id={item_id}")

[^fn-tags-functions]: Фильтрация по тэгам может быть интересна с использованием разных операций: и, или.

Формат ответа: сообщение `CataloguePart`.

### Примеры использования фильтров:

**Получение списка передач в эфире:**

	list.json?type=2&parent_ids=2912938472,229183374,2391233847&out_state=live

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `parent_ids` задает список идентификаторов каналов;
- `out_state` задает признак присутствия передачи "в эфире".

**Получение списка передач, выходящих(или вышедших) на определенном канале:**

	list.json?type=2&parent_ids=229183374&from=1389433221&to=1389533221&order=date

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `parent_ids` задает идентификатор канала;
- параметры `from` и `to` задают временные границы выхода передач;
- `order` - задает сортировку по дате.

**Получение списка популярных выпусков телепередач:**

	list.json?type=2&coll_type=popular

где:

- `type` задает тип элементов медийного каталога — выпуски телепередач;
- `coll_type` — задает выборку популярных передач.

Замечание:

- Популярное на основе агрегированной за несколько дней статистики просмотров не предусмотрено.

**Получение списка каналов с названиями и логотипами:**

	list.json?type=3&fields=id,title,logo_url

где:

- `type` задает тип элементов медийного каталога — телевизионные каналы;
- `fields` задает список полей, которые должны присутствовать в каждом сообщении `CatalogueItem` списка.

## item — Запрос детальной информации об элементе каталога

 параметр | формат  | по умолчанию | смысл
----------|---------|--------------|-------
`id`      | `число` | отсутствует  | Идентификатор элемента каталога

Формат ответа: сообщение `CatalogueItem`

Пример запроса:

	item.json?id=229183374

где:

- `id` соответствует элементу каталога с идентификатором 229183374.

## FilterParam, Collection, CollectionSelector, CollectionList [^fn-paging-info]

	enum PresentationType {
	  SEARCHABLE = 1;
	  EMBEDDED = 2;
	}

	enum PresentationSense {
	  FEATURED = 1;
	  NEW = 2;
	  POPULAR = 3;
	}

	message FilterParam {
	  optional string name = 1;
	  optional string value = 2;
	}

	message CollectionSelector {
	  optional string title = 1;
	  optional bool is_default = 2;
	  optional FilterParam filter = 3;
	}

	message Collection {
	  optional fixed32 id = 1;
	  optional string title = 2;
	  optional PresentationType type = 3;
	  optional PresentationSense sense = 4;

	  optional string icon_url = 5;

	  repeated Collection collections = 6;
	  repeated FilterParam filters = 7;
	  repeated CollectionSelector selectors = 8;
	}

	message CollectionList {
	  repeated Collection items = 1;
	}

Замечания:

- `id` — идентификатор коллекции;
- `title` — локализованное название рубрики
- `icon_url` — адрес до изображения, используемого в качестве иконки для пункта меню
- `type` — [вид пункта меню][collection-type];
- `sense` — [смысл пункта меню][collection-sense];
- `collections` — вложенные коллекции;
- `filters` — параметры для формирования данной коллекции:
	- `FilterParam.name` — название фильтра;
	- `FilterParam.value` — значение фильтра.
- `selectors` — пользовательские фильтры;
	- `CollectionSelector.title` — название пользовательского фильтра;
	- `CollectionSelector.is_default` — значение по умолчанию;
	- `CollectionSelector.filter` — параметры для фильтрации.

## CataloguePart

	message CataloguePart {
	  repeated CatalogueItem items = 1;
	  optional int32 total_count = 2;
	  optional int32 items_skipped = 3 [default = 0];

	  optional int64 expires = 4;
	  optional int32 ttl = 5;
	}

Замечания:

- `items` — упорядоченное множество элементов каталога
- `total_count` — общее количество элементов в фильтрованном множестве
- `items_skipped` — количество пропущенных элементов в выдаче
- Поля `expires` и `ttl` задают время в секундах, абсолютное (в UTC) и относительное, соответственно, в течение которого приложение может кэшировать ответ сервера. Эти два поля не должны присутствовать в ответе одновременно

## CatalogueItem [^fn-snaphosts]

	enum CatalogueItemType {
	    option allow_alias = true;
	    GROUP = 0;

	    FILM = 1;
	    SERIAL = 1;
	    TVSHOW = 1;

	    SERIE = 2;
	    TELECAST = 2;

	    TV_CHANNEL = 3;

	    TRAILER = 4;
	}

	enum CatalogueItemOutState {
		OUT = 0;
		LIVE = 1;
		FUTURE = 2;
	}

	message CatalogueItem {
	    optional int64 id = 1;
	    optional CatalogueItemType type = 2;

	    optional string title = 3;
	    optional string description = 4;
	    optional string logo_url = 5;

	    optional int64 parent_id = 6;
	    optional bool has_children = 7;

	    optional uint64 date = 8;
	    optional uint32 duration = 9;
	    optional uint32 age_restriction = 10;

	    repeated Rating ratings = 11;
	    repeated CatalogueItem similar_items = 12;
	    optional TagGroups tag_groups = 13;

	    repeated string snapshots = 14;
	    optional int32 serial_number = 15;

		optional CatalogueItemOutState out_state = 16;
	}

Замечания:

- Сообщение `CatalogueItem` является генерализованным элементом медийного каталога, для разных видов которого заполняются различные поля.
- Общие поля для всех элементов:
	- `id` — уникальный (в рамках каталога) числовой идентификатор
	- `type` — вид элемента
	- `title` — локализованное название
	- `description` — описание
	- `logo_url` — ссылка на логотип элемента, в разрешении `logo_res`
	- `parent_id` — уникальный числовой идентификатор родителя. Указывается, если осуществлялась фильтрация по ключу `parent_ids`.
	- `has_children` — признак наличия дочерних элементов
	- `date` — дата выхода, в секундах относительно UTC
	- `duration` — продолжительность, в секундах
	- `age_restriction` — возрастное ограничение
	- `ratings` — рейтинги, [см. описание Rating][Rating-message]
	- `similar_items` — похожие элементы
	- `tag_groups` — тэги, [см. описание TagGroup][TagGroup-message]
	- `snapshots` — список ссылок на стоп–кадры, в разрешении `ss_res`
	- `serial_number` — порядковый номер в родительском элементе (номер сезона или серии)
	- `out_state` — состояние выхода элемента каталога, например,  вышел в прокат, в эфире.
- Специфика для элементов вида "канал телевидения":
	- наличие дочерних элементов `has_children` равносильно наличию расписания телепередач

[^fn-snaphosts]: Спорный момент с предоставлением снапшотов для медийных элементов при помощи Catalogue API.
