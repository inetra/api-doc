# Введение

Media Catalogue API предназначен для получения информации о различных типах медиа-контента: каналы, передачи, фильмы, сериалы, а также предоставляет способ категоризации элементов каталога по различным критериям для графического представления в пользовательских приложениях. В зависимости от приложения, структура каталога может отличаться. [^fn-content-filtration]

[^fn-content-filtration]: В случае формирования выборок на основе статистической информации необходимо гарантировать правомерность и применимость используемых статистических данных. Например, в случае с популярными передачами, необходимо использовать статистику просмотров для медиа-контента, доступного на данной территории. Структура рубрикатора также может отличаться в зависимости от территории или выбранного языка.

Например, в телеприставке NV101 API поставляет в графическую оболочку системы меню-рубрикатор, а также описания фильмов из каталога для каждого из рубрик меню.

Данное API призвано заменить существующие [TVGuide API 2.0](tv-guide.md), [Films API 3.0](films.md).

## Цели разработки Catalogue API:

- введение новых возможностей по каталогизации ;
- унификация с [TVGuide API 2.0](tv-guide.md);
- поддержка нескольких форматов: JSON, protobuf;
- оптимизация клиент-серверного взаимодействия.

## Принятые решения

В качестве основного средства упаковки сообщений (вместо XML) выбрана библиотека Google Protocol Buffers. Она позволяет решить сразу несколько из заявленных целей:

- обеспечить возможность обратной совместимости при расширении передаваемого набора данных;
- уменьшить накладные расходы на генерацию/декодирование сообщения;
- уменьшить трудозатраты на разработку генератора/парсера сообщения.

# Описание предметной области

Две наиболее крупных сущности из предметной области данного API — это *каталог* и *рубрикатор*.

## Каталог 

содержит описания фильмов, сериалов и их сезонов, телевизионных каналов, телепередач и их выпусков. Рубрикатор организует простую для пользователя систему навигации по медиа–каталогу. С точки зрения разработчика рубрикатор представляет из себя систему фильтров, применяемых к каталогу. Каждый из фильтров, в свою очередь, определяет способ выбора элементов каталога или способ их упорядочивания.

### Виды элементов каталога

Каталог представлен множеством элементов, каждый из которых может включать в себя другие. Тогда этот элемент называется родительским по отношению к вложенным, а они, по отношению к нему — дочерними.

Виды элементов каталога:

 код | значение
-----|----------
`0`  | группа элементов
`1`  | фильм, телесериал или телепередача
`2`  | серия или выпуск телепередачи
`3`  | телевизионный канал
`4`  | трейлер

С помощью вложенности элементов каталога реализуется:

1. Расписание эфира вещания для канала. Расписание телепередач (элементов с кодом 2) является списком дочерних элементов для канала (элемента с кодом 1).
2. Серии у телесериала.
3. Сезоны телесериала.
4. Трейлеры фильма.

Также в описании каждого элемента содержится информация, можно ли получить для него список источников вещания (с помощью [Media Locator API][media-locator-api-ref]).

[media-locator-api-ref]: media-locator.md?h=WEBDEV-6533

## Таг [tag]

Метка или ключевое слово, используемое для категоризации, поиска, задания внутренней структуры.

## Фильтр [filter]

Набор правил, используемых для формирования выборки элементов каталога.

*Фильтр* может быть фиксированным или изменяемым. Фиксированный фильтр содержит один критерий фильтрации. Изменяемый фильтр содержит несколько критериев фильтрации, один из которых может быть впоследствии выбран пользователем.[^user-defined-value-filter]

Фиксированный фильтр может включать в себя другие фильтры. Изменяемый фильтр ничего в себя включать не может.

Пример:

- Фильмы
	- Россия/СССР
	- Зарубежные
	- Жанр \[ все | боевик | драма | комедия | ужасы \]
	- Сортировка \[ по дате | по рейтингу | по популярности \]
- Мультфильмы
	- Россия/СССР
	- Зарубежные
	- Аниме
	- Сортировка \[ по дате | по рейтингу | по популярности \]

[^user-defined-value-filter]: Здесь надо упомянуть о пользовательском виде фильтра, когда задан параметр фильтрации, но не указано его значения.

## Рубрикатор [rubricator]

Представляет собой иерархическую структуру пунктов меню - именованных категорий, каждая из которых задается набором *фильтров*. Рубрикатор предназначен для организации навигации по различным категориям элементов каталога в пользовательских приложениях.

Для формирования набора фильтров выбранной категории необходимо объединить фиксированные фильтры, находящиеся выше по иерархии, а также изменяемые фильтры и выбранный фиксированный фильтр текущего уровня.[^fn-filters-set]

[^fn-filters-set]: В случае формирования структуры рубрикатора для каждого клиента, платформы, можно отказаться от необходимости объединения фиксированных фильтров, находящихся выше по иерархии, в данном случае будет достачно передать идентификатор текущей пункта меню уровня и набор изменяемых фильтров, задающих выборку упорядочивание или дополнительную фильтрацию. 

Пример формирования набора фильтров:

Допустим, выбрана рубрика "Фильмы", "Зарубежные" с сортировкой по дате, всех жанров. Соответственно набор фильтров для данной категории будет состоять из двух фиксированных фильтров "Фильмы", "Зарубежные" и двух изменяемых: сортировка по дате, все жанры.

### Виды пунктов меню [menu-item-types] 

Пункты меню бывают следующих видов[^fn-menu-types]:

- Фиксированные, fixed. Могут содержать другие подменю. При отрисовке пункта меню выглядит как обычная надпись без возможности выбора. При переходе пользователем на данный пункт в метод выборки контента добавляется фильтр из данного пункта.
- Изменяемые, selectable. Не могут содержать подменю. При отрисовке выглядят как принимающее одно из имеющихся значений. При выборе пользователем одного из значений в метод выборки контента добавляется фильтр из данного значения.
- Заменяемые, substitutional. Представляют собой особый вид фиксированного меню. Вместо отрисовки данного пункта меню он должен быть заменен списком элементов каталога, полученным благодаря фильтрации, описанной в данном пункте.
- Предоставляющие ввод пользователя. При выборе пользователем данного пункта меню необходимо запрашивать у пользователя ввод и использовать полученые данные в качестве значения фильтра. Таким образом реализуется, например, поиск.

[^fn-menu-types]: Заменить названия и описания названий пунктов меню на более подходящие, например: Category, Selector, Expandable, Search. (?)

### Смыслы пунктов меню [menu-item-sense]

Каждый пункт меню может иметь собственную семантику, которая в приложении может быть использована для перемещения данного пункта меню в отдельный элемент интерфейса.

Возможные смыслы:

- Рекомендованные, Featured. Подборка контента редакцией каталога.
- Новинки, New.
- Популярное, Popular.
- Поиск, Search.

# Описание API

API работает по протоколу HTTP, корень доступа может быть получен из Регистратуры при помощи [Registry API](registry.md). Запросы к API составляются следующим образом:

	http://<path_to_api>/<api_version>/<method>.<format>?[params]

Где:

- `path_to_api` — путь до API, полученный в Регистратуре
- `api_version` — мажорная версия API (должна быть равна `1`)
- `method` — имя метода API
- `format` — ожидаемый формат ответа:
	- `json` — JSON
	- `protobuf` — Google Protocol Buffers
- `params` — параметры метода

API каталога состоит из следующих RPC-запросов:

- запрос меню-рубрикатора - `rubricator`
- запрос информации из каталога по набору фильтров - `list`
- запрос детальной информации об элементе каталога — `item`

Все даты передаются в UNIX time, в UTC.

Текстовые значения параметров должны передаваться в кодировке UTF-8 с использованием URI encoding.
Составные значения для параметров разделяются запятыми.

## Общие параметры запросов

Для формировании ответа с учетом особенностей клиента, во все запросы необходимо включать следующие общие параметры:

параметр | формат | по умолчанию | смысл
-------------|------------|-------------------|----------------
`client`             | число | отсутствует | Идентифицирует тип клиента, например `Peers.TV`
`client_platform`|число| отсутствует | Идентифицирует платформу клиента, например `Android`
`client_version`| строка | отсутствует | Идентифицирует версию клиента, например `3.2.1 `
`t`                    | строка | автоматически определенная | Идентификатор территории из [Регистратуры][registry-api][^default-territory]
`lang`             | строка | отсутствует | Перечень предпочитаемых языков в виде двухбуквенных кодов, указанными в порядке приоритета. Коды языков должны соответствовать стандарту [ISO 639-1]. На основе переданных языков сервером может принять решение о выдаче той или иной локализации [^default-lang]

[ISO 639-1]: http://ru.wikipedia.org/wiki/ISO_639-1

API может поддерживать несколько представлений рубрикатора в зависимости:

- от типа целевых приложений — для продуктов Peers.TV, Peers и т.д.
- от платформы целевых приложений - iOS, Android, Desktop и т.д.

По мере расширения поддерживаемых клиентов и платформ будет расширяться набор поддерживаемых рубрикаторов.

тип клиента | значение
------------------|---------------
`Peers`          |  `1`
`Peers.TV`    |   `2`

платформа клиента[^fn-supported-platforms] | значение
-----------------------------|---------------
`Android`       |  `1`
`Desktop`      |  `2`
`iOS`             |  `3`

[^fn-supported-platforms]: Возможно, имеет смысл разделять планшеты от телефонов, для предоставления разных по типу рубрикаторов.

[registry-api]: registry.md

[^default-territory]: Значение по умолчанию для территории определяется каталогом с помощью метода `whereAmI` [Registry API][registry-api]

[^default-lang]: Какое значение для языка будет выбрано, если параметр отсутствует?

## rubricator — Запрос меню-рубрикатора

Дополнительные параметры: отсутствуют.

Формат ответа: сообщение `Menu`.

Пример запроса:

	rubricator.json?client=1&client-platform=2

где:

- `client` соответствует типу клиента – `Peers`.
- `client-platform` соответствует платформе клиента – `Desktop`.


## list — Запрос фильтрованного списка элементов каталога

Cуществуют следующие стандартные параметры:

 параметр   | формат         | по умолчанию | смысл
------------|----------------|--------------|-------
Фильтрация ||||
`type`      | `число`        | отсутствует  | по типу элементов каталога
`ids`       | числа через `,`| пусто        | по идентификаторам
`from `     | `число`        | отсутствует  | по времени начала
`to`        | `число`        | отсутствует  | по времени завершения
`search`    | `строка`       | отсутствует  | по названию
`tag`       | `число`        | отсутствует  | по тэгу
`parent_id` | `число`        | отсутствует  | по идентификатору родителя
`child_id`  | `число`        | отсутствует  | по идентификатору потомка
Представление данных ||||
`logo_res`  | `WIDTHxHEIGHT` | отсутствует  | желаемое разрешение постеров
`ss_res`    | `WIDTHxHEIGHT` | отсутствует  | желаемое разрешение стоп–кадров
`detailed`  | `true`, `false`| `false`      | запрос подробной информации
Выдача упорядоченного списка элементов[^fn-orderby-note] [^fn-ordered-by-criterias]||||
`quantity`  | `число`        | отсутствует  | максимальное количество элементов в выдаче[^default-quantity]
`skip`      | `число`        | `0`          | смещение элементов в выдаче

[^default-quantity]: Если отсутствует, выбирается подходящее для указанного клиента. Длина страницы выдачи *не может* быть бесконечной или сознательно завышенной, поэтому сервер в любом случае *должен* ограничить quantity значением 200. Рекомендуется устанавливать quantity равным двойному-тройному количеству элементов на экране устройства.

[^fn-orderby-note]: Несмотря на название раздела, параметров сортировки нет. Считаю поддержку сортировки абсолютно необходимой, поскольку мы планируем поддерживать БОЛЬШИЕ каталоги, и в клиент *будет* запрашивать всякие разные подборки, в том числе «Новинки» (отсортировано по дате поступления в каталог в обратном порядке), «Фильмография» (отсортировано по дате выпуска фильмов на экран) и т.д..

[^fn-ordered-by-criterias]: Порядок упорядочивания выборки задается набором фильтров выбранной категории, если упорядочивание на задано фильтром - решение о задании порядка принимается сервером.

В зависимости от выбранной категории должны быть заданы **дополнительные параметры**, обусловленные набором фильтров категории. В этом случае параметр "Имя фильтра" задается атрибутом `filter_name` из сообщения `Menu`, а значение - атрибутом `filter_value`, в случае фиксированного меню, или составным значением `value_name` из массива `values` сообщений `FilterValue`.

Формат ответа: сообщение `CataloguePart`.


## item — Запрос детальной информации об элементе каталога

 параметр   | формат         | по умолчанию | смысл
------------|----------------|--------------|-------
`id`      | `число`        | отсутствует  | Идентификатор элемента каталога

Формат ответа: сообщение `CatalogueItem` со всеми заполненными полями (как в методе `list` с параметром `detailed=true`).

Пример запроса:

	item.json?id=2304932

где:

- `id` соответствует элементу каталога с идентификатором 2304932.

## FilterValue, MenuItem[^fn-paging-info], Menu

	enum MenuItemType {
	    FIXED = 0;
	    SELECTABLE = 1;
	    SUBSTITUTIONAL = 2;
	    USER_INPUT = 3;
	}

	enum MenuItemSense {
	    FEATURED = 1;
	    NEW = 2;
	    POPULAR = 3;
	    SEARCH = 4;
	}

	message FilterValue {
	    optional string value_name = 1;
	    optional string readable_name = 2;
	    optional bool default_value = 3;
	    optional bool disable_filter = 4;
	}

	message MenuItem {
	    optional fixed32 id = 1;
	    optional string title = 2;
	    optional string icon_url = 3;

	    repeated MenuItem subitems = 4;
	    optional string filter_name = 5;
	    optional string filter_value = 6;
	    repeated FilterValue values = 7;
	    optional MenuItemType type = 8;
	    optional MenuItemSense sense = 9;
	}
	 
	message Menu {
	    repeated MenuItem items = 1;
	}

Замечания:

- `title` — локализованное название рубрики
- `icon_url ` — адрес до изображения, используемого в качестве иконки для пункта меню
- `subitems` — подрубрики
- `filter_name` — локализованное имя фильтра для передачи в параметрах запроса
- `filter_value` — значение фильтра для передачи в параметрах запроса (передается для фиксированных фильтров)
- `values` — возможные значения фильтра (для изменяемых фильтров), при этом:
	- `FilterValue::value_name` — значение для передачи в параметрах запроса
	- `FilterValue::readable_name` — локализованное значение фильтра, отображаемое пользователю.
	- `FilterValue::default_value` — признак значения, которое выбирается по умолчанию для данного пункта меню
	- `FilterValue::disable_filter` — если выбрано данное значение изменяемого фильтра, не включать имя и значение фильтра в запрос
- `type` — [вид пункта меню][menu-item-types]
- `sense` — [смысл пункта меню][menu-item-sense]

[^fn-paging-info]: Сообщение MenuItem *должно* поддерживать доп. информацию о постарничной выдаче (order, quantity, skip), чтобы при принудительном ограничении длины ответа клиент мог запросить недостающую информацию. Замечание: для реализации постраничной выдачи было бы логично задавать также глубину выдачи(по иерархии), а иерархичность реализовать через идентификаторы родительских пунктов меню. 

## CataloguePart

	message CataloguePart {
	    repeated CatalogueItem items = 1;
	    optional int32 total_count = 5;
	    optional int32 items_skipped = 2 [default = 0];

	    optional int64 expires = 3;
	    optional int32 ttl = 4;
	}

Замечания:

- `items` — упорядоченное множество элементов каталога
- `total_count` — общее количество элементов в фильтрованном множестве
- `items_skipped` — количество пропущенных элементов в выдаче
- Поля `expires` и `ttl` задают время в секундах, абсолютное (в UTC) и относительное, соответственно, в течение которого приложение может кэшировать ответ сервера. Эти два поля не должны присутствовать в ответе одновременно

- Сообщение `CatalogueItem` является генерализованным элементом медийного каталога, для разных видов которого заполняются различные поля.
- Общие поля для всех элементов:
	- `id` — уникальный (в рамках каталога) числовой идентификатор
	- `type` — вид элемента
	- `title` — локализованное название
	- `description` — описание
	- `logo_url` — ссылка на логотип элемента, в разрешении `logo_res`
	- `ratings` — рейтинги, [см. описание Rating][Rating-message]
	- `similar_items` — похожие элементы
	- `tag_groups` — тэги, [см. описание TagGroup][TagGroup-message]
	- `has_children` — признак наличия дочерних элементов
	- `can_have_media_sources` — признак возможного наличия источника вещания
	- `age_restriction` — возрастное ограничение
	- `date` — дата выхода, в секундах относительно UTC
	- `duration` — продолжительность, в секундах
	- `snapshots` — список ссылок на стоп–кадры, в разрешении `ss_res`
	- `serial_number` — порядковый номер в родительском элементе (номер сезона или серии)
- Специфика для элементов вида "канал телевидения":
	- наличие дочерних элементов `has_children` равносильно наличию расписания телепередач
	- `current_telecast_id` — идентификатор телепередачи, которая на данный момент транслируется на канале
- При запросе не детализированной информации выдаются лишь следующие поля (если есть): `id`, `type`, `title`, `logo_url`, `has_children`, `can_have_media_sources`, `current_telecast_id`

### Rating [Rating-message]

	message Rating {
	    optional int32 id = 1;
	    optional string title = 2;
	    optional int32 votes = 3;
	    optional float rating = 4;
	    optional float max_rating = 5;
	}

Замечания:

- `title` — название системы оценок, отображаемое пользователю ("Кинопоиск", "IMDB" и т.д.)
- `votes` — количество голосов
- `max_rating` — максимальный рейтинг для системы оценок
- `rating` — текущая оценка

### Tag, TagGroup [TagGroup-message]

	message Tag {
	    optional int64 id = 1;
	    optional string title = 2;
	}
	
	message TagGroups {
	    repeated Tag directors = 1;
	    repeated Tag actors = 2;
	    repeated Tag countries = 3;
	    repeated Tag genres = 4;
	}

Замечания:

- `Tag::title` — название тэга, отображаемое пользователю
- поля `TagGroups`:
	- `directors` — режиссеры
	- `actors` — актеры
	- `countries` — страны
	- `genres` — драматургические жанры
