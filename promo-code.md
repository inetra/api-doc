# Введение

Для пользователей предусмотрена система промокодов, которые пользователь может ввести на странице, адрес которой можно 
получить посредством [Регистратуры][registry-doc].
Ввод промокода через Promocode API влечёт за собой сохранение промокода в профиле пользователя, но не его активацию 
(сохранить один промокод у себя могут несколько пользователей). 
Активация осуществляется при покупке продукта, входящего в промоакцию сохранённого пользователем промокода.

[registry-doc]: registry.md

# Взаимодействие с Promocode API

Страница ввода промокода в значительной степени связана со страницей [Личного кабинета][private-office-doc], 
поэтому все параметры, используемые для открытия страницы "Личного кабинета" необъодимо передать и при вызове всех 
методов Promocode API. 

[private-office-doc]: private-office.md

Завершение взаимодействия пользователя со страницей ввода промокода может быть осуществлено двумя способами:

1. По инициативе пользователя. Пользователь самостоятельно закрывает страницу с помощью элементов графического 
интерфейса, например, с помощью кнопки "закрыть окно" в браузере.
2. По инициативе страницы ввода промокода. Для этого браузер, открывший страницу "Личного кабинета" абонента должен 
быть перенаправлен на адрес, указанный в параметре `inetra-callback-url`. 
В случае перехода на указанный адрес клиент должен закрыть браузер.

## Аутентификация пользователя

При обращении к странице ввода промокодов клиент может указать аутентификационные данные пользователя с 
использованием схем [HTTP Basic Auth][RFC2617], [Bearer][RFC6750] или с использованием GET-параметра "token". 
Для схемы [Bearer][RFC6750] рекомендуется использовать HTTP заголовок `Authorization`.

[RFC2617]: http://tools.ietf.org/html/rfc2617
[RFC6750]: http://tools.ietf.org/html/rfc6750
[auth-api-doc]: auth.md

# Взаимодействие с API

Точка входа определяется [Регистратурой][registry-doc].

Запросы формируются следующим образом:

	http://<path_to_api>/promocode/1/?[параметры]

# Методы

## `main` — Получение html страницы для ввода промокода

Запрос: `/main` или `/`

Дополнительные параметры: отсутствуют.

Формат ответа: text/html.

## `apply` — попытка сохранения промокода

#####Вызов метода осуществляется из JS кода страницы ввода промокода и обычно этот метод не требует специальной поддержки со стороны клиентских приложений. 

Запрос: `/apply`

Дополнительные параметры:

 параметр          | cмысл                              | тип                 | по умолчанию
-------------------|------------------------------------|---------------------|--------------
`code`             | тело кода                          | строка (6 символов) | -


Формат ответа: `PromocodeApplyResult`.

параметр              | cмысл                                   | тип                       | по умолчанию
----------------------|-----------------------------------------|---------------------------|--------------
`message`             | сообщение для пользователя              | строка (до 1000 символов) | пустая строка
`link`                | ссылка для перенаправления пользователя | строка (до 1000 символов) | пустая строка

Также, можно обращать внимание на варианты HTTP-кода ответа:

код                   | cмысл                                   
----------------------|--------------------------------------------------------------------------------------------
`200`                 | код удалось сохранить
`404`                 | код не удаётся применить (не существует, не прошёл валидацию, уже активирован и прочее)              

# Общие коды ошибок

Варианты HTTP-кода ответа:

код                   | cмысл                                   
----------------------|------------------------------------------
`403`                 | нет доступа (проблемы с токеном)              
`500`                 | неизвестная проблема на стороне сервера

#Структуры
### PromocodeApplyResult — результат применения промокода

	message Tag {
	  required string message;
	  required string link;
	}
