# Часовые пояса в Peers.TV

> Этот документ описывает концепцию поддержки разных часовых поясов в продукте Инетры Peers.TV. Приведено общее описание, правила применения и примеры использования. Кому непонятно про то, зачем-почему в Peers.TV эти самые часовые пояса – читать полчаса документацию про Видение Продукта. Кому непонятно, почему некоторые слова начинаются с большой буквы, читать раздел «Термины и определения» в документе [«О программных интерфейсах сервисов Инетры»][about-ref].

## Термины и определения

id телеканала, channel_id
:	Каждый телеканал идентифицируется уникальным логическим идентификатором. Id канала не зависит от региональности телепрограммы канала, он единый для всей территории. По этому id подсистемы получают метаинформацию о канале, такую, как описание, логотип канала и всякое такое.

код территории, territory_id
:	в контексте этого документа – это уникальный код Территории (из Регистратуры), но не для любой Территории, а для субъектов федерации, для которых по отраслевым связным правилам полагается свой региональный источник телевещания с региональными вставками (новостными, рекламными, оповещения и пр.). Проще  говоря, это области, автономные округа и т.п. в составе РФ, по [списку][federation-subjects-ref].

федеральный выпуск телепередачи, региональный выпуск телепередачи
:	будем называть *федеральными* те выпуски телепередач, которые одинаковы во всех регионах, т.е. выходят на одном канале, называются одинаково, начинаются в то же самое (местное) время, той же длительности, и главное, с тем же контентом; а *региональными* те выпуски, которые в регионах отличаются по контенту от федеральных. 

	Например, на каком-то телеканале во всех регионах в 20:00 местного времени начинается передача «Спокойной ночи, малыши», одна и таже для всех регионов – этот выпуск федеральный. На этом же канале в 19:00 часов местного времени начинается передача «Новости», которая своя для каждого (или части) регионов, причём она может быть отличающейся или такой же продолжительности – это региональный выпуск.

Оператор
:	сокращение, то же самое, что и Оператор связи.

## Идеальная услуга

Будем считать идеальным результатом, т.е. идеальным продуктом такой продукт, в котором любой Пользователь в любом регионе открывает наше приложение-Клиент, видит список всех уже доступных ему телеканалов, телепрограмму для этих каналов для его города (Территории), с учётом всех местных новостей, рекламы и т.п., видит записи выпусков телепередач именно этих каналов именно для этого города. 

Сложность в получении такого результата в том, что сразу получить правильную телепрограмму ещё можно, а вот *быстро* получить записи всех телеканалов для всех регионов, со всеми их местными новостями и прочими вставками затруднительно, по причинам «организационно сложно» и/или «тупо дорого». Такие дела. Постепенно эти записи появятся, но очевидно, что нужен алгоритм выбора замен источников данных для сервисов, которые различаются в разных регионах.

## Реализация идеала

Очевидно, что во всех подсистемах, реализующих услуги продукта Peers.TV, для операций с источниками услуг телевещания, записей телепередач, даже для телепрограммы необходимо использовать составной ключ `(channel_id, territory_id)`. Использование такого составного ключа описано в соответствующих версиях CN.API.

Однако, как написано чуть выше, не для всех услуг не для всех Территорий существуют свои региональные источники. Нужно применять набор правил для подстановки замещающих данных.

## Кто и как замещает и приоритезирует

В различных компонентах системы правила замещения применяются с разными ограничениями. 

Сервер
:	Компоненты системы, которые исполняется *на серверах*, должны пользоваться указанными ниже правилами подстановки для генерации списков источников, возвращая по запросу Клиента наиболее приоритетные источники от запрошенного Контрагента, *но только от этого Контрагента*. Нельзя просто взять и заменить источник телевещания Контрагента-А на источник Контрагента-Б. Но допускается заменять источник Контрагента-А в Городе-Х на источник того же Контрагента-А из Города-У из того же Региона-Х+У.

Клиент
:	Клиент, который получает списки источников от разных Контрагентов, должен пользоваться правилами подстановки для приоритезации источников и выбора наилучшего источника *среди источников всех Контрагентов*.

Предполагается, что наиболее частой замене будет подвергаться телепрограмма (в рамках одного поставщика, Инетры-информатория), и записи выпусков телепередач (в рамках одного поставщика, Инетры-вещателя).

## Правила подстановки замещающих данных

Настоящие правила дополняют правила выбора источников услуг, указанные в документе «О программных интерфейсах сервисов Инетры». 

1. Наивысшим приоритетом обладают источники локального оператора, исходя из предположения, что он исполняет отраслевые требования и вещает региональные телесигналы.
2. Если у локального оператора источников услуги нет, то следует выбрать источники из того же региона, с точностью до области.
3. Если источников всё еще не нашлось, следует выбрать источники по-умолчанию, если они есть. Источником по-умолчанию считается источник для территории Москва, если он есть для данной услуги у данного контрагента.

Для всех правил, если не сказано явно, подразумеваются требования качественной услуги. Критерии качества для каждой услуги должны быть описаны явно. Некачественная услуга услугой не является. На данный момент (декабрь 2013) описания критериев качества нет, как нет и реализаций оценки качества услуг. Предполагается реализация оценки качества позднее, в первой половине 2014 года. До тех пор все услуги (в контексте выбора источников) считаются качественными.

## Замечание по реализации на Клиенте

Для некоторых услуг допускается наличие нескольких источников от разных контрагентов. При подборе Клиентом источников по перечисленным выше правилам *рекомендуется* не исключать менее подходящие по совокупности всех правил источники из общего списка (условной структуры TV Services), а всего лишь ранжировать их по приоритету, и в итоге выбирать самый приоритетный.

## Пример подстановки

Предположим, что  

* Пользователь находится в регионе Уфа (Республика Башкортостан).
* Пользователь выбрать для просмотра телеканал Россия 24.
* Пользователь подключен к локальному оператору Уфанет.
* Оператор Уфанет обеспечивает услуги:
	*  вещание для канала Россия 24.
* Инетра-Регистратура обеспечивает услуги
	* расписание телепередач для телеканала Россия 24 для нескольких регионов, в том числе и для региона Уфа (Республика Башкортостан).
* Инетра-вещатель обеспечивает услуги 
	* вещание для телеканала Россия 24 (для региона Новосибирская область), и 
	* записи выпуском телепередач канала Россия 24.

Алгоритм (с использованием псевдотерминов)

* Клиент вызвал метод `whereami`
* Регистратура вернула в ответе структуру Services, содержащую
	* `iptv; Уфанет; http://ufanet.ru/iptv/playlist.m3u8` -- потому что «Уфанет» для Пользователя есть локальный оператор.
	* `iptv; Инетра(вещатель); http://peers.tv/iptv/playlist.m3u8` – потому что Инетра добавляется всегда, и потому что Инетра по определению предоставляет услуги на регион «Российская Федерация».
	* `media-locator; Инетра(вещатель); http://peers.tv/api/media-locator/` – потому что Инетра добавляется всегда, и потому что Инетра по определению предоставляет услуги на регион «Российская Федерация».
	* `tv-guide; Инетра(регистратура); http://peers.tv/api/tv-guide/` – потому что Инетра-регистратура добавляется всегда.
* Клиент опросил все источники услуг iptv и составил структуру TV Service, содержащую (условно)
	* Россия 24; Уфанет; UTC+6; республика Башкортостан; iptv; http://ufanet.ru/iptv/rossiya_24.m3u8
	* Россия 24; Инетра; UTC+7; Новосибирская область; media-locator; http://peers.tv/media-locator/
* Клиент запросил список всех каналов и телепрограмму для телеканала Россия 24 для региона локального оператора (республика Башкортостан), и дополнил.
