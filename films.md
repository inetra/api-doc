Введение
========

API каталога фильмов предназначен для приложений, которые не могут воспользоваться веб-интерфейсом этого каталога.

Например, в телеприставке NV101 API поставляет в графическую оболочку системы меню-рубрикатор, а также описания фильмов из каталога для каждого из рубрик меню.

Изложение мотивов
-----------------

Разработка третьей версии API преследует следующие цели:
- возможность расширения API с обеспечением обратной совместимости
- упрощение разработки генераторов/парсеров сообщений
- уменьшение сетевого трафика между клиентом и сервером
- уменьшение расходов на генерацию/разбор сообщений
- потенциальная унификация с TV API
- возможности обмена данными в разных форматах

Принятые решения
----------------

В качестве основного средства упаковки сообщений (вместо XML) выбрана библиотека Google  Protocol Buffers. Она позволяет решить сразу несколько из заявленных целей:

- уменьшить накладные расходы на генерацию/декодирование сообщения
- уменьшить расходы на разработку генератора/парсера сообщения
- (самое важное) обеспечить возможность обратной совместимости при расширении передаваемого набора данных.

Изменения относительно версии 2.x
---------------------------------

- поддержка нескольких форматов упаковки сообщений: Protocol Buffers, JSON
- в списке элементов каталога в элементы не включается детальное описание (*в графических интерфейсах при просмотре каталога детальная информация не нужна и занимает много места; зато она есть в детальной информации об элементе каталога*)
- иерархический рубрикатор (взамен одноуровневого списка) с возможностью добавления различных "полезностей"
- нет выделенного RPC-запроса для поиска, поиск теперь является одним из фильтров запроса списка элементов каталога

Описание предметной области
===========================

Две наиболее крупных сущности из предметной области данного API — это **каталог** и **рубрикатор**.

Каталог содержит описания фильмов, а рубрикатор организует простую для пользователя систему навигации по каталогу фильмов. С точки зрения разработчика рубрикатор представляет из себя систему фильтров, применяемых к каталогу. Каждый из фильтров, в свою очередь, определяет способ выбора элементов каталога или способ их упорядочивания.

Рубрикатор состоит из набора **фильтров**, каждый из которых имеет название, видное пользователю. **Фильтр** может быть фиксированным или изменяемым. Фиксированный фильтр содержит один критерий фильтрации. Изменяемый фильтр содержит несколько критериев фильтрации, один из которых может быть впоследствии выбран пользователем.

Фильтры в рубрикаторе образуют иерархическую структуру. Фиксированный фильтр может включать в себя другие фильтры. Изменяемый фильтр ничего в себя включать не может.

Пример:

- Фильмы
	- Россия/СССР
	- Зарубежные
	- Жанр \[ все | боевик | драма | комедия | ужасы \]
	- Сортировка \[ по дате | по рейтингу | по популярности \]
- Мультфильмы
	- Россия/СССР
	- Зарубежные
	- Аниме
	- Сортировка \[ по дате | по рейтингу | по популярности \]

Фиксированные фильтры, при выборе пользователем в качестве рубрики, применяются в объединении со статическими фильтрами, находящимися выше по иерархии, одновременно с выбранными значениями изменяемых фильтров, находящихся на том же уровне или выше по иерархии.

Описание API
============

API каталога фильмов состоит из нескольких RPC-запросов типа GET по протоколу HTTP:

- запрос меню-рубрикатора - `/rubricator/`
- запрос описаний фильмов из каталога по набору фильтров - `/list/`
- запрос подробной информации о фильме - `/item/<id>/`

аргументы RPC передаются в виде параметров URI. Например:

	http://api.cn.ru/films/3/list.protobuf?type=film&client=nv101&client-version=fs_nv101_121203

где задано 3 параметра:

- `type` со значением `film`
- `client` со значением `nv101`
- `clien-version` со значением `fs_nv101_121203`

Параметры делятся на частные и общие. Общие параметры должны присутствовать во всех запросах, а частные только в тех, с которыми они связаны.

Текстовые значения параметров должны передаваться в кодировке UTF-8 с использованием URI encoding.

## Общие параметры запросов

Для формировании ответа с учетом особенностей клиента, во все запросы необходимо включать следующие общие параметры:

- `client` - строка, идентифицирующая тип клиента, например `nv101`
- `client-version` - строка, идентифицирующая версию клиента, например `fs_nv101_121203`

## Запрос меню-рубрикатора /rubricator/

Запрос меню рубрикатора имеет вид:

	http://api.cn.ru/films/3/rubricator.protobuf/

и должен возвращать меню рубрикатор в сообщении типа `Menu`. Дополнительных частные параметры отсутствуют.

### Описание формата сообщений

	// тип фильтра 
	enum FilterType {
	    SINGLE_VALUE = 0;	// фиксированный фильтр с одним значением
	    MULTIPLE_VALUE = 1; // множественный фильтр с несколькими вариантами значений
	    USER_VALUE = 2;	// значение этого фильтра задаётся пользователем (например, поисковая строка)
	}
	
	// контейнер рубрик
	message Menu {
	    repeated Filter items = 1;			// основные рубрики 
	    repeated Filter specialItems = 2;		// специальные (вспомогательные) рубрики (например, "Поиск")
	}
	
	// рубрика (фильтр)
	message Filter {
	    optional fixed32 id = 1;			// идентификатор фильтра
	    optional string title = 2;			// отображаемое пользователю название пункта меню
	    repeated Filter subitems = 3;		// список вложенных подрубрик
	    optional string parameter_name = 4;		// имя параметра для вызова list
	    optional string parameter_value = 5;	// значение параметра для вызова list 
	    optional FilterType filter_type = 6 [default = SINGLE_VALUE];		// тип фильтра
	    optional FilterParameter parameters = 7;	// параметры фильтра
	}
		
	// параметр фильтра
	message FilterParameter {
	    optional string parameter_value = 1;	// значение параметра в запросе list
	    optional string readable_value = 2;         // 
	    optional bool isDefault = 3;
	    optional bool disable_filter = 4;
	}

## Запрос фильтрованного списка элементов каталога /list/

Запрос фильтрованного списка элементов имеет вид:

	http://www.cn.ru/path_to_api/list?param1=value1&param2=value2

где `param1` и `value1`, `param2` и `value2` - частные параметры и их значения из рубрики меню (фильтра).

Имя параметра (param) берётся из поля `Filter::parameter_name`, значение параметра (value) из поля `Filter::paremeter_value` или из `FilterParameter::parameter_value`.

### Ограничение списка по количеству элементов и пропуск элементов

Параметры `quantity` и `skip` зарезервированы для ограничения порции данных списка.

- `skip` - cмещение в фильтрованном подмножестве: `skip=n`, если отсутствует `n = 0`
- `quantity` - желаемое количество элементов: `quantity=n`, если отсуствует выбирается `n`, подходящее для указанного клиента

### Описание формата сообщений

    // список элементов каталога
    message CataloguePart {
        repeated CatalogueItem items = 1;                // упорядоченный список элементов каталога
        optional int32 items_skipped = 2 [default = 0];  // смещение списка в упорядоченном фильтрованном подмножестве элементов
    }
    message CatalogueItem {
        optional int64 id = 1;                           // идентификатор элемента каталога
        optional string title = 2;                       // название элемента, отображаемое пользователю
        optional string poster_url = 4;                  // URL картинки-постера для элемента каталога
    }

### Пример вызова

Вызов для получения списка *фильмов* с жанром *детектив*.

Вызов с параметром `search` для поиска по названию элемента каталога.

	http://www.cn.ru/path_to_api/list?search=house&api-version=3&client=nv101&client-version=fs_nv101_121203
