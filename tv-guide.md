# Цель и смысл

Данный документ описывает программный интерфейс двух веб–служб:

- TV Guide, также известный как "программа телепередач"
- Peers.TV, позволяющий смотреть записи телепередач и эфир каналов

Службы имеют общую предметную область, поэтому передаются с использованием одинаковой схемы данных.

С помощью данного API у обоих служб можно выяснить:

- название, описание канала
- текущую телепередачу для канала
- расписание выпусков телепередач (привязанное к территории)
- описание выпусков телепередач
- идентификаторы: каналов, телепередач и выпусков телепередач

TV Guide предоставляет меньше информации. Так, в нем не содержится информации:

- об адресах вещания каналов
- наличия записей телепередач для каналов и телепередач
- о ссылках на записи телепередач (ни magnet, ни HTTP, ни HLS, никаких)

В рамках службы Peers.TV можно получить всю указанную выше информацию.

На замену настоящему API для получения информации о каналах, телепередачах и выпусках готовится [Catalogue API][catalogue-api-ref], плановый срок релиза – июнь-июль 2014, поэтому для новых разработок рекомендуется ориентироваться на новый API.

[catalogue-api-ref]: catalogue.md?h=catalogue

Получение ссылок на адреса вещания разбивается на две отдельные сущности:

- Адреса вещания каналов. Приложение формирует список доступных адресов вещания каналов на основе доступных ему списков вещания каналов, предоставляемых различными контрагентами. Списки каналов обычно поставляются в XSPF или M3U форматах.
- Адреса вещания записей выпусков телепередач. Для этого разработана и внедрена служба Media Locator, работающая по одноименному протоколу: [Media Locator API][media-locator-api-ref]. 

[media-locator-api-ref]: media-locator.md

## Рубрикатор <span style="color:#f00">\[только в Peers.TV\]</span>  [ch-menu] 

Начиная с версии 2.8 в сервис Peers.TV введено понятие рубрикатора. Рубрикатор служит для формирования выборок выпусков телепередач или их фрагментов при навигации пользователем по меню приложения или схожим по функциональности с ним элементам графического интерфейса.

Меню иерархично, при этом выборка из каталога производится для выбранного на данный момент пункта меню, с учетом выбранных пользователем опций.

Например, меню приложения может состоять из следующих пунктов:

1. "Популярное", опции:
	- "Выборка". Возможные значения: "за неделю", "за все время"
	- "Сортировка". Возможные значения: "по новизне", "по количеству просмотров"
2. "Подборки", с подпунктами:
	1. "Чемпионат мира по хоккею"
	2. "Чемпионат мира по снукеру"
3. "Рекомендации"
4. "Поиск", опции:
	- "Поисковая строка", вводится пользователем

Меню может различаться в зависимости от типа приложения, от устройства, на котором запущено приложение, от территории или от контагента, в сети которого запущено приложение.

Например, для устройств с пультом дистанцинного управления меню из предыдущего примера может выглядеть так:

1. "Популярное", с подпунктами:
	1. "За неделю"
	2. "За все время"
2. "Подборки", с подпунктами:
	1. "Чемпионат мира по хоккею"
	2. "Чемпионат мира по снукеру"
3. "Рекомендации"
4. "Поиск", опции:
    - "Поисковая строка", вводится пользователем

### Структура меню

Меню представляет собой дерево, узлы в котором называются пунктами. При выборе каждого пункта  меню может быть осуществлена выборка выпусков телепередач.

Каждый пункт меню может иметь дочерние пункты, а также опции, задающие дополнительные параметры выборки выпусков телепередач: сортировку или фильтрацию.

Опции возможны двух типов:

1. Переключаемые. В каждый момент времени пользователь должен выбрать одно из предлагаемых сервером значений. Одно из значений должно быть помечено как значение по умолчанию, отображаемое приложением при выборе пользователем пункта меню.
2. Требующие пользовательский ввод. Приложение должно отобразить пользователю поле для ввода значения опции.

Самые верхние пункты меню могут быть использованы в качестве главного меню приложения, или разнесены по другим графическим элементам интерфейса. Так, роль главного меню в iOS может выполнять TabBar, при этом элемент поиска обычно располагается в верхней части интерфейса.

Пункты меню могут содержать дополнительную подсказку `ui_hint` о том, как их отображать в приложении. Это может помочь приложению реализовать ожидаемое поведение для имеющихся элементов графического интерфейса и выбрать требуемое отображение списка выбранных выпусков телепередач.

### Получение и интерпретация меню [para-menu-interpret]

Построение связи между графическим интерфейсом пользователя и серверным меню должно производится по следующему алгоритму:

1. Отображается интерфейс пользователя.
2. Отправляется [запрос `menu`][m-menu] на получение доступных пунктов меню.
3. Для каждого полученного пункта меню верхнего уровня подбирается подходящий элемент графического интерфейса. Соответствие осуществляется на основе подсказки `ui_hint`, указанной в пункте меню.
	1. Если подходящий элемент графического интерфейса приложения не был найден, пункт меню игнорируется как неподдерживаемый.
4. Если для какого-то элемента графического интерфейса не был найден подходящий пункт меню верхнего уровня, данная функциональность должна либо не отображаться, либо отображаться как недоступная на данный момент.
5. Приложение запоминает построенную иерархию на определенное время:
	1. Либо до времени, указанного в HTTP заголовке `Expires` ответа сервера,
	2. Либо до смены контрагента и/или территории,
	3. Иначе на 8 часов, после чего попытается обновить информацию с сервера.

Получение или обновление рубрикатора с сервера и построение соответствия полученных пунктов меню с имеющимися элементами графического интерфейса должно производиться в фоновом режиме и не влиять на работу остальной функциональности приложения. При этом допускается отображать надпись "Производится загрузка информации" или ей подобную для выбранных пользователем пунктов меню, для которых ожидается рубрика с сервера, но в данный момент получение и построение рубрикатора еще не завершено.

### Обработка выбора пользователем пункта меню [para-get-for-menuitem]

При выборе пользователем пункта меню приложение:

  1. Для всех опций данного пункта, выставляет значение по умолчанию. Если это предусмотрено в дизайне, опции отображаются в графическом интерфейсе.
  2. Все дочерние пункты меню отображаются согласно дизайну приложения.
  3. Если это не предусмотрено в интерфейсе приложения, следующее действие может не производиться, если у выбранного пункта меню имеются фиксированные подпункты.
  4. С помощью [метода `get`][m-get] производится выборка списка выпусков телепередач, относящихся к данному пункту меню. Полученные выпуски телепередач отображаются согласно дизайну для соответствующего значения `ui_hint`.

При изменении значения любой опции пункта меню происходит переполучение списка выпусков телепередач, с последующим обновлением интерфейса приложения в соответствии со значением `ui_hint` пункта меню.

Если это предусмотрено интерфейсом, для опций, требующих ввод, пользователю предлагаются возможные подсказки, с помощью [метода `suggest`][m-suggest].

При получении списка выпусков телепередач [методом `get`][m-get], передаются следующие параметры:

1. Числовой идентификатор выбранного пункта меню, в параметре `menu`.
2. Выбранные значения опций — в параметре `menu_options`, при этом кодируются следующим образом:
	1. Для каждой опции формируется строка, содержащая ее числовой идентификатор и — через символ `,` — выбранное значение.
	2. Для переключаемых опций значение передается в поле `value`, для опций требующих ввод, используется введенная пользователем строка в кодировке UTF-8.
	3. Выбранное значение опции должно быть кодировано на стороне приложения, если оно содержит зарезервированные символы URI. Символы `,` и `;` при этом также должны быть кодированы.
	4. Все полученные строки конкатенируются через разделитель `;`.

При обработке метода `get` сервер с помощью переданного параметра `menu` определяет запрос, который необходимо будет выполнить в базе данных, а параметры запроса формирует из параметра `menu_options`. Массив значений получается путем разбивания полученной строки разделителем `;`. Данный массив далее преобразуется в ассоциативный массив с помощью отделения ключа от значения символом `,`. На третьем шаге значения ассоциативного массива декодируются с помощью функции `urldecode` (PHP) или аналогичной.

Продолжая пример с приложением под iPhone при выборе пользователем рубрики "Популярное" приложение должно отправить в API запрос `get` с параметрами `menu=1` и `menu_options=100,today`, так как значением опции "Период" с идентификатором `100` по умолчанию является "За сегодня", что и будет отображено в интерфейсе:

# Размещение и использование

Точка входа в веб–службы определяется [Регистратурой][registry-api-ref], при этом:

- TV Guide имеет числовой идентификатор `4`, строковый — `tv_guide`
- Peers.TV имеет числовой идентификатор `2`, строковый — `peerstv`

Запросы формируются следующим образом:

[registry-api-ref]: registry.md

	http://<path_to_api>/<method>.<format>?[parameters]

Где:

- `path_to_api` — путь до API, полученный из Регистратуры
- `method` — имя метода
- `format` — формат передачи данных, может быть одним из:
	- `.json` — JSON
	- `.xml` — XML
	- `.xspf` — XSPF (только для метода list)
	- `.png` — Portable Network Graphics, только для метода `logo` (<span style="color:#0f0">новое в 2.8</span>)
- `parameters` — параметры метода

Запрос к корневому URL API (без указания метода и формата) равносилен на запросу `list.xspf`.

# Возрастные ограничения

В версии TV API 2.1 введено понятие возрастного ограничения (возраст в годах, с которого можно потреблять медиа–контент без вреда для психики человека) для:

- выпуска телепередачи;
- телепередачи;
- канала.

Возрастные ограничения могут быть выставлены вручную или автоматически, на основании возрастных ограничений элементов, из которых состоит сущность. При автоматическом вычислении возрастного ограничения результат является максимумом возрастных ограничений элементов. Таким образом, для канала, возрастные ограничения телепередач которого колеблются от 0 до 18 лет, возрастным ограничением будет 18 лет.

# Методы

Для всех методов в квадратных скобках далее будет указано, в рамках каких служб реализован тот или иной метод. Если этого не указано — метод должен быть реализован в рамках обоих служб.

## `idbytitle` — получение списка идентификаторов телеканалов по их именам (<span style="color:#0f0">новое в версии 2.2</span>) <span style="color:#f00">\[только в TV Guide\]</span>

Запрос идентификаторов каналов, для которых в плейлисте провайдера не использовано расширение `cn_id`.

 параметр | значение
----------|----------
`titles`  | Список названий телеканалов из плейлиста провайдера, для которых запрашиваются идентификаторы

Список названий телеканалов кодируются следующим образом:

1. Название канала передается в кодировке текста utf-8
2. Все запятые (`,`) в названии каналов экранируются символом `\`
3. Преобразованные названия склеиваются с помощью запятой (`,`)

Формат ответа: сообщение `ChannelsList`.

Замечания:

- Порядок каналов в ответе строго соответствует порядку каналов в запросе
- Для каждого запрошенного названия возвращается либо один идентификатор, либо ни одного
- Если для канала не было найдено подходящего идентификатора, но на соответствующей позиции *должно присутстовать пустое* сообщение `Channel`
- Если для канала был найден подходящий идентификатор, то в сообщении `Channel` должны заполняться поля:
	- `title` — название найденного телеканала
	- `channelId` — идентификатор найденного телеканала
- При поиске канала по названию сервер:
	- производит регистронезависимый поиск по названию канала
	- производит замену символов `е` и `ё` при необходимости
	- производит замену символов табуляции и переноса строки на символ пробела
	- удаляет лишние пробелы в названии (лидирующие, хвостовые и идущие подряд несколько раз)

## `channels` — получение информации о каналах [m-channels]

Дополнительные параметры:

 параметр     | значение
--------------|----------------
`channel_ids` | список идентификаторов каналов через `,`
`fields`      | список полей через `,` из сообщения `Channel`. Только указанные поля должны присутствовать в выдаче.

Параметр `fields` по умолчанию включает поля `title`, `channelId`, `alias`, `logoURL`, `ageRestriction`, `hasSchedule`, что гарантирует наличие в выдаче:

- названия телеканала;
- идентификатора телеканала (в том числе строкового);
- URL логотипа канала;
- возрастного ограничения;
- наличие расписания для канала (без указания точных дат).

Если параметр `channel_ids` не задан, то будет возвращена информация по всем каналам.

Формат ответа: сообщение `ChannelsList`.

## `channel` — получение информации о канале по его идентификатору (<span style="color:#f00">устарел с версии 2.8</span>) [m-channel]

 параметр | значение
----------|----------
`channel` | идентификатор канала

Формат ответа: сообщение `Channel`.

## `schedule` — получение расписания для канала [m-schedule]

 параметр | значение
----------|----------
`channel` | идентификатор канала

## `logo` — Запрос логотипа для элемента каталога (<span style="color:#0f0">новое в 2.8</span>) [m-logo]

 параметр     | формат         | по умолчанию | смысл
--------------|----------------|--------------|-------
`menu`        | `число`        | отсутствует  | Идентификатор элемента меню рубрикатора
Представление данных ||||
`profile`     | `строка`       | `web`        | желаемый профиль изображения
`strict`      | `true`, `false`| `false`      | возращать логотип только при точном соотвествии параметров представления
`resolution`  | `WIDTHxHEIGHT` | отсутствует  | желаемое разрешение

Данный метод производит перенаправление на адрес запрашиваемого ресурса. Получение списка логотипов в формате, отличном от PNG, не предусмотрено.

Для логотипов элементов медиа–каталога может существовать несколько профилей отображения, адаптированных под дизайн или возможности платформы. Чтобы задать желаемый профиль отображения необходимо указать параметр `profile`, в случае отсутствия изображения с запрошенным профилем сервер вернет изображение по умолчанию.

Поддерживаемые значения для параметра `profile`:

- `web` — адаптированный для отображения в вебе;
- `android` — адаптированный для устройств на базе Android;
- `ios` — адаптированный для устройств на базе iOS.

Также можно указать желаемые размеры логотипов для элементов медиа-каталога при помощи параметров `resolution`, если данный параметр указан, то сервер вернет наиболее близкое по размеру изображения, но не меньше запрашиваемого, если подходящего изображения не найдено, то будет возвращено изображение по умолчанию.

При указании параметра `strict` со значением `true` сервер должен вернуть HTTP код `404` с пустым телом ответа, если логотип с запрашиваемыми параметрами представления не найден.

	  optional uint64 views_count = 13;

Замечания:

- `id` — идентификатор выпуска телепередачи
- `title` — название выпуска
- `description` — описание выпуска
- `date` — время выхода выпуска по расписанию
- `duration` — продолжительность (в секундах)
- `URL` — адрес телепередачи на сайте
- `telecastImages` — изображения для телепередачи
- `telecastParts` — записанные части телепередачи <span style="color:#f00">\[только в Peers.TV\]</span>
	- `TelecastPart.duration` — общее время файла части телепередачи, в милисекундах
	- `TelecastPart.startPos` — время начала выпуска телепередачи в файле, в милисекундах
	- `TelecastPart.endPos` — время окончания выпуска телепередачи в файле, в милисекундах
	- `TelecastPart.FileLocation` — локация файла, может быть задана в различных сетях и способах хранения данных:

		- `MAGNET` — файл располагается в P2P-сети, в `location` — magnet-ссылка на файл
		- `HLS` — файл распространяется с помощью Apple HTTP Live Streaming

- `channel` — канал выпуска телепередачи. При наличии, указывается только идентификатор канала
- `ageRestriction` — возрастное ограничение для выпуска телепередачи
- `views_count` — количество просмотров выпуска телепередачи (<span style="color:#0f0">новое в 2.3</span>) <span style="color:#f00">\[только в Peers.TV\]</span>
- `time_offset` — разница в секундах между фактическим временем выхода выпуска и временем по расписанию (<span style="color:#f00">устарел с версии 2.8</span>)
- `full_version_id` — идентификатор полной версии фрагмента выпуска телепередачи (<span style="color:#0f0">новое в версии 2.8</span>)
