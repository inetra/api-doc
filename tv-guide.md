Описание
========

API реализует интерфейс для получения информации о каналах телевидения, а также их расписания. Идентификаторы сущностей (канал, телепередача, выпуск телепередачи) должны быть использованы другими поставщиками данных для расширения:

- списка каналов провайдера (добавление логотипа канала, названия и другой информации)
- списка записей выпусков телепередач

Возрастные ограничения
----------------------

Возрастное ограничение — это возраст (в годах), с которого можно потреблять медиа–контент без вреда для психики человека. Он определен для:

- выпуска телепередачи;
- телепередачи;
- канала.

Возрастные ограничения могут быть указаны вручную или получены автоматически, на основании возрастных ограничений элементов, из которых состоит сущность. При автоматическом вычислении возрастного ограничения результат является максимумом возрастных ограничений элементов. Таким образом, для канала, возрастные ограничения телепередач которого колеблются от 0 до 18 лет, возрастным ограничением будет 18 лет.

Взаимодействие с API
--------------------

API работает по протоколу HTTP, корень доступа получается приложением из Регистратуры. Запросы к API составляются следующим образом:

	https://<path_to_api>/<api_version>/<method>.<format>?[params]

Где:

- `path_to_api` — путь до API, полученный в Регистратуре
- `api_version` — мажорная версия API (должна быть равна `3`)
- `method` — имя метода API
- `format` — ожидаемый формат ответа:
	- `json` — JSON
	- `protobuf` — Google Protocol Buffers
- `params` — параметры метода

Все даты передаются в UNIX time, в UTC.

### Общие параметры запросов

 параметр | смысл                        | возможные значения | значение по умолчанию
----------|------------------------------|--------------------|-----------------------
`t`       | идентификатор территории[^1] | число              | автоматически определенная

[^1]: из Registry API

## Получение списка элементов каталога

Запрос: `list`.

 параметр   | формат         | по умолчанию | смысл
------------|----------------|--------------|-------
`t`         | `число`        | отсутствует  | тип выдаваемых элементов каталога
`resolution`| `WIDTHxHEIGHT` | отсутствует  | предпочтительное разрешение изображений
`ids`       | числа через `,`| пусто        | список идентификаторов запрашиваемых элементов
`detailed`  | `true` `false` | `false`      | передача полной информации об элементе каталога
`from `     | `число`        | отсутствует  | фильтр по времени
`to`        | `число`        | отсутствует  | фильтр по времени
`quantity`  | `число`        | отсутствует  | максимальное количество элементов в выдаче
`skip`      | `число`        | `0`          | смещение элементов в выдаче

Отсутствие параметра `ids` означает передачу информации обо всех каналах.

## Запрос меню–рубрикатора

Запрос: `rubricator`.

Формат ответа: сообщение `Menu`.

Полученный рубрикатор меню следует отображать в приложениях отдельно от списка каналов. Фильтр, полученный в результате выбора пункта меню необходимо передавать параметрами к методу получения списка выпусков телепередач.

# Описания форматов способом Google Protocol Buffers

Для всех списков определены два целочисленных свойства:

- `total_count` – общее количество элементов в списке
- `items_skipped` — количество пропущенных элементов в списке

## Menu — меню рубрикатора

	message FilterValue {
	    optional string value_name = 1;
	    optional string readable_name = 2;
	    optional bool default_value = 3;
	}
	 
	message MenuItem {
	    optional fixed32 id = 1;
	    optional string title = 2;
	    repeated MenuItem subitems = 3;
	    optional string filter_name = 4;
	    optional string filter_value = 5;
	    repeated FilterValue values = 7;
	}
	 
	message Menu {
	    repeated MenuItem items = 1;
	}

Замечания:

- Данный формат полностью совпадает с таковым из [Films API v3][films-api-v3]
- Фильтры делятся на фиксированные и изменяемые следующим образом:
	- Поле `filter_value` может присутствовать только в фиксированном меню
	- Поле `values` — только в изменяемом
	- Отсутствие обоих полей, но присутствие `filter_name` означает, что в качестве значения может быть передана любая строка, введенная пользователем
- `title` — название рубрики
- `subitems` — подрубрики
- `filter_name` — имя фильтра для передачи в параметрах запроса
- `filter_value` — значение фильтра для передачи в параметрах запроса (передается для фиксированных фильтров)
- `values` — возможные значения фильтра (для изменяемых фильтров), при этом:
	- `FilterValue::value_name` — значение для передачи в параметрах запроса
	- `FilterValue::readable_name` — отображаемое пользователю значение фильтра
	- `FilterValue::default_value` — признак значения, которое выбирается по умолчанию для данного пункта меню

[films-api-v3]: films.md?h=dev

## CatalogueItem — элемент каталога

	message Rating {
	    optional int32 id = 1;
	    optional string title = 2;
	    optional int32 votes = 3;
	    optional float rating = 4;
	    optional float max_rating = 5;
	}
	
	message Tag {
	    optional int64 tag_id = 1;
	    optional string title = 2;
	}

	enum CatalogueItemType {
	  option allow_alias = true;
	  FILM = 0;
	  CHANNEL = 1;
	  TVSHOW = 2;
	  TELECAST = 3;
	}

	message CatalogueItem {
	  optional int64 id = 1;
	  optional string title = 2;
	  optional string description = 3;
	  optional string url = 4;
	  
	  repeated CatalogueItem similar_items = 9;
	  
	  optional CatalogueItemType type = 13;
	  optional uint32 age_restriction;
	  
	  // для канала
	  optional string logo_url;
	  optional int64 telecast_id; // идентификатор текущей телепередачи
	  optional int64 schedule_from;
	  optional int64 schedule_to;
	  
	  // для выпуска телепередачи
	  optional int64 channel_id;
	  optional int64 tvshow_id;
	  optional uint64 date;
	  optional uint32 duration;
	  
	}
	
	message CataloguePart {
	  repeated CatalogueItem items = 1;
	  optional int32 items_skipped = 2;
	  optional int64 expires = 3;
	  optional int32 ttl = 4;
	  optional int32 total_count = 5;
	}

История версий
==============

Изменения в версии 3.0
----------------------

1. API предназначено только для получения информации о каналах
	- удалены адреса источников вещания каналов
	- удалены источники записей телепередач
2. XML изъят из обращения
3. Время передается в едином стиле
4. Упрощена передача информации о наличии расписания канала
5. Добавлено понятие рубрикатора (из [Films API v3][films-api-v3])
6. Расписание для канала обобщено до метода получения списка выпусков телепередач
7. <span style="color:#f00">TODO</span>:
	- Метод получения списка телепередач

Изменения в версии 2.1
----------------------

1. Добавлен признак доступности эфира и записей телепередач канала.
2. Метод `/list` помечен как "устаревший". В версии 3.0 TV API данного метода *не будет*.
3. Добавлена сущность "Телепередача".
4. В информацию о выпуске телепередачи добавлен канал, на котором был выпуск.
5. Добавлены параметры "Возрастные ограничения" для канала, передачи и выпуска телепередачи.
6. Добавлен параметр наличия расписания в сообщении `Channel`.

Изменения в версии 2.0
----------------------

1. Изменения в общих параметрах:
	- Убран `ao` — за ненадобностью;
	- Убран `uid` — должен передаваться на сервер статистики, а не в API;
	- Убран параметр `tz` — данные берутся из описания территории.
2. В XSPF оставлен только один метод — list.xspf, для клиентов, не поддерживающих API. Все остальное переведено на JSON, XML и Protocol Buffers.
3. Убран метод договора оферты.
4. Убран метод получения дат с наличествующем расписанием для канала.
5. Добавлен метод получения описания о конкретном канале.
6. Добавлен метод получения информации о канале по идентификатору выпуска телепередачи.
7. Добавлена возможность получения расписания передач канала для нескольких дат.
