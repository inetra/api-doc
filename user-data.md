Общее описание
==============

Данное API предназначено для централизованного хранения данных пользователя. Здесь описывается не физическая структура хранения, а логическая структура данных пользователя. Сервис предполагает доступ только аутентифицированного пользователя.

Примерами использования данного API являются:

- истории просмотров медиа–контента;
- реализация списка избранного контента;
- хранение идентификаторов устройств;
- подписки на медиа–контент.

Структура данных
----------------

Данные пользователя имеют древовидную структуру элементов, на одном уровне иерархии которого не может существовать двух элементов с одинаковым идентификатором.

Каждый элемент имеет идентификатор и относится к одному или более классам. Класс определяет набор атрибутов элемента.

Атрибуты элементов могут быть следующих типов данных:

- булев;
- целое число;
- вещественное число;
- строка (в UTF-8 кодировке).

Виды атрибутов:

- по обязательности:
	- обязательные — должны быть заполнены
	- необязательные — могут быть не заполнены
- по количеству:
	- единичные — могут быть заполнены только одним значением
	- множественные — могут быть заполнены сколько угодно раз

Каждый элемент имеет следующие обязательные атрибуты:

- доступные пользователю посредством данного API:
	- `object_id` — строковый единичный — уникальный (среди элементов текущего уровня) идентификатор элемента
	- `class_name` — строковый множественный — множество классов элемента
- недоступные пользователю через API, необходимые серверу для служебных нужд:
	- `created_by` — строковый единичный — идентификатор приложения, создавшего элемент
	- `object_id_autogenerated` — булев единичный — признак автоматически сгенерированного идентификатора элемента

Фильтр элементов
----------------

При выборке элементов используется понятие фильтра элементов. Фильтр — это выражение, определяющее критерии отбора элементов. Если фильтр не указан, в выборку попадают все элементы.

Выражение фильтра поиска записывается в префиксной нотации, состоящей из логических операторов и операндов, в свою очередь являющихся внутренними операторами сопоставления значений атрибутов (в левой части) с выражениями (в правой части) с использованием знака оператора.

Одним из операторов сопоставления значений является пустой оператор, в таком случае фильтр интерпретируется как допускающий любое заполненное значение для необязательного атрибута.

Все остальные операторы работают по–разному в зависимости того, применяются они к единичным атрибутам или ко множественным.

### Операторы над единичными атрибутами ##

Так как для всех типов данных атрибутов определено отношение порядка, для единичных атрибутов определены операторы больше и меньше. Полная таблица операторов:

 название     | обозначение | количество аргументов | описание
--------------|-------------|-----------------------|----------
строго меньше |  `<`        | 1                     | фильтрует элементы с меньшими значениями атрибута, чем операнд в правой части
строго больше |  `>`        | 1                     | фильтрует элементы с большими значениями атрибута, чем операнд в правой части
равенство     |  `=`        | 1 или больше          | фильтрует элементы со значениями атрибута, равными одному из перечисленных в операнде в правой части

Оператор равенства для единичных атрибутов позволяет сокращать запись для огранизации множественных выборок, указывая имя атрибута один раз (ср. с оператором `IN` в SQL)

### Операторы над множественными атрибутами [multivalue-operators] ##

Для множественных атрибутов операции равносильны работе со множествами, при этом правый операнд трактуется как множество, состоящее из перечисленных через запятую элементов.

При этом вводится дополнительное отношение порядка "строго меньше" для множеств, содержащих упорядоченные элементы (лексикографический). Множество `A` считается "строго меньшим" множества `B`, если после сортировки элементов множеств `A` и `B`, существует такой индекс `n`, что выполняется:

1. для всех `i`, `(i < n) => (A[i] = B[i])`,
2. и одно из двух:
	- либо количество элементов в `A` меньше `n`, но количество элементов `B` не меньше `n`,
	- либо `A[n]` существует и `A[i] < B[i]`.


 название              | обозначение | количество аргументов | описание
-----------------------|-------------|-----------------------|----------
является подмножеством | >           | 1 или больше          | фильтрует элементы, атрибут которых включает в себя все значения из операнда в правой части
является надмножеством | <           | 1 или больше          | фильтрует элементы, атрибут которых является подмножеством множества значений из операнда в правой части
равенство              | =           | 1 или больше          | фильтрует элементы, атрибут которых равен множеству значений из операнда в правой части
строго меньше          | <<          | 1 или больше          | фильтрует элементы, атрибут которых "строго меньше" множества значений из оператора в правой части
строго больше          | >>          | 1 или больше          | фильтрует элементы, атрибут которых "строго больше" множества значений из оператора в правой части

Например, имеется следующий набор элементов:

	{ object_id: '1', class_name: ['1'] },
	{ object_id: '2', class_name: ['1', '2'] },
	{ object_id: '3', class_name: ['1', '2', '3'] },
	{ object_id: '4', class_name: ['2', '3'] }

 фильтр           | список идентификаторов элементов после применения фильтра
------------------|-----------------------------------------------------------
`class_name>1,2`  | `[ '2', '3' ]`
`class_name<1,2`  | `[ '1', '2' ]`
`class_name=1,2`  | `[ '2' ]`
`class_name>>1,2` | `[ '3', '4' ]`
`class_name>>2,3` | `[ ]`

	Filter := Equation

Сортировка элементов
--------------------

При выдаче элементов важной частью является порядок, в котором возвращаются элементы. Порядок сортировки определяется пользователем указанием последовательности имен атрибутов через запятую, предваряя символом `-` при необходимости сортировки в убывающем порядке.

Если в именах атрибутов встречаются символы `-` или `,`, они должны быть экранированы с помощью символа обратного слэша: `\-` и `\,`, соответственно.

Для множественных атрибутов сортировка осуществляется c помощью [операций "строго больше" и "строго меньше"][multivalue-operators].

Авторизация доступа для приложений
----------------------------------

Авторизация доступа для приложений состоит из

- списка элементов, к которым приложение имеет доступ 
- и множества действий, которые разрешено производить приложению над ними. Действия выбираются из следующего списка:
	- чтение элементов и значений их атрибутов
	- запись новых элементов, изменение атрибутов элементов и удаление элементов, созданных этим же приложением
	- изменение атрибутов элементов, созданных другими приложениями (всех или только ограниченного набора)
	- удаление элементов, созданных другими приложениями (всех или только ограниченного набора)

Наличие доступа до элемента автоматически влечет наследование авторизации доступа приложения для всех его дочерних элементов.

Взаимодействие приложений с API
===============================

API работает по протоколу HTTPS (передаваемые данные должны шифроваться), корень доступа до API получается приложением из Регистратуры. Запросы к API составляются следующим образом:

	https://<path_to_api>/<api_version>/<path_to_element>?method=<method>&token=<token>&format=<format>&[extra_data]

Где:

- `path_to_api` — путь до API, полученный в Регистратуре
- `api_version` — мажорная версия API (должна быть равна `1`)
- `path_to_elem` — имя элемента, над которым производится действие
- `method` — метод, который производится над элементом
- `token` — токен доступа, полученный на сервере аутентификации пользователя и авторизации приложения
- `format` — формат упаковки данных
- `extra_data` — дополнительные параметры методов

Формат упаковки параметров в теле ответа (или в теле запроса) может быть одним из:

- `json` — JSON;
- `protobuf` — Google Protocol Buffers.
- 
Значения всех параметров перед передачей серверу необходимо кодировать для предотвращения неоднозначной интерпретации так, как это рекомендуется в [RFC3986].

[RFC3986]: http://tools.ietf.org/html/rfc3986

Некоторые запросы, такие как вставка элементов и изменение атрибутов элементов, могут потребовать передачи большого количества параметров, в таком случае они передаются в теле запроса методом POST. Возможны также "облегченные" варианты, когда параметров не очень много, они могут быть переданы в строке запроса. Способ кодирования параметров в таком случае обычно принимается как `атрибут=значение`, в отдельных случаях, когда данный способ кодирования не подходит для элементов класса, он должен быть описан вместе с описанием класса.

Стандартные коды ответов
------------------------

Для каждого метода API предусмотрены стандартные коды ответов. При этом, если это была групповая операция, то существует код ответа для групповой операции вцелом, а также коды ответов для каждой элементарной операции. Ниже приведены стандартные коды ответов:

- `200` — успешное завершение операции
- `400` — ошибка декодирования параметров метода
- `403` — ошибка доступа к элементу
- `404` — элемент или атрибут не найден
- `409` — ошибка схемы данных (не задан обязательный атрибут, попытка добавления множественного значения для единичного атрибута)

Методы
======

search — поиск дочерних элементов
---------------------------------

Дополнительные параметры (передаются в строке запроса):

 параметр | значение по умолчанию | смысл
----------|-----------------------|-------
`filter`  | пусто                 | фильтр результатов поиска
`order`   | `object_id`           | порядок возвращаемых элементов
`quantity`| `10`                  | максимальное количество возвращаемых элементов
`skip`    | `0`                   | количество элементов, которые необходимо пропустить при выдаче

Поиск производится только среди дочерних элементов (на один уровень вниз).

Формат ответа: сообщение `SearchResults`.

Также в заголовках ответа должно присутствовать поле `X-Ordered-By` с описанием сортировки, использованной при выдаче элементов.

modify — добавление и изменение элементов
-----------------------------------------

Дополнительные параметры передаются либо:

- в теле запроса методом POST (сообщение `ModifyRequests`, кодируется форматом, указанным в параметре запроса),
- в дополнительных параметра строки запроса (в таком случае возможна только одна операция над только одним элементом).

Параметр `operation` отвечает за тип производимых изменений и может принимать следующие значения:

- `0` — add — добавление значений для множественных атрибутов;
- `1` — delete — удаление атрибута;
- `2` — replace — замена всех значений атрибута переданными.

Формат ответа: сообщение `ActionResults`.

В теле ответа содержатся результаты операций (сгруппированные по элементам) в том же порядке, в котором они были запрошены. В случае неуспешного запроса к элементу не применяется ни одна из операций, участвующих в нем.

Изменение элемента с несуществующим идентификатором фактически означает запрос на его создание, идентификатор в таком случае создается сервером. При этом, последний должен сохранять признак самостоятельной генерации идентификатора элемента (выставлять атрибут `object_id_autogenerated` в значение `true`). В дальнейшем данный атрибут необходим для эффективной работы алгоритма объединения данных пользователей.

Дополнительные коды ответов:

- `201` — элемент создан.

delete — удаление дочерних элементов
------------------------------------

Дополнительные параметры:

 параметр   | значение по умолчанию | смысл
------------|-----------------------|-------
`object_id` | отсутствует           | идентификаторы удаляемых дочерних элементов

При удалении элемента также удаляются все его дочерние элементы.

Идентификаторы передаваемых дочерних элементов фактически являются частным примером фильтра для атрибута `object_id`. К ним применяются те же правила, что и к обычному `Equation`: в идентификаторах элементов нужно экранировать символ `,`, а чтобы удалить несколько дочерних элементов, необходимо перечислить их через запятую. Все значение параметра `object_id` необходимо закодировать стандартным алгоритмом кодирования значений элементов URI.

Если количество удаляемых элементов достаточно велико, допускается передача параметра `object_id` методом POST.

Формат ответа: сообщение `ActionResults`. 

Рекомендации к реализации на сервере:

1. данный метод не удаляет элементы, а помечает их таким образом, чтобы они не участвовали в выдаче метода search;
2. приложениям запрещается удалять корневой элемент.


Спецификация API для Google Protocol Buffers
============================================

	package UserDataAPIv1;
	
	message Element {
	  optional string object_id = 1;
	  repeated string class_name = 2;
	  optional bytes attributes = 3;
	}
	 
	message SearchResults {
	  repeated Element elements = 1;
	  optional int32 total_count = 2;
	  optional int32 items_skipped = 3 [default = 0];
	}
	 
	message ModifyRequest {
	  message Change {
	    enum Operation {
	      ADD = 0;
	      DELETE = 1;
	      REPLACE = 2;
	    }
	 
	    optional Operation operation = 1;
	    optional bytes attributes = 2;
	  }
	 
	  optional string object_id = 1;
	  repeated Change changes = 2;
	}
	 
	message ModifyRequests {
	  repeated ModifyRequest modify_requests = 1;
	}
	 
	message ActionResult {
	  optional string object_id = 1;
	  optional int code = 2;
	}
	 
	message ActionResults {
	  repeated ActionResult results = 1;
	}

Замечания:

- Значения атрибутов элемента в общем случае описать нельзя, так как они определяются классами элемента.
- При конвертировании сообщения `Element` в формат JSON параметр `attributes` превращается в отдельный объект, описывающий атрибуты.
- При конвертировании сообщения `Element` в формат Protocol Buffers параметр `attributes` превращается в отдельное сообщение, содержащее атрибуты.
- При выдаче списка элементов в формате JSON, если у элемента отсутствуют атрибуты, допускается пропуск данного свойства. Аналогичная ситуация допускается с дочерними элементами.

--------

Хранит устройства пользователя. Может использоваться для организации проталкивающих уведомлений на устройства пользователя.

Дочерними выступают элементы класса [`device`][cn-device], дочерние элементы являются терминальными.

В качестве идентификаторов элементов выступают идентификаторы устройств.

/applications
-------------

Хранит приложения пользователя для указания их, например, в списке истории просмотра фильмов.

Дочерними выступают элементы класса [`application`][cn-application], дочерние элементы являются терминальными.

В качестве идентификаторов элементов выступают идентификаторы экземпляра инсталляции программы.

/history/playback/rips
----------------------

Хранит историю воспроизведения рипов фильмов. Используется для удобства продолжения просмотра.

Дочерними выступают элементы классов [`action`][cn-action]+[`time_limited_playback`][cn-time-limited-playback]+[`catalogue_item`][cn-catalogue-item].

В качестве идентификаторов элементов используются идентификаторы рипов (`MediaPart::id` в терминах Films API). Уточнения по атрибутам:

- `catalogue_item_id` — идентификатор карточки афиши (элемента каталога), `CatalogueItem::id` из Films API
- `catalogue_id` — идентификатор афиши (сервиса фильмов из Registry API)

При слиянии атрибутов дочерних элементов выбираются атрибуты того элемента, у которого `action_time` больше.

/history/playback/channels
--------------------------

Хранит историю воспроизведения телевизионных каналов.

Дочерними выступают элементы классов [`action`][cn-action]+[`catalogue_item`][cn-catalogue-item].

Именование элементов можно как делегировать серверу, так и использовать идентификаторы каналов из "Универсальной телепрограммы". Уточнения по атрибутам:

- Если в при воспроизведении телеканала оператором был присвоен идентификатор канала из сервиса "Универсальной программы":
	- `catalogue_item_id` — идентификатор канала, `Channel::id` из TV API
	- `catalogue_id` — идентификатор сервиса "Универсальная телепрограмма"
- иначе
	- `catalogue_item_id` — название канала, если оно было указано, иначе — номер строки канала в списке
	- `catalogue_id` — идентификатор сервиса телевидения

При слиянии атрибутов дочерних элементов выбираются атрибуты того элемента, у которого `action_time` больше.

/favourites/tv/channels
-----------------------

Хранит список избранных телевизионных каналов.

Дочерними выступают элементы класса [`catalogue_item`][cn-catalogue-item].

В качестве идентификаторов элементов следует использовать идентификаторы каналов из сервиса "Универсальная телепрограмма".
