# Введение

MoneyMiner API предназначен для медиации и таргетирования рекламных сетей, используемых в приложениях.
Использую систему управления медиацией и таргетированием можно:

- отключить рекламу для определенного провайдера
- отключить рекламу для пользователя, оформившего подписку
- старгетировать рекламную сеть на определенную территорию (Европа)

# Взаимодействие с API

Точка входа в API определяется Регистратурой, идентификатор сервиса — "money_miner". Обращения строятся по схеме:

	<entry_point>/<method>.<format>?[parameters]

где:

- `<entry_point>` — точка входа, полученная из Регистратуры
- `<method>` — название метода
- `<format>` — формат ответа, всегда JSON
- `[parameters]` — список параметров метода в виде "ключ=значение", разделенных символом "&"

пример обращения:

	http://api.peers.tv/money_miner/1/places.json?id=iap-s0321384,iap-d7das7132

Значения всех параметров необходимо кодировать для предотвращения неоднозначной интерпретации так, как это рекомендуется в [RFC3986]. Кодирование запросов и ответов должно выполняться в кодировке UTF-8.

[RFC3986]: http://tools.ietf.org/html/rfc3986

## Аутентификация

Для аутентификации пользователя клиент должен передать полученный ранее токен доступа, выданный Auth API контрагента, по схеме аутентификации в соответствии с типом токена.

Для авторизации по типу токена "[Bearer][rfc6750]" рекомендуется использовать HTTP заголовок Authorization, пример:

	Authorization: Bearer 18dasd81230dah12032

[rfc6750]: http://tools.ietf.org/html/rfc6750

## Стандартные коды ответов

Для каждого метода API предусмотрены стандартные коды ответов ([RFC2616][rfc2616]). Ниже описана интерпретация некоторых кодов:

- 200 — запрос успешно обработан
- 400 — некорректно составлен запрос
- 401 — требуется аутентификация:
	- необходимо передать данные аутентификации;
	- данные аутентификации некорректны;
	- данные аутентификации корректны, но переданный токен доступа был отозван или истек срок его действия.
- 403 — доступ запрещен:
	- переданы данные аутентификации, которые не позволяют выполнить запрос в силу отсутствия необходимых разрешений.

В случае кодов 401, 403 должен быть передан HTTP заголовок WWW-Authenticate с указанием ожидаемой схемы аутентификации и дополнительнной информации (если применимо). Например, для схемы "[Bearer][rfc6750]" может быть указан дополнительный атрибут error со значением:

 - invalid_token — передан некорректный, просроченный или отозванный токен доступа (код 401);
 - insufficient_scope — запрос требует более высоких привилегий, чем те, которыми обладает токен доступа (код 403).

[rfc2616]: http://www.w3.org/Protocols/rfc2616/rfc2616-sec10.html

# Требования по реализации [implementation-requirements]

Для корректной работы системы приложение *должно*:

- поддерживать кэш результатов выполнения запросов и сбрасывать его:
	- по истечению таймаута (1 час)
	- при смене сетевых реквизитов
- для конкретного баннерного места:
	- игнорировать неподдерживаемые типы рекламных сетей
	- учитывать порядок следования рекламных сетей
	- учитывать ограничение на частоту запросов к рекламным сетям
	
# Типы рекламных сетей

Каждая [рекламная сеть][p-ad-system] может включать индивидуальный набор параметров инициализации рекламного места.

Параметры:

- VAST API
	- `vast_ad_tag` — шаблон URL, содержащий макросы вида \[MACRO\]. Известные макросы приложение должно заменить на соответствующее значение, неизвестные — на процент-кодированное по [RFC3986] название макроса.
- Admob SDK
	- `banner_id` — идентификатор баннера
- WapStart API
	- `site_id`— идентификатор приложения
- Yandex Video SDK
	- `partner_id` — идентификатор партнера (соответствует идентификатору ресурса, см. пояснение ниже)
	- `block_num` — номер блока (см. пояснение ниже)
	- `target_ref` — площадка размещения
	- `page_ref` — страница перехода (для приложений всегда равно `target_ref`)
-  Ivengo SDK
	- `application_id` идентификатор приложения
- IMA SDK
	- `vast_ad_tag` — шаблон URL, содержащий макросы вида \[MACRO\]. Известные макросы приложение должно заменить на соответствующее значение, неизвестные — на процент-кодированное по [RFC3986] название макроса
- Yume SDK
	- `domain_id` — идентификатор рекламной площадки
	- `ad_server_url` — адрес рекламного сервера
- myTarget SDK
	- `slot_id` — идентификатор баннера
- Yandex Ads SDK
	- `block_id` — идентификатор рекламного блока
- SpotX SDK
	- `channel-id` — идентификатор рекламного блока

Список известных макросов для параметра `vast_ad_tag`:

- `[CACHEBUSTING]` — случайная строка для обхода кэширования
- `[USER_ID]` — идентификатор пользователя в формате UUID (рекомендуется использовать `IDFA` или `ADVERTISING_ID`)
- `[SESSION_ID]` — идентификатор сессии воспроизведения в формате UUID
- `[INSTALL_ID]` — идентификатор установки приложения в формате UUID


Пояснение по параметрам для Yandex Video SDK:

В панели администратора используются идентификаторы блоков вида `R-V-171889-2`, в данном идентификаторе зашит идентификатор партнера `171889` и номер блока `2`.

# Методы

## places — получение информации по местам баннеров [m-places]

Параметры:

параметр|   тип данных    | значение
--------|-----------------|-----------
`id`    | строки через ','| список идентификаторов рекламных мест

Формат ответа: [`AdPlaceList`][p-ad-place-list]

*ВАЖНО*: метод принимает не более 10 идентификаторов рекламных мест.

### Пример успешного взаимодействия

*Запрос*

	GET /money_miner/1/places.json?id=JxDBgQmd
	Authorization: Bearer 18dasd81230dah12032
	Host: api.peers.tv

*Ответ*

	HTTP/1.1 200 OK
	Content-Type: application/json

	{
	   "places": [{
	      "place_id":"JxDBgQmd",
	      "ad_systems": [{
	          "type":1,
	          "name":"Адривер",
	          "id":370223,
	          "price":200,
	          "params": [{
	             "key":"vast_ad_tag",
	             "value":"http://ad.adriver.ru/cgi-bin/erle.cgi?sid=170878&sz=test&bn=322&target=top&bt=61&pz=1&rnd=[CACHEBUSTING]"
	          }]
	       }],
	   "request_delay":15
	   }]
	}

# Описание ответов в формате Google Protocol Buffers

## AdPlaceList, AdPlace — рекламной место [p-ad-place-list]

	message AdPlaceList {
	  repeated AdPlace places = 1;
	}

	message AdPlace {
	  optional string place_id = 1;
	  repeated AdSystem ad_systems = 2;
	  optional int32 request_delay = 3 [default = 0];
	}

Замечания:

- `place_id` — идентификатор запрошенного рекламного места
- `ad_systems` — упорядоченный список рекламных сетей
- `request_delay` — минимальная задержка между показами рекламы для рекламного места (в секундах)

## AdSystem, AdSystemParam — описание рекламной сети [p-ad-system]

	message AdSystem {
	  message AdSystemParam {
	    optional string key = 1;
	    optional string value = 2;
	  }

	  enum AdType {
	    VAST_API   = 1;
	    ADMOB_SDK  = 2;
	    WAPSTART   = 3;
	    YANDEX_VIDEO = 4;
	    IVENGO_SDK = 5;
	    IMA_SDK    = 6;
	    YUME_SDK   = 7;
	    MY_TARGET_SDK = 8;
	    YANDEX_ADS = 9;
	    SPOTX_SDK = 10;
	  }

	  enum BannerType {
	    INTERSTITIAL    = 1;
	    GRAPHIC         = 2;
	    VIDEO           = 3;
	    NATIVE          = 4;
	    NATIVE_TEMPLATE = 5;
	  }

	  optional AdType type = 1;
	  optional string name = 2;
	  repeated AdSytemParam params = 3;
	  optional int32 id = 4;
	  optional int32 price = 5;
	  optional BannerType banner_type = 6;
	}

Замечания:

- `type` — тип SDK для интеграции рекламной сети
- `name` — название рекламной сети
- `params` — параметры для рекламной сети
- `id` — уникальный идентификатор рекламной сети
- `price` — эффективная стоимость размещения на 1000 показов баннера (eCPM)
- `banner_type` — тип баннера:
	- `INTERSTITIAL` — межстраничный
	- `GRAPHIC` — графический или текстовый
	- `VIDEO` — видео-реклама
	- `NATIVE` — нативный
	- `NATIVE_TEMPLATE` — нативный с шаблоном
