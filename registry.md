Общая информация
================

Регистратура — точка входа для всех приложений Инетры, позволяющая определить:

- интернет–провайдера абонента
- территории, на которой располагается абонент
- список доступных пользователю сервисов на определенной территории

Синхронизация времени
--------------------

Клиент может синхронизировать локальное время с серверным на основе информации о часовом поясе и времени генерации ответа, полученного из HTTP–заголовка `Date` (см. [RFC822][rfc822-url]).

Данный прием позволяет выполнить синхронизацию времени с некоторой ошибкой (ввиду сетевых задержек).

[rfc822-url]: http://tools.ietf.org/html/rfc822

Расположение API
----------------

Корневой адрес API — `http://api.cn.ru/registry/2/`. Формат ответа зависит от суффикса запроса:

- `.xml` — XML;
- `.json` — JSON;

Цифра `2` символизирует версию API и может меняться в дальнейшем.

Коды ответов
------------

API возвращает результат работы в HTTP–коде и имеет следующие стандартные коды ответов:

 Код  | Значение
------|----------
`200` | Успешное обращение к методу
`400` | В запросе отсутствует обязательные параметры
`501` | Метод не реализован

Сервисы контрагентов
--------------------

Сервис может иметь несколько способов доставки. К примеру, IP–телевидение может поставляться как с помощью multicast, так и с помощью других средств, вроде HTTP Live Streaming или RTSP.

Методы
======

whereAmI — где я
----------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`territory`  | автоматически определенный | идентификатор территории
`contractor` | автоматически определенный | идентификатор оператора

Возвращает информацию о месторасположении клиента. Если заданы дополнительные параметры, абонент рассматривается, как будто он находится на указанной территории и/или провайдере.

Формат ответа: сообщение [`WhereAmI`][whereami-message].

Замечания:

- Список территорий, возвращаемых данным методом, зачастую состоит из одной территории, на которой находится абонент. Однако возможны случаи, когда вернется несколько территорий. Обычно это случаи, когда абонент находится на стыке двух контрагентов (например, Инетры и Владлинка), адресное пространство которых распределено между несколькими территориями (Новосибирск и Владивосток, соответственно).

territories — получение списка территорий
-----------------------------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`id`         | отсутствует                | список идентификаторов территорий, разделенных символом запятая (`,`)
`territory`  | `0`, т.е. "весь мир"       | идентификатор территории, для которой запрашиваются дочерние
`contractor` | отсутствует                | идентификатор контрагента, которому должны принадлежать запрашиваемые территории
`q`          | отсутствует                | строка, с которой начинается название территории
`parents`    | `0`                        | количество родительских территорий, возвращаемых в запросе (<span style="color:#0f0">новое в 2.8</span>)

Ответ: сообщение [`TerritoryList`][territoryinfo-message].

Замечания:

- Начиная с версии 2.6 Registry API при запросе можно добавить дополнительный фильтр, указывающий на то, что в выдаче списка территорий будут присутствовать только те территории, на которых предоставляются запрашиваемые сервисы. При этом, если сервис предоставляется не в самой территории, а только в ее подтерритории, она также будет присутствовать в выдаче. Например, сервис peers предоставляется на территории России. Но в выдаче всех территорий, на которых предоставляется этот сервис есть территория "Весь мир", так как в нее входит территория "Россия", но отсутствует "Америка"
- Начиная с версии 2.8 Registry API с помощью данного запроса можно получить не только идентификатор родительской территории, но и всю информацию о всех родительских территориях, если их вложенность не превышает параметра `parents`

neighborhood — информация о соседних ареалах
--------------------------------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`area`       | автоматически определенный | идентификатор ареала

Формат ответа: сообщение [`AreaList`][area-message].

hubList — хабы ареала
---------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`area`       | отсутствует                | идентификатор ареала

Формат ответа: сообщение [`HubList`][hub-message].

Если параметр `area` не задан, возвращаются все хабы всех ареалов.

hubIsolations — изоляция между хабами ареала
--------------------------------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`area`       | отсутствует                | идентификатор ареала

Формат ответа: сообщение [`HubIsolationList`][hubisolation-message].

prefixes — IP–префиксы контрагента
----------------------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`contractor` | отсутствует                | идентификаторы контрагента
`territory`  | отсутствует                | идентификаторы территории

Формат ответа: сообщение [`PrefixList`][prefixlist-message].

Замечания

- Начиная с версии 2.5 список префиксов можно получить не только по одному идентификатору контрагента, но также задав уточняющую информацию о территории. При указании нескольких параметров одного типа (например, контрагентов) конструкция понимается как логическое "ИЛИ", при указании разных типов — как логическое "И"

Например, чтобы получить список префиксов контрагентов `1` и `2`, которые находятся на территории с идентификатором `6`, необходимо в данном запросе передать параметры `contractor=1,2&territory=6`.

contractors — получение списка контрагентов
-------------------------------------------

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`id`         | отсутствует                | список идентификаторов контрагентов, разделенных символом запятая (`,`)
`area`       | отсутствует                | идентификатор ареала
`territory`  | отсутствует                | идентификатор территории
`q`          | отсутствует                | строка, с которой начинается название контрагента
`services`   | отсутствует                | строковые идентификаторы сервисов, перечисленные через запятую

Формат ответа: сообщение [`ContractorList`][contractorinfo-message].

Замечания:

- Начиная с версии 2.6 API можно производить поиск по имени контрагента, а также (аналогично получению списка территорий) получать список только контрагентов, которым предоставляются указанные сервисы

knownInfo — информация от пользователя
--------------------------------------

Формат запроса: сообщение [`KnownInfo`][knowninfo-message].

Запрос передается методом POST в формате, соответствующем суффиксу запроса.

Запрос используется для новых контрагентов, информации о которых нет в Регистратуре, а также для сбора данных от пользователей о неверных результатах определения контрагента и территорий.  Данная информация сохраняется на сервере и используется в качестве справочной при создании нового контрагента на основе данных, введенных пользователем. Во время сохранения информации в базе данных также фиксируется IP адрес источника запроса, а также информация из RIPE на момент запроса.

Идентификатор устройства пользователя позволяет модератору Регистратуры отделять запросы одного и того же пользователя в случае преднамеренной отправки множества данных и/или информационного мусора.

## WhereAmI — Где я [whereami-message]

	message WhereAmI {
	  optional ContractorInfo contractor = 1;
	  repeated TerritoryInfo territories = 2;
	  repeated APIInfo apis = 3 [deprecated=true];
	  repeated Service services = 4;
	  optional string ipAddress = 5;
	} 

	message APIVersion {
	  optional uint32 majorVersion = 1;
	  optional uint32 minorVersion = 2;
	  optional string location = 3;
	  optional string params = 4;
	}
	 
	message APIInfo {
	  enum APIType {
	    FILMS = 0;        // Films API
	    IPTV = 1;         // телевидение провайдера
	    TV_RECORDS = 2;   // контент Peers.TV
	  }
	  
	  optional APIType apiType = 1;
	  optional string name = 2;
	  repeated APIVersion apiVersions = 3;
	}
	 
	message Service {
	  enum Type {
	    option allow_alias = true;

	    FILMS = 0 [(CN.string_value) = "films"];
	    IPTV = 1 [(CN.string_value) = "iptv"];
	    PEERSTV = 2 [(CN.string_value) = "peerstv"];
	    PEERS = 3 [(CN.string_value) = "peers"];
	    TV_GUIDE = 4 [(CN.string_value) = "tv_guide"];
	    MEDIA_GUIDE = 4 [(CN.string_value) = "tv_guide"];
	    NOTIFICATION = 5 [(CN.string_value) = "notification"];
	    TRACKING = 6 [(CN.string_value) = "tracking"];
	    AUTH = 7 [(CN.string_value) = "auth"];
	    DATA = 8 [(CN.string_value) = "data"];
	    USERS_MERGE = 9 [(CN.string_value) = "users_merge"];
	    MEDIA_LOCATOR = 10 [(CN.string_value) = "media_locator"];
	    PINGER = 11 [(CN.string_value) = "pinger"];
	    RADIO = 12 [(CN.string_value) = "radio"];
	    CATALOGUE = 13 [(CN.string_value)="catalogue"];
	  }
	 
	  optional Type type = 1;
	  optional ContractorInfo contractor = 2;
	  optional string name = 3;
	  repeated APIVersion apiVersions = 4;
	  optional uint32 pingInterval = 5;
	}

Замечания:

- `APIType` задает тип API: фильмы, телевидение или записи телепередач
- `APIVersion.params` задает дополнительные обязательные параметры, для передачи в указанное API
- `WhereAmI.apis` — <span style="color:#f00">устарело с версии 2.6</span>
- `WhereAmI.services` — сервисы, доступные пользователю данного контрагента на данной территории:
	- `Service.type` — код (для JSON и XML представлений — строковый идентификатор) сервиса
	- `Service.contractor` — контрагент, предоставляющий услугу
	- `Service.name` — название сервиса
	- `Service.apiVersions` — доступные версии API сервиса
	- `Service.pingInterval` - интервал времени между двумя запросами (заполняется только для сервиса `PINGER`)
- `WhereAmI.ipAddress` — строковое представление IP адреса клиента, IPv4 или IPv6 (<span style="color:#0f0">новое в 2.7</span>)

## TerritoryInfo, TerritoryList — информация о территории [territoryinfo-message]

	message TerritoryInfo {
	  optional uint32 territoryId = 1;
	  optional string name = 2;
	  optional string parentId = 3;
	  optional bool isLeaf = 4;
	  optional TerritoryInfo parent = 5;
	  optional int32 timezone = 6;
	}
	 
	message TerritoryList {

Замечания:

- `TerritoryInfo.parent` — иерархия родительских территорий (<span style="color:#0f0">новое в 2.8</span>)
- `TerritoryInfo.timezone` — часовой пояс, выраженный в секундах относительно UTC, например, для Новосибирска принимает значение `25200`, а для Нью–Йорка — `-18000` (по зимнему времени)(<span style="color:#0f0">новое в 2.12</span>)

Замечание: для часового пояса не учитывается переход на зимнее/летнее время, а также в некоторых случаях значение может отсутствовать, например, когда для территории может быть определено более одного часового пояса (пример: Россия, СФО).

## Prefix, PrefixList — список IP–префиксов [prefixlist-message]

	message PrefixList {
	  message Prefix {
	    optional string CIDR = 1;
	    optional string NAT = 2;
	    optional bool peersAccess = 3;
	    optional ContractorInfo contractor = 4;
	    repeated TerritoryInfo territories = 5;
	  }
	 
	  repeated Prefix prefixes = 1;
	}

Замечания:

- Параметры `CIDR` и `NAT` задаются в формате `A.B.C.D/Y` или `A.B.C.D` (в случае одиночного IP адреса)
- Параметр `NAT` может присутствовать только для частных адресов, задает их трансляцию
- Параметр `peersAccess` отвечает за наличие доступа в Пирс абонентам указанного префикса
- `contractor` — информация о контрагенте префикса. Гарантируется передача только идентификатора контрагента
- `territories` — территории, за которыми закреплен префикс. Гарантируется передача только идентификатора территории. Если за префиксом не закреплена территория, возвращается список территорий контрагента

Замечания:

- `contractorId` — идентификатор контрагента известный нам и выбранный пользователем
- `contractorName` — название контрагента (оператора связи)
- `territoryId` — идентификатор территории известный нам и выбранный пользователем
- `territoryName` — название территории
- `parentTerritoryId` — идентификатор родительской территории (если задана, то должна присутствовать в Регистратуре)
- `iptvPlaylistAddress` — адрес списка каналов оператора связи
- `uid` — идентификатор устройства пользователя, с которого совершен запрос

История версий
==============

Изменения в версии 2.0
----------------------

- Дополнительные способы сериализации (Google Protocol Buffers)
- Дополнительные методы:
	- получения списка территорий
	- получение списка контрагентов по территории
- Фиксирование типов данных
- Добавлена возможность передачи мажорной и минорной версий сторонних API
- Для контрагентов (провайдеров) добавлены логотипы
- При передаче известной информации от пользователя добавлена возможность указывания надтерритории
- Выдача метода об изоляции нод синхронизирована с конфигурацией хаба.

Изменения в версии 2.1
----------------------

- Добавлено поле "бренд" для контрагента.

Изменения в версии 2.2
----------------------

- Добавлена информация об ареалах, в которых участвует хаб
- Добавлена возможность получения списка всех хабов без указания идентификатора ареала.

Изменения в версии 2.3
----------------------

- Реализован метод `knownInfo`.
- В метод `prefixes` добавлена информация о наличии доступа в Пирс.

Изменения в версии 2.4
----------------------

- Переработан метод `knownInfo`.
- Добавлено описание по возвращаемым ошибкам.
- Убран из описания нереализованный формат Google Protocol Buffers.

Изменения в версии 2.5
----------------------

- Добавлен способ получения списка префиксов по территории и/или контрагенту.
- Для префикса добавлена информация о контрагенте и территориях.
- Добавлен полнотекстовый поиск по территориям.

Изменения в версии 2.6
----------------------

- Добавлено понятие сервисов и метод для получения списка доступных сервисов абоненту.
- Добавлен способ фильтрации контрагентов и территорий по предоставляемым сервисам.
- Добавлен полнотекстовый поиск по контрагентам.

Изменения в версии 2.7
----------------------

- Добавлено поле для URL личного кабинета контрагента.
- В метод `whereAmI` добавлен IP адрес, видимый сервером.

Изменения в версии 2.8
----------------------

- Добавлены дополнительные сервисы (коды с `4` по `6`).
- В метод `territories` добавлен способ получения полной информации об определенном количестве родительских территорий.

Изменения в версии 2.9

- Добавлены дополнительные сервисы (коды с `7` по `9`).

Изменения в версии 2.10
