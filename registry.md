# Общая информация

Регистратура[^responsibility] — точка входа для всех приложений Инетры, позволяющая определить:

- интернет–провайдера абонента
- территории, на которой располагается абонент
- список доступных пользователю сервисов на определенной территории

[^responsibility]: указать область ответственности документа и API.

# Ограничения

Регистратура представляет собой большую систему привязки IP адресов к территориям и провайдерам. Поддержка Регистратуры в актуальном состоянии является довольно затратным мероприятием, так как частично задействован человеческий ресурс.

Для защиты от сбора информации, а также от избыточного количества запросов одного пользователя предусмотрено следующее:

1. В случае, когда передаются списки данных, подразумевается выдача не всех результатов единовременно, но небольшими порциями. Количество результатов *всегда* ограничено. При этом в каждом ответе, в котором подразумевается выдача списка элементов, указывается общее количество элементов в выборке, а также количество пропущенных элементов в выдаче, относительно начала списка.
2. Если приложение запрашивает некоторое количество элементов, сервер вправе уменьшить это количество для оптимизации трафика.
3. В случае обнаружения аномального количества запросов к Регистратуре вместо корректных ответов может вернуться пустой ответ, с кодом статуса ответа `429 Too Many Requests`. При этом сервер может сообщить, через какое количество времени можно получить корректный ответ в заголовке `Retry-After` (время указывается в секундах).
4. В случае повторения запросов время получения корректного ответа может быть увеличено.

# Взаимодействие с API

Корневой адрес API — `http://api.cn.ru/registry/3/`. Формат ответа зависит от суффикса запроса:

- `.json` — Classical JSON
- `.protobuf` — Google Protocol Buffers

Цифра `3` символизирует версию API и может меняться в дальнейшем.

## Коды ответов

API возвращает результат работы в HTTP–коде и имеет следующие стандартные коды ответов:

 Код  | Значение
------|----------
`200` | Успешное обращение к методу
`400` | В запросе отсутствует обязательные параметры
`429` | Слишком большое количество запросов
`501` | Метод не реализован

# Методы

## whereami — где я

Возвращает информацию о месторасположении клиента: его интернет–провайдере и территории.

Список территорий, возвращаемых данным методом, зачастую состоит из одной территории, на которой находится абонент. Однако возможны случаи, когда вернется несколько территорий. Обычно это случаи, когда абонент находится на стыке двух контрагентов (например, Инетры и Владлинка), адресное пространство которых распределено между несколькими территориями (Новосибирск и Владивосток, соответственно).

Формат ответа: сообщение [`WhereAmI`][whereami-message].

## services — список доступных сервисов

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`territory`  | автоматически определенный | идентификатор территории
`contractor` | автоматически определенный | идентификатор оператора
`types`      | пусто                      | список запрашиваемых типов сервисов
`quantity`   | 15                         | максимальное количество сервисов в выдаче[^services-quantity-max-limit]
`skip`       | 0                          | количество пропущенных сервисов в сортированной выдаче

[^services-quantity-max-limit]: количество сервисов в одном ответе не может превышать: 100 при отсутствующих параметрах `territory` и `contractor` и 10 — если хотя бы один из них задан.

Если заданы дополнительные параметры, возвращается список сервисов, предоставляемых на территории с идентификатором `territory` и/или в сети провайдера с идентификатором контрагента `contrator`.

Упоминание сервиса определённого типа должно присутствовать в ответе только тогда, когда для определённой или указанной явно территории определённый или указанный явно контрагент фактически предоставляет услугу этого типа[^russia-rostelecom-how]. Т.е., сообщение `Service` с пустым параметром `apiVersions` передавать **нежелательно**.

Формат ответа: сообщение [`ServiceList`][service-list-message]

[^russia-rostelecom-how]: В рассмотрении той ситуации, что провайдер Ростелеком предоставляет услугу телевидения на территории всей России, стоит ли понимать данное предложение как отсутствие упоминания сервиса на территории Новосибирской области? Скорее всего, нет. Надо переделать предложение.

## territories — получение списка территорий

 параметр    | значение по умолчанию | значение
-------------|-----------------------|----------
`territory`  | `0`, т.е. "весь мир"  | идентификатор территории, для которой запрашиваются дочерние
`contractor` | отсутствует           | идентификатор контрагента, которому должны принадлежать запрашиваемые территории
`q`          | отсутствует           | строка, с которой начинается название территории
`services`   | отсутствует           | фильтр сервисов, которые должны предоставляться на территории
`parents`    | 0                     | количество родительских территорий, возвращаемых в запросе
`quantity`   | 10                    | максимальное количество территорий в выдаче
`skip`       | 0                     | количество пропущенных территорий в выдаче

Ответ: сообщение [`TerritoryList`][territoryinfo-message].

Замечания:

- Начиная с версии 2.6 Registry API при запросе можно добавить дополнительный фильтр, указывающий на то, что в выдаче списка территорий будут присутствовать только те территории, на которых предоставляются запрашиваемые сервисы. При этом, если сервис предоставляется не в самой территории, а только в ее подтерритории, она также будет присутствовать в выдаче. Например, сервис `peers` предоставляется на территории России. Но в выдаче всех территорий, на которых предоставляется этот сервис есть территория "Весь мир", так как в нее входит территория "Россия", но отсутствует "Америка"
- Начиная с версии 2.8 Registry API с помощью данного запроса можно получить не только идентификатор родительской территории, но и всю информацию о всех родительских территориях, если их вложенность не превышает параметра `parents`

## neighborhood — информация о соседних ареалах

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`area`       | автоматически определенный | идентификатор ареала
`quantity`   | 10                         | максимальное количество ареалов в выдаче
`skip`       | 0                          | количество пропущенных ареалов в выдаче

Формат ответа: сообщение [`AreaList`][area-message].

## prefixes — IP префиксы контрагента

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`contractor` | отсутствует                | идентификаторы контрагента
`territory`  | отсутствует                | идентификаторы территории
`quantity`   | 10                         | максимальное количество префиксов в выдаче
`skip`       | 0                          | количество пропущенных префиксов в выдаче

Формат ответа: сообщение [`PrefixList`][prefixlist-message].

Замечания

- Начиная с версии 2.5 список префиксов можно получить не только по одному идентификатору контрагента, но также задав уточняющую информацию о территории. При указании нескольких параметров одного типа (например, контрагентов) конструкция понимается как логическое "ИЛИ", при указании разных типов — как логическое "И"

Например, чтобы получить список префиксов контрагентов `1` и `2`, которые находятся на территории с идентификатором `6`, необходимо в данном запросе передать параметры `contractor=1,2&territory=6`.

## contractors — получение списка контрагентов

 параметр    | значение по умолчанию      | значение
-------------|----------------------------|----------
`area`       | отсутствует                | идентификатор ареала
`territory`  | отсутствует                | идентификатор территории
`q`          | отсутствует                | строка, с которой начинается название контрагента
`services`   | отсутствует                | фильтр сервисов
`quantity`   | 10                         | максимальное количество контрагентов в выдаче
`skip`       | 0                          | количество пропущенных контрагентов в выдаче

Формат ответа: сообщение [`ContractorList`][contractorinfo-message].

Замечания:

- Начиная с версии 2.6 API можно производить поиск по имени контрагента, а также (аналогично получению списка территорий) получать список только контрагентов, которым предоставляются указанные сервисы

## knownInfo — информация от пользователя

Формат запроса: сообщение [`KnownInfo`][knowninfo-message].

Запрос передается методом POST в формате, соответствующем суффиксу запроса.

Запрос используется для новых контрагентов, информации о которых нет в Регистратуре, а также для сбора данных от пользователей о неверных результатах определения контрагента и территорий.  Данная информация сохраняется на сервере и используется в качестве справочной при создании нового контрагента на основе данных, введенных пользователем. Во время сохранения информации в базе данных также фиксируется IP адрес источника запроса, а также информация из RIPE на момент запроса.

Идентификатор устройства пользователя позволяет модератору Регистратуры отделять запросы одного и того же пользователя в случае преднамеренной отправки множества данных и/или информационного мусора.

	  optional ContractorInfo contractor = 1;
	  repeated TerritoryInfo territories = 2;

Замечания:

	    }

	      RETINA = 2;

	    }
	    
	    optional SizeType size_type = 1;
	    optional OSType os_type = 2;
	    optional uint32 width = 3;
	    optional uint32 height = 4;
	    optional string url = 5;
	    optional PlatformType platform_type = 6;
	    optional DeviceType device_type = 7;
	    optional ScreenDensity screen_density = 8;
	  }
	  
	  optional uint64 id = 1;
	  optional string name = 2;
	  repeated ContractorImage images = 3;
	  optional string brand_name = 4;
	  optional string private_office_url = 5;
	}
	 
	message ContractorList {
	  repeated ContractorInfo contractors = 1;
	  optional uint64 skipped = 2;
	  optional uint64 total_count = 3;
	}

Замечания:

- `ContractorInfo::name` — юридическое именование контрагента (например, "ООО Вымпелком")
- `ContractorInfo::brand_name` — имя бренда контрагента (например, "Билайн")
- `ContractorInfo::private_office_url` — адрес личного кабинета пользователя (для открытия в браузере)
- Тип картинки нужен для возможности применять максимально подходящий логотип контрагента в соответствии с типовым дизайном приложения на конкретной платформе/ОС/устройстве. Сервер на основании информации о платформе клиента может принять решение о выдаче неполного списка картинок-логотипов. Алгоритм выбора подходящей картинки, применимый для сервера и клиента:
	1. Если известна об использовании нативного приложения под ОС `os_type` (`IOS`, `OSX`, `WINDOWS` и другие), включить в список выдачи картинки всех размеров с этим признаком
	2. Если известен тип платформы `platform_type` (`DESKTOP`, `TV`, `MOBILE`), включить в список выдачи картинки всех размеров с этим признаком
	3. Если известен тип устройства `device_type` (`PHONE`, `TABLET`), включить в список картинки всех размеров с этим признаком
	4. Если набор размеров картинки в списке выдачи ещё неполон, и если известно об использовании браузера `platform_type`: `WEB`, включить в список картинки всех размеров с этим признаком
	5. Если набор размеров картинки в списке выдачи ещё неполон, и существует картинка с незаполненным полями (`os_type`, `platform_type`, `device_type`), включить в список картинки всех размеров без этих признаков
	6. Приоритет использования картинок на клиенте: используется первая найденная в списке картинка нужного размера.

## Prefix, PrefixList — список IP–префиксов [prefixlist-message]

	message Prefix {
	  optional string CIDR = 1;
	  optional string NAT = 2;
	  optional bool peersAccess = 3;
	  optional ContractorInfo contractor = 4;
	  repeated TerritoryInfo territories = 5;
	}

	message PrefixList {
	  repeated Prefix prefixes = 1;
	  optional int64 skipped = 2;
	  optional int64 total_count = 3;
	}

Замечания:

- Параметры `CIDR` и `NAT` задаются в формате `A.B.C.D/Y` или `A.B.C.D` (в случае одиночного IP адреса)
- Параметр `NAT` может присутствовать только для частных адресов, задает их трансляцию
- Параметр `peersAccess` отвечает за наличие доступа в Пирс абонентам указанного префикса
- `contractor` — информация о контрагенте префикса. Гарантируется передача только идентификатора контрагента
- `territories` — территории, за которыми закреплен префикс. Гарантируется передача только идентификатора территории. Если за префиксом не закреплена территория, возвращается список территорий контрагента

## KnownInfo — информация от пользователя [knowninfo-message]

	message KnownInfo {
	  optional uint32 contractor_id = 1;
	  optional string contractor_name = 2;
	  optional uint32 territory_id = 3;
	  optional string territory_name = 4;
	  optional uint32 parent_territory_id = 5;
	  optional string iptv_playlist_url = 6;
	  optional string uid = 7;
	}

Замечания:

- `contractor_id` — идентификатор контрагента известный нам и выбранный пользователем
- `contractor_name` — название контрагента (оператора связи)
- `territory_id` — идентификатор территории известный нам и выбранный пользователем
- `territory_name` — название территории
- `parent_territory_id` — идентификатор родительской территории (если задана, то должна присутствовать в Регистратуре)
- `iptv_playlist_address` — адрес списка каналов оператора связи
- `uid` — идентификатор устройства пользователя, с которого совершен запрос
