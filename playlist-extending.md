# Правила расширения плейлистов

Данный документ описывает правила расширения плейлистов формата M3U и XSPF для поддержки расширенных атрибутов при описании списка каналов.

Документ предназначен для разработчиков приложений и поставщиков услуг IPTV-вещания, записей телепередач.

## Общее описание [^fn-check-playlist]

Основной целью расширения форматов плейлистов является внесение дополнительной информации (атрибутов), способной улучшить взаимодействие пользователя с приложением.

Плейлист может быть расширен на двух уровнях:

- на уровне плейлиста. В этом случае расширение может применяться как к плейлисту, так и ко всем элементам плейлиста.
- на уровне элемента плейлиста. Расширение применяется только к элементу.

Расширение плейлиста на затрагивает совместимость с большинством известных проигрывателей, таких как VLC, и соответствует существующим стандартам.

Важно: плейлист должен использовать кодировку UTF-8.

[^fn-check-playlist]: Провести аудит версии 0.10.0 на совместимость с клиентами мобильных приложений.

### Атрибуты каналов

- Идентификатор канала (доступен в [TV Guide API](tv-guide.md))
- Признак наличия записей
- Признак доступности канала: `allowed`, `forbidden`, `payable`
- Разрешение источника: `SD`, `HD`, `FullHD`, `UltraHD`, 720x576
- Соотношение сторон: 4:3, 16:9, 16:10
- Признак потока: только аудио.

### Версионирование

Версионирование расширений для форматов M3U, XSPF осуществляется путем добавления специальной директивы. Если версия не указана явно, то подразумевается первая версия.

Вторая и последующие версии являются надмножеством первой версии, т.е. обратно совместимы, если не указано обратное. Таким образом, возможно сформировать промежуточный плейлист, совместимый с первой и второй версией одновременно.

## Интеграция со сторонними системами генерации плейлистов

При обращении за плейлистом рекомендуется устанавливать HTTP-заголовок `User-Agent`. Данный заголовок может быть использован при системой генерации плейлиста. Значение заголовка должно однозначно определять платформу и класс устройства.

Пример задания заголовка `User-Agent`

	Peers.TV/3.2.1 (iOS/3.2.1; iPad/5,1;) Darwin/14.0.0

### Рекомендации для поставщиков услуги IPTV

При реализации системы ограничения доступа к плейлисту, например, только для своих абонентов, при обращении к плейлисту для неабонентов сети рекомендуется возвращать пустой плейлист с кодом 200 HTTP-статуса.

Для указания для элементов плейлиста или плейлиста в целом дополнительных атрибутов, неописанных в данной документации, могут использоваться следующие техники:

- Для формата M3U дополнительные атрибуты могут быть описаны в рамках стандартных директив EXTM3U, EXTINF, так и путем ввода новых, при этом запрещается использовать для этих целей описанные ниже *новые* директивы.
- Для формата XSPF дополнительные атрибуты могут быть описаны с использование стандартных расширений (см. [стандарт XSPF](http://www.xspf.org/xspf-v1.html)).

# Формат M3U

Формат M3U разработан для использования кодировки текста Latin–1, позже был раcширен для использования кодировки текста UTF–8 (в данном случае формат называют M3U8).

Плейлист является текстовым файлом, который содержит набор строк. Каждая строка должна завершаться символом переноса строки (`\n`) или символами возврата каретки и переноса строки (`\r\n`). Каждая строка строка может содержать адрес медиа–ресурса, пустую строку или директиву, начинающуюся с символа решетка (`#`).

Пустые строки и неизвестные директивы должны быть интерпретированы как комментарий и проигнорированы клиентом.

Директива может применяться ко всем элементами плейлиста или только к следующему адресу медиа–ресурса. Директива может быть замена последующей директивой, если имена директив совпадают.

Расширение плейлиста осуществляется на основании возможности определения новых директив.

**Mime-type**: audio/x-mpegurl

## Директивы

Каждая директива может включать набор обязательных и дополнительных атрибутов, дополнительные атрибуты записываются последовательно с разделением пробельными символами. Каждый атрибут предоставляет собой пару ключ–значение, разделенных символом равно (`=`).

**Стандартные директивы**:

- EXTM3U
- EXTINF

**Новые директивы**:

- EXT-CN-VERSION
- EXT-CN-PLAYLIST-INFO
- EXT-CN-CHANNEL-INFO
- EXT-CN-STREAM-INFO

Ниже приведены соглашения по типам данных дополнительных атрибутов:

тип данных | примечания
-----------|------------
`число`    | значение из множества целых чисел
`дробное`  | дробная часть отделяется точкой
`строка`   | при наличии пробельных символов (или символа ',') строка оборачивается символом '"'
`булев`    | принимает два значения `true` или `false`

### EXTM3U

Директива определяет содержимое как M3U плейлист. Может содержать дополнительные расширения.

Формат директивы:

	#EXTM3U [<attributes-list>]

### EXTINF

Директива описывает длительность и название элемента плейлиста. Может содержать дополнительные атрибуты.

Формат директивы:

	#EXTINF:<duration> [<attributes-list>], <title>

где:

- `duration` — длительность элемента плейлиста, в случае live–вещания указывается `-1`;
- `title` — название элемента плейлиста.

Дополнительные атрибуты:

название     | тип   | по умолчанию | смысл
-------------|-------|--------------|-------------
`cn-id`      |`число`| `0`          | Идентификатор канала, доступен в [TV Guide API](tv-guide.md)
`cn-records` |`число`| `0`          | Признак наличия записей, `1` — если присутствует Архив передач.

Замечание: Начиная с версии 2 дополнительные параметры в тэге EXTINF не указываются и считаются устаревшими, однако могут быть использованы для формирования одного плейлиста, совместимого с клиентами, поддерживающими только 1 версию.

### EXT-CN-VERSION

Директива задает версию расширения плейлиста. При отсутствии данной директивы будет подразумеваться версия 1.

Формат директивы:

	#EXT-CN-VERSION:<version>

где:

- `version` — версия расширения документа.

### EXT-CN-PLAYLIST-INFO

Директива задает атрибуты по умолчанию для каждого элемента плейлиста. Доступна с версии 2.

Формат директивы:

	#EXT-CN-PLAYLIST-INFO:<attributes-list>

Список поддерживаемых атрибутов:

название      | тип    | по умолчанию | смысл
--------------|--------|--------------|-------------
`territory-id`|`число` | отсутствует  | Идентификатор территории (доступен в [Registry API](registry.md))

Идентификатор территории `territory-id` описывает регион, для которого осуществляется вещание.

### EXT-CN-CHANNEL-INFO

Директива описывает информацию о канале. Доступна с версии 2.

Формат директивы:

	#EXT-CN-CHANNEL-INFO:<attributes-list>

Дополнительные параметры:

название      | тип    | по умолчанию | смысл
--------------|--------|--------------|-------------
`channel-id`  |`число` | `0`          | Идентификатор канала(доступен в [TV Guide API](tv-guide.md))
`territory-id`|`число` | отсутствует  | Идентификатор территории (доступен в [Registry API]
`access`      |`строка`| `allowed`    | Условия доступа к каналу
`recordable`  |`булев` | `false`      | Наличие записей для данного канала

Значения параметра `access`:

- `allowed` — Доступен для просмотра;
- `forbidden` — Доступ запрещен;
- `payable` — Может быть оформлена подписка.

Идентификатор территории `territory-id` описывает регион, для которого осуществляется вещание.

### EXT-CN-STREAM-INFO

Директива описывает свойства медиа-потока. Доступна с версии 2.

Формат директивы:

	#EXT-CN-STREAM-INFO:<attributes-list>

Дополнительные параметры:

название      | тип    | по умолчанию | смысл
--------------|--------|--------------|-------------
`definition ` |`строка`| отсутствует  | Идентифицирует разрешение источника.
`aspect-ratio`|`строка`| отсутствует  | Идентифицирует соотношение сторон, например 4:3.
`audio-only`  |`булев` | `false`      | Признак отсутствия видео-дорожки в потоке

Параметр  `definition` может быть задан константой или в формате `ширина` x `высота`, например `720`x`576`.

Возможные значения параметра `definition`:

значение | смысл
---------|------------------
`SD`     | Разрешение стандартной четкости (480p и ниже)
`HD`     | Разрешение высокой четкости (720p)
`FullHD` | Разрешение высокой четкости (1080p)
`UltraHD`| Разрешение очень высокой четкости (2160p или 4320p)

## Примеры формирования плейлиста

**Версия 2:**

	#EXTM3U
	#EXT-CN-VERSION:2
	
	#EXTINF:-1, Первый канал
	#EXT-CN-CHANNEL-INFO: channel-id=10338245 access=allowed recordable=true
	#EXT-CN-STREAM-INFO: definition=SD aspect-ratio=4:3
	udp://@239.1.15.1:1234

	#EXTINF:-1, Россия 1
	#EXT-CN-CHANNEL-INFO: channel-id=10338258 access=allowed
	udp://@239.1.15.2:1234

**Версия 1:**

	#EXTM3U
	#EXTINF:-1 cn-id=10338245 group-title="Эфир", Первый канал
	udp://@239.1.15.1:1234
	#EXTINF:-1 cn-id=10338258, Россия 1
	udp://@239.1.15.2:1234


# Формат XSPF

Расширение плейлиста осуществляется на основе документации [стандарта XSPF](http://www.xspf.org/xspf-v1.html). Стандарт XSPF позволяет описывать отдельно расширения плейлиста и элементов плейлиста. Расширение содержит набор директив, находящихся в пространстве имен `cn`, и атрибутов к ним. Пространство имен должно быть указано соответствующим параметром в свойствах корневого элемента `playlist` формата XSPF.

Пример задания пространства имен `cn`:

	<playlist version="1" xmlns="http://xspf.org/ns/0/" xmlns:cn="http://www.cn.ru">


**Mime-type**: application/xspf+xml

## Директивы

Каждая директива может содержать значение или набор атрибутов, атрибуты указываются при помощи ключевого слова `attribute` в рамках директивы. Пример задания атрибута:

	<cn:playlist-info attribute="territory-id">3</cn:playlist-info>

Ниже приведены соглашения по интерпретации типов данных атрибутов:

тип данных | примечания
-----------|------------
`число`    | числовое предоставление
`дробное`  | дробная часть отделяется точкой
`строка`   | символьное представление строки
`булев`    | принимает два значения `true` или `false`

**Версия 2**:

- cn:version
- cn:playlist-info
- cn:channel-info
- cn:stream-info

**Версия 1**:

- cn:id
- cn:link
- cn:records
- cn:location

**Версия для приставок Eltex**:

- cn:tv-channel-definition
- cn:tv-channel-status
- cn:tv-channel-subscription

### cn:id

Директива содержит информацию об идентификаторе канала в сервисе [TV Guide API](tv-guide.md).

### cn:link

Директива содержит ссылку на программу телепередач для данного канала.

### cn:records

Директива описывает признак наличия записей для канала.

Принимает значения:

- `0` – отсутствуют записи для канала;
- `1` - присутствуют записи для канала.

### cn:location

Директива описывает альтернативные источники для вещания, в свойства атрибута при помощи параметра `type` дополнительно указывается тип вещания.

Известные типы вещания:

- `hls` — вещание осуществляется по протоколу HTTP Live Streaming.

### cn:tv-channel-definition

Атрибут описывает разрешение источника вещания.

Разрешение может быть задано константой:

- `SD` — стандартная чёткость;
- `HD` — высокая чёткость.

### cn:tv-channel-status

Атрибут описывает статус канала.

Возможные статусы канала:

- `TESTING ` — канал "в бою", продаётся;
- `LAUNCHED` — канал в тестовом вещании.

### cn:tv-channel-subscription

Атрибут содержит информацию о подписке на канал.

Возможные значения:

- `NOT_SUBSCRIBED ` — подписки нет, но подписаться можно;
- `SUBSCRIPTION_PENDING ` — подписка есть, идёт применение подписки к оборудованию;
- `SUBSCRIBED ` — подписка есть, применена к оборудованию.

## Примеры формирования плейлиста

**Версия 2:**

	<?xml version="1.0" encoding="UTF-8"?>
	<playlist version="1" xmlns="http://xspf.org/ns/0/" xmlns:cn="http://www.cn.ru">
    <extension application="http://www.cn.ru">
        <cn:version>2</cn:version>
    </extension>
    <title>Телевидение Электронного города</title>
    <trackList>
        <track>
            <location>http://hls.cn.ru/streaming/1kanal/tvrec/playlist.m3u8</location>
            <title>Первый</title>
            <extension application="http://www.cn.ru">
                <cn:channel-info attribute="channel-id">10338245</cn:channel-info>
                <cn:channel-info attribute="recordable">true</cn:channel-info>
                <cn:channel-info attribute="access">allowed</cn:channel-info>
                <cn:stream-info attribute="definition">SD</cn:stream-info>
            </extension>
        </track>
        <track>
            <location>udp://@239.1.15.2:1234</location>
            <title>Россия 1</title>
            <extension application="http://www.cn.ru">
                <cn:channel-info attribute="channel-id">10338258</cn:channel-info>
                <cn:channel-info attribute="recordable">false</cn:channel-info>
                <cn:channel-info attribute="access">forbidden</cn:channel-info>
                <cn:stream-info attribute="definition">SD</cn:stream-info>
            </extension>
        </track>
    </trackList>
	</playlist>
