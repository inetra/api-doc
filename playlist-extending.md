# Правила расширения плейлистов

Данный документ описывает правила расширения плейлистов формата M3U и XSPF для поддержки расширенных атрибутов при описании списка каналов.

## Общее описание

Основной целью расширения форматов плейлистов является внесение дополнительной информации, способной улучшить взаимодействие пользователя с приложением.

Плейлист может быть расширен на двух уровнях:

- на уровне плейлиста. В этом случае расширение может применяться как к плейлисту, так и ко всем элементам плейлиста.
- на уровне элемента плейлиста. Расширение применяется только к элементу.

Расширение плейлиста на затрагивает совместимость с большинством известных проигрывателей, таких как VLC, и должно соответствовать известным стандартам.

Важно: плейлист должен использовать кодировку UTF-8.

### Атрибуты каналов[^fn-broadcasting-area]

- Идентификатор канала(доступен в [TV Guide API](tv-guide.md))
- Признак наличия записей
- Признак доступности канала: `allowed`, `forbidden`, `payable`
- Разрешение источника: `SD`, `HD`, `FullHD`, `4D`, 720x576
- Соотношение сторон: 4:3, 16:9, 16:10
- Признак потока: только аудио.

[^fn-broadcasting-area]: Некоторые каналы могут вещаться в различных сетках, только сторона–вещатель может знать об этом.

### Версионирование

Версионирование расширений для форматов M3U, XSPF осуществляется путем добавления специальной директивы. Если версия не указана явно, то подразумевается первая версия. Вторая и последующие версии являются надмножеством первой версии, т.е. обратно совместимы, если не указано обратное.

## Интеграция со сторонними системами генерации плейлистов[^fn-iptv-services]

При обращении за плейлистом рекомендуется устанавливать HTTP-заголовок `User-Agent` . Данный заголовок может быть использован при генерации плейлиста. Значение заголовка должно однозначно определять платформу и класс устройства.

Пример задания заголовка `User-Agent`

	Peers.TV/3.2.1 (iOS/3.2.1; iPad/5,1;) Darwin/14.0.0

[^fn-iptv-services]: Описать механизмы, которые могут быть использованы провайдерами для расширения плейлистов, а именно дополнительные атрибуты для известных тэгов.

### Рекомендации для поставщиков услуги IPTV

При реализации системы ограничения доступа к плейлисту, например, только для своих абонентов, при обращении к плейлисту для неабонентов сети рекомендуется возвращать пустой плейлист с кодом 200 HTTP-статуса.


# Формат M3U

Формат M3U разработан для использования кодировки текста Latin–1, позже был раcширен для использования кодировки текста UTF–8 (в данном случае формат называют M3U8). Расширение плейлиста осуществляется на основании возможности включения комментариев и произвольных директив, начинающиеся со символа '#'.

При необходимости задать строковое значение, содержащее пробельные симоволы, для параметра тэга необходимо обрамлять значение кавычками.

**Mime-type**: audio/x-mpegurl

## Директивы:

- EXTM3U
- EXTINF
- EXT-CN-VERSION
- EXT-CN-CHANNEL-INFO
- EXT-CN-STREAM-INFO

Каждая директива может включать набор обязательных и дополнительных атрибутов, дополнительные атрибуты записываются последовательно с разделением пробельными символами. Каждый атрибут предоставляет собой пару ключ–значение, разделенных символом '='.

Ниже приведены соглашения по типам данных дополнительных атрибутов:

тип данных | примечания
-----------|------------
`целое`    | записывается как есть
`дробное`  | дробная часть отделяется точкой
`строка`   | при наличии пробельных символов (или символа ',') строка оборачивается символом '"'
`булев`    | принимает два значения `true` или `false`

### EXTM3U

Определяет содержимое как M3U плейлист.

### EXTINF

Описывает длительность и название элемента плейлиста. Может содержать дополнительные атрибуты.

Формат директивы:

	#EXTINF:<duration> [<attributes-list>], <title>

где:

- `duration` — длительность элемента плейлиста, в случае live–вещания указывается `-1`;
- `title` — название элемента плейлиста.

Дополнительные атрибуты:

название     | по умолчанию | смысл
-------------|--------------|-------------
`cn-id`      | `0`          | Идентификатор канала, доступен в [TV Guide API](tv-guide.md)
`cn-records` | `0`          | Признак наличия записей, `1` — если присутствует Архив передач.

Начиная с версии 2 дополнительные параметры в тэге EXTINF не указываются и считаются устаревшими.

### EXT-CN-VERSION

Данная директива задает версию расширения плейлиста. При отсутствии данной директивы будет подразумеваться версия 1.

Формат директивы:

	#EXT-CN-CHANNEL-INFO:<version>

где:

- `version` — версия расширения документа.

### EXT-CN-CHANNEL-INFO

Директива описывает информацию о канале. Доступна с версии 2.

Формат директивы:

	#EXT-CN-CHANNEL-INFO:<attributes-list>

Дополнительные параметры:

название    | по умолчанию | смысл
------------|--------------|-------------
`channel-id`| `0`          | Идентификатор канала(доступен в [TV Guide API](tv-guide.md))
`access`    | `allowed`    | Условия доступа к каналу
`recordable`| `false`      | Наличие записей для данного канала

Значения параметра `access`:

- `allowed`. Доступен для просмотра;
- `forbidden`. Доступ запрещен;
- `payable`. Может быть оформлена подписка.


### EXT-CN-STREAM-INFO

Директива описывает свойства медиа-потока. Доступна с версии 2.

Формат директивы:

	#EXT-CN-STREAM-INFO:<attributes-list>

Дополнительные параметры:

название      | по умолчанию | смысл
--------------|--------------|-------------
`definition ` | отсутствует  | Идентифицирует разрешение источника.
`aspect-ratio`| отсутствует  | Идентифицирует соотношение сторон, например 4:3.
`audio-only`  | `false`      | Идентифицирует отсутствие видео-дорожке в потоке

Параметр `definition` может быть задан:

- константой: SD, HD, FullHD, 4D;
- в формате `ширина` x `высота`, например `720`x`576`.

## Примеры формирования плейлиста

### Версия 2

	#EXTM3U
	#EXT-CN-VERSION:2
	
	#EXTINF:-1, Первый канал
	#EXT-CN-CHANNEL-INFO: channel-id=10338245 access=allowed recordable=true
	#EXT-CN-STREAM-INFO: definition=SD aspect-ratio=4:3
	udp://@239.1.15.1:1234

	#EXTINF:-1, Россия 1
	#EXT-CN-CHANNEL-INFO: channel-id=10338258 access=allowed
	udp://@239.1.15.2:1234

### Версия 1

	#EXTM3U
	#EXTINF:-1 cn-id=10338245 group-title="Эфир", Первый канал
	udp://@239.1.15.1:1234
	#EXTINF:-1 cn-id=10338258, Россия 1
	udp://@239.1.15.2:1234



# Формат XSPF

Расширение плейлиста осуществляется на основе документации [стандарта XSPF](http://www.xspf.org/xspf-v1.html).

**Mime-type**: application/xspf+xml


## Теги

- cn:version
- cn:channel-id
- cn:channel-access
- cn:channel-recordable
- cn:stream-definition
- cn:stream-aspect-ratio
- cn:stream-audio-only


### Устаревшие теги

Версия 1:

- cn:id
- cn:link
- cn:records
- cn:location

Версия для приставок Eltex ("Электронный Город"):

- cn:tv-channel-definition
- cn:tv-channel-status
- cn:tv-channel-subscription


## Примеры формирования плейлиста

### Версия 2[^fn-vlc-support]

	<?xml version="1.0" encoding="UTF-8"?>
	<playlist version="1" xmlns="http://xspf.org/ns/0/" xmlns:cn="http://www.cn.ru">
		<extension application="http://www.cn.ru">
			<cn:version>2</cn:version>
		</extension>
		<title>Телевидение Электронного города</title>
		<trackList>
			<track>
				<location>http://hls.cn.ru/streaming/1kanal/tvrec/playlist.m3u8</location>
				<title>Первый</title>
				<extension application="http://www.cn.ru">
					<cn:channel-id>10338245</cn:channel-id>
					<cn:channel-recordable>true</cn:recordable>
					<cn:channel-access>allowed</cn:access>
					<cn:stream-definition>SD</cn:definition>
				</extension>
			</track>
			<track>
				<location>udp://@239.1.15.2:1234</location>
				<title>Россия 1</title>
				<extension application="http://www.cn.ru">
					<cn:channel-id> 10338258</cn:channel-id>
					<cn:channel-recordable>false</cn:recordable>
					<cn:channel-access>forbidden</cn:access>
					<cn:stream-definition>SD</cn:definition>
				</extension>
			</track>
		</trackList>
	</playlist>
