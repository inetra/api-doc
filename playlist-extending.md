# Общее описание

Данный документ описывает правила расширения форматов M3U и XSPF для внесения дополнительной информации (директив), способной улучшить взаимодействие пользователя с приложением, при описании списка каналов (плейлиста).

Документ предназначен для разработчиков приложений и поставщиков услуг IPTV–вещания, записей телепередач.

В зависимости от типа директивы могут быть применены:

- ко всему плейлисту в целом или ко всем элементам.
- только к одному элементу.

Расширение форматов не затрагивает совместимость с большинством известных проигрывателей, таких как VLC, и соответствует существующим стандартам.

При формировании списка каналов должна использоваться кодировка UTF–8.

## Атрибуты каналов

- Идентификатор канала (доступен в [TV Guide API][tv-guide-api]);
- Признак наличия архива записей телепередач;
- Признак доступности канала: `allowed`, `forbidden`, `payable`;
- Разрешение источника: `SD`, `HD`, `FullHD`, `UltraHD`, 720x576;
- Соотношение сторон: 4:3, 16:9, 16:10;
- Признак потока: только аудио.

Архив записей телепередач предоставляется при помощи [TV Guide API][tv-guide-api] и [MediaLocator API][media-locator-api]. Признак наличия архива не гарантирует доступность записей для конечного пользователя.

[tv-guide-api]: tv-guide.md
[media-locator-api]: media-locator.md

## Версионирование

Версионирование расширений для форматов M3U, XSPF осуществляется путем добавления специальной директивы. Если версия не указана явно, то подразумевается первая версия.

Версия указывает на минимально поддерживаемую версию расширения. Клиенты могут распознавать директивы старшей, чем указано, версии, если отсутствует явное требование к минимальной версии расширения.

Таким образом, возможно сформировать список каналов, совместимый с первой и второй версией расширения одновременно.

## Рекомендации для поставщиков услуги IPTV

Для указания дополнительных директив, не описанных в данной документации, могут использоваться следующие техники:

- Для формата M3U дополнительные директивы могут быть описаны в рамках стандартных директив EXTM3U, EXTINF, так и путем ввода новых, при этом запрещается использовать для этих целей описанные ниже *новые* директивы.
- Для формата XSPF дополнительные директивы могут быть описаны с использованием механизма расширения (см. [стандарт XSPF](http://www.xspf.org/xspf-v1.html)).

# Формат M3U

Формат M3U разработан для использования кодировки текста Latin–1, позже был раcширен для использования кодировки текста UTF–8 (в данном случае формат называют M3U8).

Плейлист является текстовым файлом, который содержит набор строк. Каждая строка должна завершаться символом переноса строки (`\n`) или символами возврата каретки и переноса строки (`\r\n`). Каждая строка строка может содержать адрес медиа–ресурса, пустую строку или директиву, начинающуюся с символа решетка (`#`).

Пустые строки и неизвестные директивы должны быть интерпретированы как комментарий и проигнорированы клиентом.

Директива может применяться ко всем элементами плейлиста или только к следующему адресу медиа–ресурса. Директива может быть замена последующей директивой, если имена директив совпадают.

Расширение формата осуществляется на основании возможности определения новых директив.

**Mime-type**: audio/x-mpegurl

## Директивы

Каждая директива может включать набор обязательных и дополнительных атрибутов, дополнительные атрибуты записываются последовательно с разделением пробельными символами. Каждый атрибут предоставляет собой пару ключ–значение, разделенных символом равенства (`=`).

**Стандартные директивы**:

- EXTM3U
- EXTINF

**Новые директивы**:

- EXT-CN-VERSION
- EXT-CN-CHANNEL-INFO
- EXT-CN-STREAM-INFO

Ниже приведены соглашения по типам данных дополнительных атрибутов:

тип данных | примечания
-----------|------------
`число`    | значение из множества целых чисел
`дробное`  | дробная часть отделяется точкой
`строка`   | при наличии пробельных символов (или символа ',') строка оборачивается символом '"'
`булев`    | принимает два значения `true` или `false`

### EXTM3U

Директива определяет содержимое как плейлист в формате M3U. Может содержать дополнительные атрибуты.

Формат директивы:

	#EXTM3U [<attributes-list>]

### EXTINF

Директива описывает длительность и название элемента. Может содержать дополнительные атрибуты.

Формат директивы:

	#EXTINF:<duration> [<attributes-list>], <title>

где:

название  | тип    | смысл
----------|--------|-------------
`duration`|`число` | длительность элемента, в случае live–вещания указывается `-1`
`title`   |`строка`| название элемента


Дополнительные атрибуты:

название     | тип   | по умолчанию | смысл
-------------|-------|--------------|-------------
`cn-id`      |`число`| `0`          | Идентификатор канала, доступен в [TV Guide API](tv-guide.md)
`cn-records` |`число`| `0`          | Наличие архива записей телепередач для данного канала, `1` — если присутствует архив записей телепередач

Замечание:

- Начиная с версии 2 дополнительные атрибуты в директивы EXTINF считаются устаревшими, однако могут быть использованы для формирования одного списка каналов, совместимого с клиентами, поддерживающими только 1 версию.

### EXT-CN-VERSION

Директива задает версию расширения. Доступна с версии 2.

Формат директивы:

	#EXT-CN-VERSION:<version>

где:

- `version` — версия расширения документа.

### EXT-CN-CHANNEL-INFO

Директива описывает информацию о канале. Появилась с версии 2.

Формат директивы:

	#EXT-CN-CHANNEL-INFO:<attributes-list>

Дополнительные параметры:

название      | тип    | по умолчанию | смысл
--------------|--------|--------------|-------------
`channel-id`  |`число` | `0`          | Идентификатор канала(доступен в [TV Guide API](tv-guide.md))
`territory-id`|`число` | отсутствует  | Идентификатор территории (доступен в [Registry API][registry-api])
`access`      |`строка`| `allowed`    | Условия доступа к каналу
`recordable`  |`булев` | `false`      | Наличие архива записей телепередач для данного канала

Значения параметра `access`:

- `allowed` — Доступен для просмотра;
- `forbidden` — Доступ запрещен;
- `payable` — Может быть оформлена подписка.

Идентификатор территории `territory-id` описывает регион, для которого осуществляется вещание. Если регион вещания не указан, то подразумевает текущий регион.

[registry-api]: registry.md

### EXT-CN-STREAM-INFO

Директива описывает свойства медиа–потока. Появилась с версии 2.

Формат директивы:

	#EXT-CN-STREAM-INFO:<attributes-list>

Дополнительные параметры:

название      | тип    | по умолчанию | смысл
--------------|--------|--------------|-------------
`definition ` |`строка`| отсутствует  | Идентифицирует разрешение источника.
`aspect-ratio`|`строка`| отсутствует  | Идентифицирует соотношение сторон, например 4:3.
`audio-only`  |`булев` | `false`      | Признак отсутствия видео–дорожки в потоке

Параметр  `definition` может быть задан константой или в формате `ширина` x `высота`, например `720`x`576`.

Возможные значения параметра `definition`:

значение | смысл
---------|------------------
`SD`     | Разрешение стандартной четкости (576p и ниже)
`HD`     | Разрешение высокой четкости (720p)
`FullHD` | Разрешение высокой четкости (1080p)
`UltraHD`| Разрешение очень высокой четкости (2160p или 4320p)

## Примеры формирования

**Версия 2:**

	#EXTM3U
	#EXT-CN-VERSION:2

	#EXT-CN-CHANNEL-INFO: channel-id=10338245 access=allowed recordable=true territory-id=16
	#EXT-CN-STREAM-INFO: definition=SD aspect-ratio=4:3
	#EXTINF:-1, Первый канал
	udp://@239.1.15.1:1234

	#EXT-CN-CHANNEL-INFO: channel-id=10338258 access=allowed
	#EXTINF:-1, Россия 1
	udp://@239.1.15.2:1234

**Версия 1:**

	#EXTM3U
	#EXTINF:-1 cn-id=10338245 group-title="Эфир", Первый канал
	udp://@239.1.15.1:1234
	#EXTINF:-1 cn-id=10338258, Россия 1
	udp://@239.1.15.2:1234


# Формат XSPF

Расширение формата осуществляется на основе документации [стандарта XSPF](http://www.xspf.org/xspf-v1.html). Стандарт XSPF позволяет описывать отдельно расширения плейлиста и элементов плейлиста. Расширение содержит набор директив, находящихся в пространстве имен `cn`, и атрибутов к ним. Пространство имен должно быть указано соответствующим параметром в свойствах корневого элемента `playlist` формата XSPF.

Пример задания пространства имен `cn`:

	<playlist version="1" xmlns="http://xspf.org/ns/0/" xmlns:cn="http://www.cn.ru">


**Mime-type**: application/xspf+xml

## Директивы

Каждая директива может содержать значение или набор атрибутов, атрибуты указываются в виде вложенных элементов.

Ниже приведены соглашения по интерпретации типов данных атрибутов:

тип данных | примечания
-----------|------------
`число`    | числовое предоставление
`дробное`  | дробная часть отделяется точкой
`строка`   | символьное представление строки
`булев`    | принимает два значения `true` или `false`

**Версия 2**:

- cn:version
- cn:channel-info
- cn:stream-info

**Версия 1**:

- cn:id
- cn:link
- cn:records
- cn:location

Дополнительные директивы для приставок Eltex:

- cn:tv-channel-definition
- cn:tv-channel-status
- cn:tv-channel-subscription

### cn:version

### cn:id

Директива содержит информацию об идентификаторе канала в сервисе [TV Guide API](tv-guide.md).

### cn:link

Директива содержит ссылку на программу телепередач для данного канала.

### cn:records

Директива описывает признак наличия записей для канала.

Принимает значения:

- `0` – отсутствуют записи для канала;
- `1` - присутствуют записи для канала.

### cn:location

Директива описывает альтернативные источники для вещания, в свойствах директивы при помощи параметра `type` дополнительно указывается тип вещания.

Известные типы вещания:

- `hls` — вещание осуществляется по протоколу HTTP Live Streaming.

### cn:tv-channel-definition

Директива описывает разрешение источника вещания.

Разрешение может быть задано константой:

- `SD` — стандартная чёткость;
- `HD` — высокая чёткость.

### cn:tv-channel-status

Директива описывает статус канала.

Возможные статусы канала:

- `TESTING ` — канал "в бою", продаётся;
- `LAUNCHED` — канал в тестовом вещании.

### cn:tv-channel-subscription

Директива содержит информацию о подписке на канал.

Возможные значения:

- `NOT_SUBSCRIBED ` — подписки нет, но подписаться можно;
- `SUBSCRIPTION_PENDING ` — подписка есть, идёт применение подписки к оборудованию;
- `SUBSCRIBED ` — подписка есть, применена к оборудованию.

	<?xml version="1.0" encoding="UTF-8"?>

	<extension application="http://www.cn.ru">
	    <cn:version>2</cn:version>
	</extension>
	<title>Телевидение Электронного города</title>
	<trackList>
	    <track>
	        <location>http://hls.cn.ru/streaming/1kanal/tvrec/playlist.m3u8</location>
	        <title>Первый</title>
	        <extension application="http://www.cn.ru">
	            <cn:channel-info>
	               <channel-id>10338245</channel-id>
	               <recordable>true</recordable>
	               <access>allowed</access>
	            </cn:channel-info>
	            <cn:stream-info>
	               <definition>SD</definition>
	            </cn:stream-info>
	        </extension>
	    </track>
	    <track>
	        <location>udp://@239.1.15.2:1234</location>
	        <title>Россия 1</title>
	        <extension application="http://www.cn.ru">
	            <cn:channel-info>
	               <channel-id>10338258</channel-id>

	            </cn:channel-info>
	            <cn:stream-info>
