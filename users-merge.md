title: Users Merge

О чем данный документ
==================

Данный документ описывает API слияния учеток двух пользователей в одну.

Виды пользователей описаны в документах История просмотра: варианты использования и [Auth API], могут быть двух видов:

- с паспортом CN.ru
- анонимные

[Auth API]: auth.md

В первой версии API возможны слияния только двух пользователей, при этом хотя бы один из них должен быть анонимным.

Слияние пользователей — суть слияние их деревьев данных. Алгоритм слияния описан в приложении к User Data API.

Общее описание
=============

API работает по протоколу HTTPS для сокрытия передаваемых данных. Запросы составляются следующим образом:

	https://<path_to_api>/<method>.<format>?[extra_data]

Где:

- `path_to_api` — путь до API, полученный из Регистратуры
- `method` — название метода
- `format` — формат кодирования данных в теле запроса и ответа
- `extra_data` — дополнительные параметры метода.

Формат кодирования данных может быть одним из двух:

- `json` — JSON;
- `protobuf` — Protocol Buffers.

Методы
======

users_merge — слияние пользователей
-----------------------------------

Дополнительные параметры:

параметр       | значение по умолчанию  |	смысл 
---------------|------------------------| ----- 
`mine_token`   | отсутствует            | токен доступа пользователя, которой производит слияние
`their_token`  | отсутствует            | временный токен доступа пользователя, который запросил слияние
`resolve_hint` | пусто                  | подсказка, в чью пользу разрешать конфликты слияния данных


Подсказка для разрешения конфликтов может принимать одно из двух значений: `mine` или `their`. Если подсказка отсутствует, сервер отдает предпочтение данным пользователя с Паспортом, т.е. не анонимному.

Возможные коды ответов:

код | значение
----|---------
200 | успешное слияние
401 | неверный токен доступа пользователя, производившего слияние
403 | неверный временный токен доступа пользователя, запросившего слияние
409 | обнаружены конфликты слияния данных

Формат ответа: сообщение `MergeConflicts`.

При обнаружении конфликтов слияния приложение, производившее слияние данных, должно отобразить пользователю список конфликтующих данных и их атрибутов (возможно, в преобразованном виде) и после принятия решения пользователем произвести изменения в данных соответствующего пользователя с помощью User Data API, после чего повторить операцию слияния до полного разрешения конфликтов.

Формат данных
=============

MergeConflicts — конфликты слияния
----------------------------------

	message MergeConflict {
	  optional string element_path = 1;
	  optional bytes mine_attributes = 2;
	  optional bytes their_attributes = 3;
	}
	 
	message MergeConflicts {
	  repeated MergeConflict conflicts = 1;
	}
